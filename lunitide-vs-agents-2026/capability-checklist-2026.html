KEY FINDING · P0 致命断链

MCP 工具一行业务代码都没跑起来。chat.go 已实现 mcpToolDefinitions()（会把 ready 状态的 MCP 工具合并进聊天请求），但 cmd/engine/main.go 从未调用 engine.SetM6Services(...)，导致 e.mcp6Registry == nil，该函数恒返回空。

STRENGTH · 安全设计领先

06免费开源组件集成清单

以下全部为开源（MIT / Apache-2.0）、免费、可直连的组件与动作，按「先修断链 → 预置 server → 技能移植 → 编排升级」四组排序，每组均可独立交付。

GROUP A · P0

接线修复：让已有 MCP 栈跑起来（约 30 行，当天完成）

engine.go:1111 的 SetM6Services 已定义好全部依赖，只差在进程入口组装：

// cmd/engine/main.go —— engine 构造完成之后追加：
mcpReg := mcp6.NewRegistry(probeFn, invokeFn, secretLease)
engine.SetM6Services(extService, mcpReg, endpointService)

// probeFn / invokeFn / secretLease 由 m6app.ExtensionService 与
// m6app.EndpointService 提供（端点持久化 + 凭证租约已实现）。

验收：配置任一远程 MCP → mcp.list 显示 ready → 聊天请求 tools 数组出现 mcp__<endpoint>__<tool> 定义 → LLM 可发起 tool_calls。同时把 web.fetch / web.search 一并提交入库。

GROUP B · P1

预置免费 MCP server（全部 MIT / Apache-2.0，零成本直连）

接入方式统一走 mcp.add（远程 HTTPS 优先；stdio 待隔离 POC 开门禁后启用），预置为「官方市场条目 + 一键启用」：

Server能力许可接入注意
fetch网页抓取（web.fetch 的 MCP 形态，可作为其兜底）MIT远程部署形态即可，免钥
filesystem受控根目录文件读写MIT根目录必须走 M5 显式授权，禁止全盘

playwright / puppeteer浏览器自动化、截图、E2EApache-2.0建议远程 headless 形态，避免 stdio 门禁

GROUP C · P1

技能移植：开源技能包改造为 Lunitide 清单

技能格式改造成本低（Lunitide 清单为 JSON + ed25519 签名），建议首批移植高频五件：

docx 文档处理 · xlsx 表格分析 · pdf 读写 · html-report 报告生成 · data-analysis 数据洞察 —— 全部来自开源技能仓库（Anthropic skills 及其衍生，MIT / CC 许可，免费直连），移植时剥离原平台专属字段、补 Lunitide 签名即可。

GROUP D · P1-P2

编排升级：给协调器装上执行回路

参考 OpenClaw「spawn + 隔离 + 结果回传」模式，在现有 Coordinator（记账完备）之上加三件套：

① 子 Agent 执行器：复用 engine 聊天流，独立上下文与工具授权域；② TodoWrite 工具：与 coordinator 的 Todo 结构对齐；③ 并行池 + 结果汇聚。落地顺序：执行器 → TodoWrite → 并行。
