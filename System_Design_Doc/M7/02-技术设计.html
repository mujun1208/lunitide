04 / STATE MACHINES

状态机与事务语义

StageRun

draft→ready→running→waiting_review→approved→completed

唯一持久化主状态为 draft/ready/running/waiting_review/approved/completed，支路为 blocked/paused/cancelled；stale 为投影态，由 stale_marks×stale_resolutions 推导，不落 stage_runs.state。依赖未完成保持 draft；依赖与输入完整转 ready；Gate 计算是事件/过程而非 gate_check 状态；Review 绑定当前输入与制品 digest。输入变化使 approved/completed 被投影为 stale，重捕获输入、重跑 Gate 与新 Review 后才可重新 approved/completed。旧 pending 仅映射 draft，gate_check 仅映射 GateEvaluation 运行事件，均不得落库。

CRRevision / Package / Promotion

CRRevision: draft → submitted → approved | rejected | superseded
Package: building → sealed | failed                // sealed 永不回退
Promotion: requested → policy_check → approval_check → migrating → deploying → validating → succeeded
                              └ denied/expired       └ failed → rolling_back → rolled_back | rollback_failed
prepare/dispatch 无确认回执 → RESULT_UNKNOWN → remote_reconcile → resume | succeeded | failed | manual

原子边界

状态更新、GateEvaluation、ApprovalBinding、AuditEvent 与 outbox 同库事务提交。Promotion 在任何迁移、部署或回滚等外部副作用前，必须验证职责分离（SoD）审批仍有效且未过期；审批绑定 canonical_intent_digest，其规范化输入完整覆盖 package、manifest、blob、from、to、migration、deployment、rollback、policy 与 expiry。执行前从权威数据重新规范化并计算摘要；任一输入、策略或有效期变化均使旧审批失效并回到 approval_check 重新审批。

外部迁移/部署采用 saga，每一步以 promotion_id+step+canonical_intent_digest 幂等。prepare 或 dispatch 已发生但未取得可信回执时必须进入 RESULT_UNKNOWN；恢复器先使用远端操作 ID、幂等键和目标环境事实对账，再决定续跑、收敛终态或人工处置，禁止盲目重试或自动另起可能重复副作用的执行。

R6 · CR / CRRevision 依赖 DAG

CRDependency 绑定不可变 revision 端点，canonical relation 固定为 requires | requires_succeeded | parallel_with：requires 要求前置 revision 已满足可消费门禁，requires_succeeded 还要求其执行/晋级终态成功，parallel_with 仅为调度提示。所有边在服务端按 revision 图增量验环并在提交前全图复核；自环、间接环、悬空端点和未知关系一律拒绝。parallel_with 不改变依赖、Review、策略、签名、成员摘要或 Promotion Gate，不得用于绕过任何 Gate。

R7 · ReleaseMemberDigest

ReleaseMemberDigest 是旧称 ArtifactDigest 的等价 canonical 名；读取兼容旧名，写入与 API 输出使用新名。每个发行成员必须记录 name、size、sha256、algorithm=sha256。成员名先按 manifest 规定的 UTF-8 字节序规范排序，再以固定字段顺序规范序列化并计算 manifest digest；拒绝重复名、路径穿越、非规范名、缺项及非 sha256 算法。封包、验签、晋级和取回时均重算成员大小与 SHA-256，并逐项比较规范顺序；成员名、顺序、大小或 digest 任一新增、删除、替换、重排或篡改均 FAIL，隔离包并阻断 Gate。

  • 凭据：API Key/OAuth token 全部经 Secret Lease（DPAPI、TTL、审计不含明文）；凭据 Lease 失效 → M7-MCP-008（401）拒绝调用并触发重授权流程，不降级明文。
