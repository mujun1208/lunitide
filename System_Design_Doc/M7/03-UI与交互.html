04 / TRACE

追踪与影响分析

左侧过滤实体类型、关系、状态和时间；中央 DAG 支持缩放、方向切换；右侧显示所选节点版本和 digest。Stale 根因以黄色路径高亮，断链红色。列表模式提供键盘与读屏可达替代。

关键交互：点击“上游变更影响”先预览将变 Stale 的阶段、Review、包候选，不执行修改；确认上游新版本后服务端自动传播，UI 只展示结果。
05 / CR, PACKAGE & PROMOTION

发行工作台

CR 修订

左侧 revision 时间线，中部 manifest 差异，右侧 Gate/Review。submitted 后编辑按钮替换为“创建新修订”。自审按钮不可见并解释职责分离。

不可变包

突出完整 SHA-256、签名状态、SBOM、来源 CRRevision。sealed 后所有字段只读，提供校验与复制 digest。

Promotion 向导

①目标环境 ②策略预检 ③确认同 digest ④迁移计划 ⑤执行。生产确认框必须键入 digest 后 8 位；不暴露 MigrationAdapter。

部署执行页

纵向时间线展示 policy_check → migrating → deploying → validating；每步展示日志、耗时、审计 ID。失败时依据能力显示“自动回退进行中”或“发起回退”；rollback_failed 显示冻结环境和人工处置手册入口。

数据加载：CR 修订/包详情/晋级部署三页分别经 release.getRevision、release.getPackage、release.getPromotion 快照读；部署执行时间线的 canonical 全态（含 denied/expired/rollback_failed/outcome_unknown 等终态）以 release.getPromotion 为准，release.promote/rollback 写响应 state 仅为对外投影。
06 / APP UPDATE

Lunitide AppUpdate 独立体验

不得混淆：AppUpdate 只在“设置 → 应用更新”出现，使用“更新/安装/重启”文案；项目发行只使用“包/晋级/部署/回退”。两者无共同列表、筛选器或状态徽标。

页面展示当前版本、更新通道、目标版本、签名、下载进度、安装结果与回退至上一客户端版本。任何 AppUpdate 失败不改变项目 Promotion；项目部署失败也不触发客户端更新。

Artifact 血缘与复现 UI

  • Artifact 详情新增版本时间线、父/输入来源、生成 Run/Tool、评审、下游引用和 stale 影响；可从任一 claim 回到叶级来源。
  • “复现”先展示 Manifest、缺失依赖、预计外发/副作用和目标工作区；默认在隔离工作区执行，不覆盖已发布版本。
  • Golden Tasks 看板显示数据集版本、成功率、干预率、轮次、成本、时延和回归差异；统计缺样本时不得显示绿色通过。
  • 临时 Widget、工作期 Artifact、正式 ArtifactVersion、sealed ReleasePackage 使用不同标签，避免把预览误认为可交付制品。

四状态

  • loading：列表骨架 + tab 可见；健康检查行内 spinner，不整页阻塞
