01 / SCOPE

目标、角色与边界

目标

以 WorkflowVersion 固化九阶段定义；以输入快照和制品版本保证可复现；以 Trace/Stale/Gate/Checkpoint 阻止过期证据进入发行。

角色

项目负责人创建流程；开发提交 DevTask；测试与安全负责人提交 Test/Scan；评审者给出 Review；发行管理员执行 Promotion；运维验证迁移与部署并可回退。

明确不做

TeamSpace、N-of-M 多人审批归 M9。M7 只保留企业发行所需策略接口、单主体授权和策略判定结果，不实现组织空间与法定人数编排。

双轨红线：用户项目的 ReleasePackage/Promotion/Deployment 与 Lunitide 客户端的 AppUpdate/UpdateChannel/UpdateInstallation 使用不同实体、状态机、权限、存储前缀与审计事件；禁止互相调用或复用状态。

04 / INVARIANTS

不可破坏规则

版本与过期

  • Review 永远指向确切 CRRevision。
  • 快照输入变化触发 Stale，不静默复用结论。
  • Checkpoint 不能替代 Gate，只保存已判定状态。

包与晋级

  • ReleasePackage 创建后不可修改、删除或换 digest。
  • Promotion 必须校验来源包和目标落地包 digest 相同。
  • 数据库迁移失败必须阻断部署并按策略回退。

企业策略

  • 生产环境强制签名、可验证 SBOM、部署时窗。
  • 开发者不得审批自己的 CRRevision。
  • 紧急发行执行前仍须独立、未过期且绑定 canonical intent digest 的紧急审批；事后 Review 只补充复盘与审计，不得替代前置授权。

06 / LEGACY DETAIL COMPLETION

旧版 DevTask、CR 与发布细节补齐

开发任务事实链

DevTask 通过 TaskSourceLink 关联已基线化需求/设计，以无环 TaskDependency 表达阻塞，以有时效且留历史的 Assignment 记录负责人，以不可变 CodeChange 绑定 repository、commit、tree/diff digest 与 provenance；解除或变更只能追加记录并触发 Stale。

风险双口径

业务优先级固定 P0/P1/P2/P3，技术风险固定 low/medium/high，独立必填且不得互代。默认建议 P0/P1→high、P2→medium、P3→low；人工调级须理由和审计，生产存在 P0 或 high 未处置项即阻断。

质量证据

TestCase 版本化验收条件、步骤和期望；TestEvidence 绑定 case version、代码/构建 digest、环境、结果和报告摘要。ScanFinding 豁免必须有 owner、reason、approved_by、expires_at；到期自动失效并重新阻断，禁止永久豁免。

100% 双向追踪门禁：每条基线需求须沿“需求→设计→DevTask→CodeChange→TestCase→TestEvidence”到达有效证据，每个下游节点也须反向到达范围内基线需求；正向覆盖率、反向覆盖率、边完整率均为 100%，断链、悬空、跨 digest 或 stale 均失败。
发布补充要求
回滚RollbackPlan/RollbackAttempt 对 binary|schema|data|external 四维分别声明策略、前置、Owner、验证与结果；缺维禁止生产 Promotion。
AppUpdate签名 manifest 必含 nonce、issued_at/not_before/expires_at、version/min_version、package digest、key/cert chain；执行时间窗、防重放、防降级及证书轮换/撤销。
备份边界桌面本地 profile 每日备份，保留最近 7 份每日备份及最近 3 份升级前备份；不得等同组织平台灾备，平台继续独立满足 RPO≤5min/RTO≤30min。
新版优先仍须同一 sealed digest 跨环境 Promotion；审批 hash 公式与重算/失效继续服从新版，旧版不得降级覆盖。

StageRun 与资产模板

StageRun: draft→ready→running→waiting_review→approved→completed，支路 blocked/paused/stale/cancelled。驳回回 running 并创建新 review round。旧 not_started/in_progress/rejected 仅作迁移别名。启动阶段冻结唯一 StageInputSnapshot；上游变化只传播 stale，不替换在途快照。

AssetTemplate: created→enabled→void；void→created→rescan→enabled。新引用只能选择 enabled 的确切版本；引用存在或影响不明时禁止物理删除。上传校验 magic/MIME/扩展、病毒、zip bomb、嵌套、绝对路径、UNC、..、symlink/hardlink 与路径穿越。

DevTask 字段、canonical 状态与 legacy 语义映射

DevTask 必含 id、project_id、title、description、priority(P0–P3)、risk(low|medium|high)、source_links、dependencies、assignment、code_changes、scan/test results、state、state_reason、verification_readiness、version。TaskDependency 条件为 must_complete|must_pass_test|must_merge|optional 且 DAG 无环；Assignment role 为 frontend|backend|db|integration|security|qa|devops，actor_type 为 agent|human|mixed。

唯一持久化状态：draft, ready, in_progress, blocked, in_review, done, reopened, cancelled。合法转换为 draft→ready、ready→in_progress、in_progress↔blocked、in_progress→in_review、in_review→in_progress、in_review→done、done→reopened、reopened→in_progress、draft→cancelled、ready→cancelled；列表外转换拒绝。任意已执行任务取消必须创建替代/撤回任务并保留历史，不直接改写终态。

测试、扫描与追踪

ScanFinding severity=critical|high|medium|low|info，status=open|fixed|waived|false_positive；TestCase type=unit|component|integration|security|migration|performance|recovery，结果 pending|pass|fail|blocked|skipped；TestRun=pass|fail|error|timeout；Evidence=screenshot|log|video|heap_dump|trace|report。历史只追加。Requirement⇄Design⇄DevTask⇄CodeChange⇄TestCase/TestEvidence 正向、反向和边完整率均为 100%；deferred/not_applicable 也需原因、审批和证据。

CRRevision、ReleasePackage、Promotion 与 Deployment

ChangeRequest 是容器，展示状态只能从 current CRRevision 投影；审批权威仅 CRRevision。CRRevision 状态机（V2 权威，与 02 技术设计 §STATE MACHINES 一致）：draft→submitted→approved | rejected | superseded；submitted 起不可变，任一 commit、DAG、证据、制品、版本、环境或回退漂移使旧 revision 置 superseded 并新建 revision 重审（承接 V1 changed_after_approval 语义），不可原地解冻；packaged/released 不落 CRRevision，由 ReleasePackage 与 Promotion 承接。

CR 提交前必须绑定 Git commit、CR DAG、测试/扫描证据、制品 SHA-256、semver、目标环境、回退策略。ReleasePackage 冻结 source_ref、成员顺序/大小/digest、SBOM、MigrationPackage、配置与回退说明；同一 digest 由 development→test→production 晋级，目标环境禁止重打包/codegen。

Promotion 转换（V2 权威状态机）规则
requested→policy_check来源成功、同 digest、路径、策略、证据有效；不满足转 denied。
policy_check→approval_check只读校验 schema、权限、容量、版本、锁和契约；失败零写入、拒绝晋级。
approval_check→migratingSoD 审批有效、未过期且绑定 canonical_intent_digest；恢复点可验证且取得短 TTL 目标 Lease；审批缺失/过期转 expired。
migrating→deploying→validating→succeeded按批准顺序迁移与部署；实际 package/code/schema/integration digest、健康和契约全部一致。
migrating/deploying/validating→failed|outcome_unknown确定失败停止后续并转 rolling_back；结果不明自动重试 0，先按 receipt/迁移账本/环境事实对账（remote_reconcile 后 resume|succeeded|failed|manual）。
failed→rolling_back→rolled_back | rollback_failed回退另建 RollbackAttempt（pending→running→succeeded|failed），binary/schema/data/external 四维分别记录；rollback_failed 冻结环境并告警。

代码+数据库顺序固定：只读契约预检→可验证恢复点→批准的 MigrationPackage→迁移后 invariant/契约校验→同包代码→健康/契约复核。破坏性变更遵循 Expand→Migrate→Contract；数据库默认不逆迁移。Deployment 为目标执行事实：pending→running→succeeded/failed/outcome_unknown，由 Promotion 编排并分别落 deployments 表；失败可创建 RollbackAttempt，四层分别记录。

  • DevTask 每条转换、DAG 环、扫描豁免到期、失败测试追加历史与 Trace 100% 有自动化证据。
  • approval hash 漂移立即失效；同 digest 晋级；断电/超时进入 outcome_unknown 且不重复副作用。
  • 项目发行与 AppUpdate 使用不同实体、签名根、receipt 和回滚链；签名撤销、防重放、防降级通过。

只读子代理产品合同（FR-23）

定位

只读子代理是主 Root Run 的能力受限执行单元，服务于阶段 2「调研与证据」及任何需要并行采集的场景：派生出去只做 fs 读取、web 抓取/搜索、evidence 列举与浏览器只读操作，结果物化为 Evidence 并以 TraceEdge 挂回主 Run，主上下文只接收摘要与 digest，防止采集内容撑爆主对话。它与 FR-19 专家协作正交：子代理不承载专家身份、不注入 {{ExpertPrompt}}、不触发 Profile Invocation，因此不受「同一 Root Run 顺序 Invocation」约束；并行度由独立预算与并发上限控制。

  • web.fetch / web.search（沿用 SSRF 与 provenance 合同）
  • evidence.list
  • browser.act 仅 navigate / read / snapshot 三个只读 op

禁止能力（fail-closed）

  • changeset.preview/apply/revert、command.*、terminal.*、MCP 写语义工具

  • browser.act 的 click / type 与一切注入脚本

MCP 客户端运行时与设置管理面产品合同（FR-25）

定位：M4 曾明令「MCP tool 不得超前进入 16 工具 manifest」，M5 交付了 per-run 的 mcp.invoke 原型、M6 交付了 mcp6.register/invoke/revoke 与能力 pin（serverIdentityDigest + toolSchemaDigests）。本合同把 MCP 升级为一等公民：新增设置「MCP 服务器」管理页（本地/云端两类 transport、市场目录一键添加、手动 JSON 配置）、endpoint 全生命周期治理与逐调用门禁——复用 M6 能力 pin 与 M4 Policy/预算/审计通道，不新建第二套 MCP 客户端。

传输与目录

  • 本地：stdio 子进程，npx / uvx 优先（官方模板默认形式），继承 M4 受控可执行文件白名单；进程生命周期归 Engine，崩溃自动降级并审计
  • 云端：https / SSE transport，TLS 强制，域名校验沿用 SSRF 合同
  • 市场：只读目录（签名索引 + 条目 digest），可搜索、可查看描述/工具清单预览；市场目录本身不含凭据

  • 「+ 添加」两入口：从市场添加（选中条目 → 预览工具清单 → 确认权限增量 → 安装）与手动配置（粘贴 mcpServers JSON，优先 npx/uvx 形态；schema 校验 + 来源确认警示）
  • endpoint 状态机：probe → ready ⇄ degraded → revoked；启停即时生效；健康探测周期化，失败自动降级
  • 能力快照：register 时固化 serverIdentityDigest + toolSchemaDigests；后续 handshake 漂移即 fail-closed
  • 凭据：API Key/OAuth 一律走 Secret Lease（DPAPI 加密、TTL、不落日志）；UI 只显示覆盖式更新入口

调用治理（不变量）

  • 每次 mcp.invoke 逐工具 Policy 裁决（读/写语义、外发边界、风险分级），写语义工具需审批与 EffectJournal
  • 调用计入 Root Run 预算（tokens/bytes/cost/wall-clock）；deadline 超时 fail-closed
  • 能力漂移、endpoint revoked、凭据失效一律拒绝且零副作用
  • 来源不明配置（无签名市场条目、非白名单 command）默认隔离，用户显式确认后方可启用
