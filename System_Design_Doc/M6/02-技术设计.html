03 · Bridges

Bridge 契约

HTTP MCP Bridge

调用：invoke(endpointId, tool, args, trace, deadline, idempotencyKey)

先做 capabilityHash 钉扎与参数 schema 校验，再解析短时认证引用；连接池、超时、指数退避、熔断和响应大小上限由网关统一处理。流式响应分片带序号和摘要。

生命周期：REGISTER → PROBE → READY → DEGRADED/REVOKED。HTTP 为 M6 首发实现。

stdio MCP Bridge

调用：spawn(signedSpec, sandboxProfile)

三态交付：POC 仅验证隔离假设；受控实现补齐真实 Worker、签名协议、恢复、撤销和供应链，且默认关闭；生产逃逸验收绑定同一 build/config digest 后才可进入 READY。任一阶段失败即保持 DISABLED。

Connector Metadata Bridge

调用：snapshot(connectorId, metadataScope)

SQL AST/驱动 API 双重白名单，仅 catalog/schema/table/column/index/constraint；只读事务、只读账号、行数/时限限制。响应先规范化再缓存，不记录连接密钥。

Worker Bridge

调用：dispatch(jobSpec, capabilityToken, budgetLease)

验签后创建容器/微虚拟机与 worktree；输出仅允许 result manifest、补丁、测试报告和资源用量。心跳续租，失联由 Reaper 强制终止并冻结结果。

04 · State Machines

三状态机

状态机 A：扩展生命周期

DISCOVERED → VERIFYING → VERIFIED → INSTALLED → ENABLED
                  └→ QUARANTINED      │   │
ENABLED → PAUSED → ENABLED            │   └→ BLOCKED
INSTALLED/PAUSED → UPGRADING → INSTALLED
INSTALLED/PAUSED/BLOCKED → UNINSTALLED
失败升级 → ROLLING_BACK → 原稳定版本；签名撤销 → BLOCKED

状态机 B：任务与委派

CREATED → QUEUED → LEASED → RUNNING → JOINING → SUCCEEDED
                  │          │          ├→ FAILED
                  │          ├→ CANCELLING → CANCELLED
                  └→ lease过期 → QUEUED（attempt+1）
Child: PLANNED → GRANT_RESERVED → DISPATCHED → ARRIVED → SETTLED
任意非法/超时 → REJECTED/EXPIRED；ARRIVED 幂等写入 Barrier

状态机 C：合并与最终验证

SUBMITTED → VALIDATING → QUEUED → CAS_CHECK → APPLYING → MERGED
                    └→ REJECTED       └→ STALE → REBASE_REQUIRED
MERGED(全部) → FINAL_TESTING → COMPLETE
                         └→ FINAL_TEST_FAILED → RECOVERY_REQUIRED

所有转换使用 entityVersion 乐观锁；状态更新与 outbox 事件同事务提交，消费者按 eventId 幂等。

Routing · Complexity Gate

全对话复杂度路由

所有对话入口共享轻量路由，但不强制所有任务进入计划或多 Agent。路由基于目标、完整逻辑会话、未完成承诺、ContextEnvelope manifest、风险、预算与工具需求，输出版本化 ComplexityDecision{simple|moderate|complex|high-risk, inputDigest, routerVersion, reasonCodes}。

档位判定输入路径
simple单步目标、低风险、无跨资源依赖单 Agent 快路径，不进入计划与委派。
moderate多步但有界、低中风险、单工作区单 Agent + Plan 投影；不创建 Child。
complex可拆分子目标相互独立、资源不冲突、预算充足升级多 Agent：DelegationEnvelope fan-out + JoinBarrier 汇合，走本页任务与委派状态机。
high-risk涉及写 effect、外部系统、Secret 或合规边界升级多 Agent 前强制展示目标、假设、可审查计划、风险、进度与证据；高风险 Review 不因路由档位降级。
  • 简单任务走单 Agent 快路径；复杂或高风险任务先向用户展示目标、假设、可审查计划、风险、进度与证据，不展示私有思维链。
  • 低置信、预算不足或 Policy 不允许时降级为单 Agent 或请求澄清，不得静默 fan-out；升级判定与 reasonCodes 全部落审计。
  • Root/Child Run：每次用户触发只有一个 Root Run；Child 保留同一 sessionId/rootRunId，以 parentRunId 关联直接父级；Child 不是新 Session、新信任域或新进程。Child 有效权限是 Root Policy、父委派限制与资源策略的更严格交集，审批 token、Secret lease 和临时 capability 不继承。
  • 恢复：按 root tree、delegation idempotency key、checkpoint、EffectJournal 与 receipt 恢复；outcome_unknown 阻断依赖节点并先对账，不得因崩溃重复 spawn 或重放副作用。

里程碑门禁：M4/M5 期间路由只允许输出单 Agent 路径；complex/high-risk 升级多 Agent 仅 M6 启用，且必须以 M4 Scope Seal 解除（见 Scope Seal 合同）与 M5 安全门禁通过为前提。

05 · Data Flow

fan-out / fan-in / merge

  1. Root 创建任务，策略引擎计算最大深度、fan-out、能力和四维预算。
  2. Parent 为每个 Child 预留预算并签发 DelegationEnvelope；信封不含 Secret 与审批。
  3. 调度器创建隔离 Worker 和独立 worktree，baseHead 被钉扎。
  4. Child 运行并提交 patchDigest、测试证据和 usage；Budget Ledger 原子结算。
  5. JoinBarrier 以 childId+attempt 去重，根据 ALL/QUORUM/FAIL_FAST 封闭。
  6. Root Writer 读取有序 MergeIntent，检查 expectedHead，CAS 成功后应用下一项。
  7. 全部合并后在最终树重新安装锁定依赖并重跑测试/扫描；通过才置 COMPLETE。

06 · Security & Recovery

安全恢复策略

故障检测恢复安全底线
扩展升级崩溃启动探针失败回滚已验证版本并隔离新包不加载未验签缓存
MCP 凭据撤销401/撤销事件熔断、清连接池、要求重新授权不回退到旧 Secret
Worker 失联租约与心跳超时Reaper 杀进程树，回收 worktree，重排任务旧 Worker 恢复后结果因 fencing token 被拒
Barrier 重复到达唯一键冲突返回既有结算结果预算不重复退款
Root Writer 崩溃写租约超时新实例读取 WAL/队列，以 head 校验后续跑同一 fencing epoch 仅一 Writer
最终测试失败测试报告非零保留证据，阻止完成；按逆序生成回退候选不把局部测试当最终成功

Secret Lease 引用约束（衔接 M1）

M6 的 McpEndpoint、Connector 与 Worker 一律只持有 Secret 引用（authRef / credentialRefId）。确需使用明文凭据时，通过 secretLease.acquire 请求（providerId、credentialRef、credentialVersion、规范化 origin、operation、deadline、requestNonce）换取完整性保护 lease frame：TTL≤5 秒、单次消费、≤64KiB；lease 绑定 Engine session/requestNonce/origin/credentialVersion，重放或换绑一律拒绝。明文仅在 connector 调用栈以 []byte 持有，禁止转换为字符串，设置 Authorization 后立即覆盖；不得进入 Renderer、Bridge DTO、日志、审计正文或 Worker job spec（信封只允许 Secret 引用句柄，见分层与信任边界）。

该机制与 M1 Secret/Gateway 基线及全局安全基线同源：API Key 明文禁止跨 Renderer/Bridge/Engine 边界；M6 不得建立第二套凭据通道；凭据撤销（401/撤销事件）即时熔断并要求重新授权，不回退旧 Secret。

05 · Operability

观测、告警与审计

  • 指标：extension_verify_fail_total、mcp_breaker_open、worker_escape_blocked、task_lease_expired、budget_drift、barrier_wait_seconds、merge_cas_conflict、final_test_fail。
  • 链路：rootId、taskId、delegationId、workerId、barrierId、mergeIntentId 共用 traceId。
  • 脱敏：认证头、Secret 值、环境变量、数据库连接串不进入日志；参数只保留 schema 和摘要。
  • 告警：budget_drift 必须为 0；检测到双 Writer、沙箱逃逸或签名撤销立即 P0 封禁。
  • 恢复：重放 outbox 和队列必须幂等；恢复前校验审计哈希链、租约 epoch 与 Git head。

Scope、stdio 交付门禁与 M7 交接

能力上下文显式 scope 合同
personal个人安装/连接与凭据引用；不得读取项目资源。
ad_hoc绑定 AdHocWorkspace 的临时能力；不得因存在项目而升级权限。
project必须携带 projectId、成员鉴权与项目策略；项目只是资源/授权边界，不是能力开关，不能仅凭“在项目中”启用扩展、委派、DB 或网络能力。

与 M5 scope 的映射（权威）：M5 root_run.scope 只有两值——普通聊天 personal/unscoped（绑定 AdHocWorkspace）与项目会话 project。本表三值是能力/安装上下文的 scope，不是 root_run.scope 的扩展：ad_hoc ⇔「绑定 AdHocWorkspace 的 personal/unscoped Run」（workspaceId 非空）；personal ⇔ 与具体 Run/Workspace 无关的用户级安装；project ⇔ M5 project 会话同值直通。M6 不得向 root_run 新增 scope 枚举值，也不得把未绑 Workspace 的 personal/unscoped Run 判为 ad_hoc。

stdio 唯一路径：POC → 受控实现 → 生产逃逸验收，三段均需独立证据和安全签字。POC 通过只允许进入受控实现，不代表生产可用；生产逃逸验收须覆盖宿主文件、网络、Secret、进程树、资源耗尽、协议欺骗与恢复。任一段失败或证据缺失即关闭 stdio 能力，M6 不得宣称“stdio 完整交付”，也不得用 HTTP 能力替代该声明。

MCP 继承：M6 必须继承并扩展 M5 的 HTTPS Remote HTTP MCP 安全子集（TLS/证书、主机 allowlist、SSRF 重查、超时、响应上限、SecretRef、只读过滤基线），复用同一 Gateway、策略与审计链；不得建设第二套 MCP Gateway。

交付 M7 的不可缺失输出

  • rootId 与 final-tree digest，证明 Root 唯一 Writer 后的最终树身份。
  • 全序 MergeIntent 清单（expectedHead/currentHead、patch digest、结果、冲突/重基记录）。
  • 最终树 test evidence（不是 Child 局部测试替代品），绑定 build、rootId 与 final-tree digest。
  • extension SBOM、签名/撤销状态、组件 digest 与许可证/漏洞结论。

持久化与读取通道：上述交付物统一落 m6_root_final（rootId、head_commit、final_tree_digest、state、test_evidence_ref、sbom_digest——状态机 C 根级 FINAL_TESTING→COMPLETE | RECOVERY_REQUIRED 的事实源）、m6_merge_intent 与 m6_extension_artifact；RootWriter 在 CAS 合并与最终测试后同事务写入并发 m6.root.final_complete outbox 事件。M7 仅经「同库只读快照查询 + m6_outbox 订阅（m6.merge.merged/m6.root.final_complete，按 eventId 幂等）」消费（读取通道权威合同见 M7/02「M6 输入适配」）；M7 对 m6_* 表禁写、不复制、不建第二套读取 API。

以上合同均已实现并通过 2026-08-16 全量回归（收口证据 docs/evidence/m6-closure）；诚实边界：S5C 服务（openapi.parse/complexity.decide/skill.import.*）与 CloudRunner 生产装配仍按披露保持关闭（bridge 返回可重试 STORAGE_UNAVAILABLE），stdio Gate 未开放。

健康聚合

人工暂停始终为 paused；无足够窗口样本为 unknown；否则成功率≥99% 为 healthy，90%≤成功率<99% 为 degraded，成功率<90% 为 unhealthy。健康匹配仅用于路由候选，不授予调用权限。

ImportCandidate 外部导入候选

外部 Skill/Profile 资产先成为候选，经流水线治理后才可转为正式资产：发现 → 锁 immutable commit → 许可/NOTICE → 签名/来源证明 → 静态/依赖/Prompt Injection 扫描 → 沙箱评测 → 人工批准 → 产品签名。

字段约束
source_url、immutable_commit、license、notice_refcommit、归档 hash、来源、作者/发布者声明、许可证兼容性与 NOTICE 必须保存；分支/tag/latest 不可作为执行锁。
publisher/signature、source_attestation来源与签名证明；无法验证即停留 quarantined。
scan_refs、injection_scan扫描覆盖 secret、恶意代码、依赖/CVE、Prompt Injection、越权指令、数据外发与混淆内容。
evaluation_id、approval评测在无真实 Secret、默认断网、最小只读数据集的沙箱执行并保存 Evaluation/Evidence；批准记录绑定审批人。
  • 状态机：discovered → pinned → inspected → scanned → evaluated → awaiting_approval → approved | rejected | revoked；全程不可直接 enabled。
  • 批准前始终 quarantined；人工批准后仍须由产品构建密钥签名才可成为内建候选。撤销来源、签名、许可或评测后，关联 ProfileVersion/SkillVersion/PromptBundle 立即禁止新调用并传播 disabled/quarantined。
  • RPC：skill.import.discover / inspect / submit / approve / reject / revoke；导入不等于安装或启用，审批与撤销幂等并审计。
  • 找不到合格候选时，产品团队自建 Skill/Profile 并走相同评测与签名流程；固定官方专家只能是产品签名内建，第三方名称不得伪装官方。
