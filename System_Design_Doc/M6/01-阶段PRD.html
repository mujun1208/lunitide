01 · Boundary

目标与边界

本期目标

  • 可发现、安装、启停、升级、回滚、卸载第三方 Skill/插件，并保留来源与签名审计。
  • 完整支持 HTTP MCP 生命周期；stdio 按“强隔离 POC → 受控实现 → 生产逃逸验收”交付，任一门禁失败即关闭能力且不得宣称完整交付。
  • Connector 与数据库仅暴露 schema、表、字段、索引等元数据读取。
  • 云任务与本地强隔离 Worker 使用统一任务协议。
  • 受治理的 Parent/Child 展开、汇合、预算核算与代码合并。

明确非目标

  • 不覆盖“项目九阶段”和正式发布。
  • 不执行数据库真实写入、DDL 或业务数据读取。
  • 不允许无限递归，不允许 Child 继承审批或 Secret。
  • 不建设多人 TeamSpace、共享席位与团队权限模型。

交付状态已更新为“已实现”（2026-08-16）。阶段顺序固定：HTTP MCP → 强隔离 Worker → stdio POC → 受控实现 → 生产逃逸验收。

FR-616任务树、预算账本、合并日志、扩展证据和错误码可检索导出。按 traceId 可还原完整因果链。

04 · Governance

不可变业务规则

授权

Child 只获得 DelegationEnvelope 显式能力；Parent 的审批票据、Secret 引用、交互会话均不继承。需要敏感能力时回到 Root 重新审批。

预算

CPU 秒、Token、费用、墙钟时间分别记账。划拨先冻结、接受后入账；未启动可原路退回，已消费不可回滚。

写入

Child 只能提交补丁与测试证据；Root Writer 持有最终树租约，以 expectedHead CAS 串行合并，随后对最终树重跑测试。

05 · Acceptance

发布门槛（功能完成判定，不代表正式发布）

  1. 16 项 FR 全部有自动化或审计型验收证据。
  2. HTTP MCP 健康检查、鉴权撤销、熔断与恢复均通过；stdio 默认关闭。
  3. 恶意扩展、依赖投毒、路径穿越、网络逃逸与 Secret 探测被阻断。
  4. 100 个 Child 并发下预算账本守恒，Barrier 不重复结算。
  5. 唯一 Writer 压测无丢补丁、无静默覆盖，CAS 冲突可恢复。
  6. 最终树测试是完成态的必要条件；局部 worktree 测试不能替代。

Scope、stdio 交付门禁与 M7 交接

能力上下文显式 scope 合同
personal个人安装/连接与凭据引用；不得读取项目资源。
ad_hoc绑定 AdHocWorkspace 的临时能力；不得因存在项目而升级权限。
project必须携带 projectId、成员鉴权与项目策略；项目只是资源/授权边界，不是能力开关，不能仅凭“在项目中”启用扩展、委派、DB 或网络能力。
stdio 唯一路径：POC → 受控实现 → 生产逃逸验收，三段均需独立证据和安全签字。POC 通过只允许进入受控实现，不代表生产可用；生产逃逸验收须覆盖宿主文件、网络、Secret、进程树、资源耗尽、协议欺骗与恢复。任一段失败或证据缺失即关闭 stdio 能力，M6 不得宣称“stdio 完整交付”，也不得用 HTTP 能力替代该声明。

MCP 继承：M6 必须继承并扩展 M5 的 HTTPS Remote HTTP MCP 安全子集（TLS/证书、主机 allowlist、SSRF 重查、超时、响应上限、SecretRef、只读过滤基线），复用同一 Gateway、策略与审计链；不得建设第二套 MCP Gateway。

交付 M7 的不可缺失输出

  • rootId 与 final-tree digest，证明 Root 唯一 Writer 后的最终树身份。
  • 全序 MergeIntent 清单（expectedHead/currentHead、patch digest、结果、冲突/重基记录）。
  • 最终树 test evidence（不是 Child 局部测试替代品），绑定 build、rootId 与 final-tree digest。
  • extension SBOM、签名/撤销状态、组件 digest 与许可证/漏洞结论。

以上合同均已实现并通过 2026-08-16 全量回归（收口证据 docs/evidence/m6-closure）；诚实边界：S5C 服务（openapi.parse/complexity.decide/skill.import.*）与 CloudRunner 生产装配仍按披露保持关闭（bridge 返回可重试 STORAGE_UNAVAILABLE），stdio Gate 未开放。

DEFER-M6-ODATA-01 · OData 完整保留合同（future capability）

OData v4 使用 HTTP Client/Service，不等于数据库直连。对象包含 service_root、version、metadata digest/cached_at、CredentialRef、read_only=true，以及 entity set 的 allowed_query_options、writable=false、etag_enabled。默认只读，支持 CSDL metadata、entity set、$select/$filter/$orderby/$top/$skip 与 @odata.nextLink；每次 nextLink 重验 SSRF。写操作只有后续独立 ADR 按 entity-set 显式开启、独立凭据、Review、If-Match 和审计后才可用。

不建立冲突的 OData 运行状态机：配置复用 Integration draft/enabled/disabled；健康为 unknown/healthy/degraded/unhealthy/paused；调用为 success/error/timeout。metadata/schema/config digest 漂移使测试与授权失效并回到 draft/disabled。

健康、云隔离与多 Agent 验收

  • HealthSample 使用滑动窗口：样本充足时成功率≥99% healthy，90%≤成功率<99% degraded，<90% 或连续失败超阈值 unhealthy；人工暂停优先 paused，健康不得扩大权限。
  • Child 有效权限是 Root Policy、父委派与资源策略交集，不继承审批、Secret lease、临时 capability；默认递归深度 1。
  • required Child 缺失、安全/测试失败不得被 QUORUM 多数覆盖；Root cancel/deadline 下传，迟到结果不能反转终态。
  • 云执行必须绑定 tenant/scope、region/驻留、workload identity、mTLS、远程出口策略、配额、成本与远程 receipt；断网结果不明进入 outcome_unknown。
  • 唯一 Writer 使用 fencing token/CAS 合并 PatchProposal，最终树重跑 required tests/scans。

受治理并行 Harness 产品增量

  • 复杂度路由只在可证明存在独立子目标、上下文隔离收益或可并行验证时创建 Child；简单任务保持 M5 单 Agent 快路径。

  • 多 Agent 的目标是提高复杂任务存活率与速度，不得降低 Policy、审批、预算、最终树验证或人工可理解性。
  • 第三方 Harness/Agent SDK 不作为默认内核；M6 继续复用 Go Engine durable Run，并通过开放协议/隔离 Worker 接入经核验生态。
