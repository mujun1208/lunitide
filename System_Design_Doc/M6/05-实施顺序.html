五切片实施顺序

顺序固定：扩展供应链与 HTTP MCP → 元数据与强隔离 Worker → 云任务与委派 → 唯一 Writer → stdio 强隔离 POC 与收口。

stdio 不因进入第五切片而自动开放；只有强隔离 POC 六项证据和独立安全评审全部通过，才允许决定是否实现。

03 · Delivery

五个纵向实施切片

切片 1｜扩展供应链与 HTTP MCP 基线

范围：Artifact/Install、目录 UI、验签/SBOM/权限差异、HTTP MCP 登记/探测/调用/熔断/撤销、审计链。

完成条件：恶意包测试全部阻断；HTTP MCP 全生命周期可用；Secret 日志扫描为零泄漏。stdio 保持禁用。

切片 2｜Connector 元数据与强隔离 Worker

范围：CatalogAdapter 双白名单、快照 UI；Worker 身份、网络/文件/资源隔离、租约、Reaper、fencing。

完成条件：DB 写/业务读取均拒绝；沙箱路径、网络、Secret、资源和失联攻击测试通过。

切片 3｜云任务与受治理 fan-out/fan-in

范围：CloudTask、DelegationEnvelope、BudgetLedger、JoinBarrier、任务树 UI；限制深度/总数；不继承审批和 Secret。

完成条件：100 Child 并发账本守恒；三种 Barrier 策略、重复消息、取消退款、租约恢复通过。

切片 4｜Child worktree 与 Root 唯一 Writer

范围：隔离 worktree、补丁清单、MergeIntent 全序、Writer 租约 fencing、Git head CAS、冲突恢复、最终树测试；m6_merge_intent/m6_root_final 建表与同事务落库、m6.root.final_complete outbox 事件。

完成条件：无非 Root 写入；崩溃恢复不重复应用；最终树失败绝不进入 COMPLETE；COMPLETE 状态与 m6.root.final_complete 事件同事务恰好一次写入 m6_root_final，且 final_tree_digest 等于 head_commit 的树摘要（M7 读取通道事实源）。

切片 5A｜stdio 强隔离 POC

范围：验证宿主文件、网络、Secret、进程树、资源耗尽与协议欺骗六类隔离假设。

完成条件：独立安全评审通过只允许进入 5B 开发；生产配置仍为 DISABLED，失败则关闭 stdio 范围。

切片 5B｜stdio 受控实现

范围：实现真实隔离 Worker、签名启动规格、帧协议、供应链校验、恢复、撤销、资源与审计合同；功能默认关闭。

完成条件：契约、恢复、撤销和负测绑定同一 build/config digest；不得以 POC 工件代替生产实现。

切片 5C｜生产逃逸验收与整体验收

范围：对 5B 真实实现执行宿主文件、网络、Secret、进程树、资源耗尽、协议欺骗、崩溃恢复和撤销红队；同时完成故障注入、审计导出、可访问性、容量和运行手册验证。

完成条件：5A/5B/5C 三段证据绑定同一 build/config digest 并由 Security Owner 签字后才可生产启用；任一失败即保持关闭，M6 不得宣称 stdio 完整交付。

04 · Quality Gates

实施门禁与退出规则

门禁必须满足阻断条件
G1 供应链签名、摘要、SBOM、权限增量自动验证任一高危绕过
G2 隔离Worker 沙箱红队用例通过宿主/Secret/内网可达
G3 守恒并发与故障注入下 budget_drift=0负余额、重复退款、跨树转账
G4 Writer单 Writer、CAS、WAL 恢复、最终树测试通过静默覆盖或双写
G5a stdio POC六类隔离假设证据+独立安全评审；仅允许进入开发任一项失败或试图生产启用
G5b stdio 受控实现真实 Worker、签名协议、供应链、恢复、撤销与负测绑定同一 digest默认开启、POC 工件冒充实现或证据漂移
G5c stdio 生产逃逸验收八类红队与恢复验收通过，5A/5B/5C 同 build/config digest，Security Owner 签字任一逃逸、结果未知、撤销失效或证据缺失

容量基线

  • 目录查询 P95≤500ms；HTTP MCP 网关额外开销 P95≤80ms（不含远端）。
  • 单 Root 支持 100 Child、16 并行 Worker、1000 条 MergeIntent 队列。
  • Barrier arrival P95≤200ms；Writer 恢复 RTO≤60s；审计事件零丢失。

Scope、stdio 交付门禁与 M7 交接

能力上下文显式 scope 合同
personal个人安装/连接与凭据引用；不得读取项目资源。
ad_hoc绑定 AdHocWorkspace 的临时能力；不得因存在项目而升级权限。
project必须携带 projectId、成员鉴权与项目策略；项目只是资源/授权边界，不是能力开关，不能仅凭“在项目中”启用扩展、委派、DB 或网络能力。
stdio 唯一路径：POC → 受控实现 → 生产逃逸验收，三段均需独立证据和安全签字。POC 通过只允许进入受控实现，不代表生产可用；生产逃逸验收须覆盖宿主文件、网络、Secret、进程树、资源耗尽、协议欺骗与恢复。任一段失败或证据缺失即关闭 stdio 能力，M6 不得宣称“stdio 完整交付”，也不得用 HTTP 能力替代该声明。

MCP 继承：M6 必须继承并扩展 M5 的 HTTPS Remote HTTP MCP 安全子集（TLS/证书、主机 allowlist、SSRF 重查、超时、响应上限、SecretRef、只读过滤基线），复用同一 Gateway、策略与审计链；不得建设第二套 MCP Gateway。

交付 M7 的不可缺失输出

  • rootId 与 final-tree digest，证明 Root 唯一 Writer 后的最终树身份。
  • 全序 MergeIntent 清单（expectedHead/currentHead、patch digest、结果、冲突/重基记录）。
  • 最终树 test evidence（不是 Child 局部测试替代品），绑定 build、rootId 与 final-tree digest。
  • extension SBOM、签名/撤销状态、组件 digest 与许可证/漏洞结论。

以上均为待实现合同，不表示当前已产出或已通过。
