组织治理、共享市场与混合执行 PRD

建立组织隔离、只可收紧的层级策略、职责分离、N-of-M、预算、审计与运营控制面。

架构阻断

受 ADR-011 等决策阻断。Organization 边界、企业身份、策略合并、Runner 信任、审计保留和市场签名根未决前，生产能力保持关闭；本文不假定决策已批准。

功能需求与 GWT

ID需求规则Given / When / Then
FR-01Organization组织是计费、策略、审计和隔离根；停用不等于清除。给定组织停用；当成员访问；则拒绝新会话并保留被 Hold 数据。
FR-02TeamSpace继承同组织策略，成员与资产按空间隔离。给定用户属于两空间；当搜索；则仅当前空间参与召回。
FR-03身份角色支持人类、服务、外部身份和限时角色，默认最小权限。给定外部身份到期；当请求；则令牌与批准票失效。
FR-04PolicyCenter平台→组织→空间→项目只可收紧，无法证明则拒绝。给定子级放宽父规则；当保存；则拒绝并定位冲突来源。
FR-05职责分离请求、审批、执行、审计角色可互斥。给定请求者尝试自批；当 SoD 生效；则拒绝并审计。
FR-06N-of-MM 名冻结候选中至少 N 名独立有效批准；撤票重算。给定 2-of-3 已达标；当一票撤回；则回 WAITING_APPROVAL。
FR-07共享能力市场支持发布、签名、审核、安装、撤回和隔离。给定签名失效；当安装；则隔离；不自行声称第三方许可兼容。
FR-08混合 Runner本地、托管、云 Runner 按驻留、能力和信任路由。给定数据禁止出域；当仅云 Runner 可用；则阻断而不外发。
FR-09预算组织/空间/项目/运行支持软硬限额、预留和结算。给定硬预算不足；当派发；则拒绝且不产生 Runner 成本。
FR-10合规审计追加式证据链、导出、访问复核，正文最小化。给定审计导出；当校验；则摘要链连续且裁剪正确。
FR-11Legal Hold保全优先于常规删除，激活、访问、解除均审计。给定删除命中保全；当执行；则用户侧隐藏并转受限证据库。
FR-12运营度量采用、失败、审批时延、预算、Runner 健康和安全指标；聚合输出必须满足最小样本阈值（k 阈值，随 D-5 隐私决策冻结，口径见 02 驻留与评测边界），禁止按提示、文件、个人轨迹或存在性下钻。给定查看者无内容权；当查看；则仅见满足最小样本阈值（k）的聚合，低于阈值一律显示「样本不足」。

前置决策与边界

ADR-011 须明确组织租户边界；相关决策须明确 SSO/SCIM、服务身份、策略代数、Runner 证明与驻留、Legal Hold 权威流程、市场签名与许可审查。许可只记录正式审查结果，工程文档不提供法律意见。

个人资产进入组织的硬边界

M8 个人资产默认私有。个人→组织仅允许本人显式选择，完成脱敏预览、按组织目的重新授权，并生成独立、可撤回、可追溯的组织版本；不得改变或引用私人原件作为组织可读对象。组织管理员、审计员和支持人员均不得读取私人思维过程、聊天正文或未发布记忆，也不得通过搜索、指标或审计侧信道推断其存在。

唯一内核：M9 仅在 M6 生态/Worker/CloudTask 上叠加组织治理，不建设第二套 Registry、Runner 或执行状态机。

组织级增量合同与全局治理边界

范围裁决：Policy Engine、单主体 Review、TOCTOU、ConsentSnapshot、数据分类、审计、日志、诊断和错误模型是 M0–M8 的全局基线，不依赖 M9，也不得因 ADR-011 未决而关闭。M9 只增加 Organization、TeamSpace、企业身份、N-of-M、Legal Hold、组织市场与混合 Runner 治理。

组织策略与审批

能力完整合同
策略层级platform→organization→teamspace→project→run 只可收紧；allowlist 交集、denylist 并集、预算取最小、强制 Review 取更严格。无法证明单调性时拒绝发布。
身份human/service/external，绑定 org/teamspace、角色、认证强度、有效期和撤销版本；逻辑 Agent 不是登录用户。
SoD请求、审批、执行、审计角色可互斥；自批、共享身份或过期角色无效。
N-of-M冻结 M 名候选与 N 阈值；批准绑定相同 OperationSnapshot digest，撤票/身份失效/摘要变化立即重算并回 WAITING_APPROVAL。
Legal Hold命中保全的对象对普通用户隐藏但不物理清除，进入受限证据库；激活、访问、导出和解除全审计。

混合执行与市场

Runner 路由输入必须含数据分类、驻留地域、能力、信任证明、网络、Secret、预算和可用性；任何必需约束无匹配 Runner 时阻断，不降级外发。组织市场包发布、审核、签名、安装、撤销与隔离复用 M6 Registry/SkillInstall，不建设第二套生命周期；许可字段只记录正式审查结果，不作法律推断。

退出门禁

  • ADR-011 及企业身份、策略代数、Runner 证明/驻留、Legal Hold 和市场签名根均 Accepted。
  • 跨组织内容和存在性泄漏 0；子级放宽成功 0；SoD 违规执行 0；N-of-M 凭证完整率 100%。
  • 硬预算不足不产生 Runner 成本；驻留违规 0；审计导出 hash chain 连续且内容裁剪正确。
  • 个人资产进入组织必须由本人显式选择、脱敏预览、重新授权并生成独立组织版本；不得让组织侧引用私人原件。

状态机与恢复

对象状态与 Guard
Organization/TeamSpacedraft→active→suspended→closed；suspended 拒绝新运行但保留 Hold/审计；closed 不等于物理删除。
Principal/Bindinginvited/provisioning→active→suspended/expired/revoked；身份或 binding version 变化使未执行批准失效。
PolicyVersiondraft→validating→approved→published；失败 rejected；新版本 supersedes 旧版但不改写历史。单调性无法证明即拒绝。
ApprovalRequestpending→waiting_approval→approved/rejected/expired/cancelled；撤票或身份失效可使 approved 回 waiting_approval，但已执行事实不可反转。
Runnerregistering→attesting→online→draining→offline；证明失败 quarantined。心跳丢失且结果不明的任务进入 outcome_unknown 并对账。
BudgetReservationpending→reserved→committed/released/expired；结算 receipt 不明为 outcome_unknown，禁止重复扣费或退款。
LegalHolddraft→active→release_requested→released；active 时普通删除只隐藏并转受限证据库，释放需独立授权和审计。

上述为可评审产品合同，不是开工授权。ADR-011、身份/策略/Runner/Legal Hold/签名根决策未 Accepted 前，不得创建生产 schema、Bridge API 或启用 UI。

组织级 Harness 与评测治理增量

  • 组织可治理 Profile/Prompt/Skill/Tool/Golden Task/Policy 包，但不能读取私人聊天、思维过程、未发布记忆或个人评测样本。
  • 组织自动化必须显示责任主体、预算、数据驻留、允许 Runner、审批和停止条件；“全自动”不等于取消 SoD/N-of-M 或结果对账。
  • 跨团队复用以签名、版本化、可撤销的组织 Artifact 为边界；个人资产须显式复制、脱敏和重新授权。
  • ADR-011 accepted 前，本节仅为产品与威胁设计，不授权生产 schema/API 开发。
