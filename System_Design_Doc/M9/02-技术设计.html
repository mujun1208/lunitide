M9 技术设计

组织控制面、策略代数、审批预算、市场签名、混合 Runner 与合规恢复。

控制面 / 数据面

Enterprise IdP → Identity Bridge → Org Directory
Request → PolicyCenter → Approval + Budget → Execution Governance Projection → M6 Runner Broker
Capability Market → Review/Sign → Registry       ├→ Local Runner
Audit Outbox → Evidence Vault / Legal Hold       ├→ Managed Runner
                         └→ Metric Aggregator     └→ Cloud Runner

控制面签发绑定组织、策略版本、包摘要、预算预留和有效期的短期能力票据；数据面不得放宽策略。除平台全局只读目录外，所有控制面与数据面资源都以不可变 org_id 为隔离根；该值只能从已验证会话或签名能力票据导出，不接受请求正文、查询参数或 Runner 自报覆盖。

组织隔离不变量

  • 除经审核发布、不可由租户写入的平台全局只读目录外，所有实体、event、outbox、账本、审批、Runner 任务、blob、cache 与 queue 记录创建时都必须写入不可变 org_id；禁止后续 UPDATE 改绑组织。
  • Repository/ORM 在每条读写、关联、聚合和删除查询中强制注入 org_id = :verified_org_id 谓词；缺少组织上下文即 fail closed，禁止调用方选择性关闭。
  • 主键引用使用 (org_id, id) 复合外键，业务唯一性使用包含 org_id 的复合唯一键；对象存储路径、blob 引用、缓存 key、幂等/去重 key、queue topic/partition 与死信队列均带组织前缀并验证票据组织。
  • 后台消费者、定时任务、索引重建、备份恢复、数据迁移、支持工具与管理员操作同样从已验证会话或签名票据取得组织上下文，不得使用 super-tenant、缺省组织或关闭谓词绕过；跨组织运维必须拆分成逐组织授权、执行和审计的任务。

PolicyCenter 与审批

  • 约束规范化后：允许集合取交集，上限取最小，禁止项与必需项取并集；无法证明“相等或更严格”即拒绝发布。
  • 请求、投票、派发、审计动作计算互斥角色；服务身份不能替代必须的人类批准。
  • M 候选在请求创建时冻结；每票绑定请求摘要和策略版本；撤回、身份过期或策略收紧触发重算。
  • 派发前原子预留多层预算，回执后结算；失联释放到期预留，但运行进入状态不明隔离。

Execution Governance 只读投影与安全恢复（复用 M6）

禁止第二状态机：下表不是可写聚合或持久化 FSM。RECEIVED/POLICY_LOCKED/WAITING_APPROVAL/BUDGET_RESERVED/ROUTED 分别投影 PolicyDecision、ApprovalRequest、BudgetReservation 与 RouteDecision；DISPATCHED/CHECKPOINTED/SUCCEEDED/UNKNOWN/COMPENSATING 直接投影 M6 CloudTask/Runner canonical 状态和事件。M9 不得独立推进、重试、补偿、写第二账本或创建第二 checkpoint；投影冲突时以 M6 事实与 M9 治理实体分别对账并 fail-closed。

只读投影来源与门禁恢复语义
RECEIVED组织、空间、主体有效幂等键返回原执行
POLICY_LOCKED策略可验证且只收紧策略变严时重新求值
WAITING_APPROVALSoD 与 N-of-M 候选冻结撤票/身份过期回退等待
BUDGET_RESERVED多层账本预留成功超时释放；重放不重复扣款
ROUTEDRunner 信任、驻留、能力匹配无安全 Runner 则 BLOCKED
DISPATCHED票据绑定包摘要和运行失联转 UNKNOWN，不自动另跑有副作用步骤
CHECKPOINTED签名检查点和输出摘要入库重验身份、策略、Hold 后恢复
SUCCEEDED回执、结算、审计链齐全只读终态
COMPENSATING可逆步骤逆序执行失败转 QUARANTINED
BLOCKED/UNKNOWN/QUARANTINED门禁不确定或证据矛盾只允许诊断、终止或独立批准恢复

市场、审计与 Legal Hold

  • 包内容寻址、签名、恶意扫描、权限清单、审核结论彼此分离；撤回传播至 Broker 与 Runner 缓存。
  • 心跳不是 Runner 信任证明；注册、证明、短期票据、网络出口和驻留标签共同决定路由。
  • 领域事务与 Audit Outbox 同提交；事件按组织分区串联摘要，跨区使用签名检查点。
  • 清除先查保全投影并二次查权威库；命中转受限证据库并留替代墓碑。
  • 恢复时先加载 Legal Hold、策略和身份吊销水位，再开放读取；随后按 org_id 分区重放账本、审批和审计投影。恢复器与管理员不能绕过组织谓词、复合 FK 或存储/缓存/队列分区。

M6 复用与组织覆盖层

图中的 Registry、Execution Bridge、Runner Broker 与 Runner 状态全部是 M6 生态/Worker/CloudTask 的既有组件与状态投影。M9 只提供组织目录解析、审批凭证、不可变 org_id、驻留标签、预算预留和只可收紧策略，作为 M6 派发前置门禁与票据约束；禁止复制 Registry、Runner 租约/检查点/重试/补偿或另建执行状态机。

个人资产发布适配器只接收 M8 生成的组织版本及其脱敏证明、重新授权票据和来源摘要；M6/M9 永不接收私人原件、思维过程或未发布记忆。撤回组织版本向 M6 Registry 缓存和任务输入传播 tombstone，不影响私人原件的私有控制权。
