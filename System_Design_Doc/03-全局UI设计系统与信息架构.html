3.2 对话优先的轻量开发工作台

Lunitide MUST 集成完整的代码开发闭环，但不得复制一套重型 IDE。默认主画布始终是对话；进入开发任务或点击文件、命令、预览、变更对象时，按需展开一个统一工作面板。

对话主画布

目标澄清、实现说明、工具结果摘要、审批卡片和下一步动作。

统一工作面板

文件、代码、终端、浏览器、变更五种互斥视图，支持关闭、轻览和聚焦三种状态。

按需抽屉

计划、活动、上下文、审批详情；默认收起且不永久压缩对话。

长上下文、压缩与跨窗口续接

  • 百万 token 是逻辑容量，不是每轮直塞：单会话以固定版本的 canonical tokenizer 计量累计可重建内容，至少支持 1M tokens；每次请求另用当前模型 tokenizer 估算，由 Context Builder 按真实窗口、输出预留、工具预算和任务相关性动态装配。
  • 自动 + 手动压缩：接近窗口预算时后台生成新摘要版本；用户也可执行“压缩上下文”，预览压缩范围、摘要差异和保留项。压缩失败不得破坏当前可用上下文。
  • 类 Codex 续接：当前会话可“续接到新对话”，生成 Context Handoff；新对话展示来源、生成时间、覆盖消息范围和待办后再导入，且可返回原会话查证。
  • 保真与追溯：摘要和 Handoff MUST 结构化保存目标、关键决策及理由、硬约束、未完成任务、文件/符号/版本引用、工具与验证结果、风险和建议下一步；每个事实/状态/决策/约束/任务/证据 claim 均关联叶级来源，建议与推断须显式标型并保存推导来源。
  • 原文保留：压缩只新增派生版本，MUST NOT 改写或删除源 Message。只有用户显式发起的数据删除/保留期策略才可删除，并使所有摘要、索引和 Handoff 失效或重建。

请求预算利用率统一按 requiredTokens / effectiveWindow 计算：effectiveWindow = min(provider context window, input/output limit) - tokenizer safety margin；requiredTokens 包含 system、tool schema、选定上下文、当前输入、最大输出预留和工具续接预留。能力未知时必须采用保守默认值。

请求预算利用率默认动作用户感知
请求预算 < 70%近期消息 + 相关历史 + 引用按预算装配显示剩余上下文，不打扰
70%–85%预生成增量摘要、外置大工具输出、保留输出预算轻量提示“正在整理上下文”
85%–95%启用已校验摘要替换较老片段；可手动预览/重做显示压缩版本与可追溯入口
≥ 95%完成压缩并重新预算后再调用；仍超预算则返回 CONTEXT_BUDGET_EXCEEDED 并建议续接新对话不得用静默截断或越窗请求冒充成功
容量与分页解耦：消息列表单次 RPC/API 的 pageSize、payload 字节上限仅保护传输和渲染，不得实现成单会话消息数或 token 总上限；历史使用稳定 cursor 按 message.sequence 分页。
视图内置能力明确边界
文件任务相关文件、轻量目录树、搜索、加入上下文不默认递归展开整个仓库
代码语法高亮、单文件轻编辑、选区解释/修改、诊断、inline diff不自建完整 LSP、调试器和插件生态
终端Agent 命令与用户终端、流式输出、停止、重跑、解释错误任意 shell 不直接暴露给 Renderer
浏览器本地预览、导航、视口、截图、控制台/请求错误摘要不复制完整 DevTools
变更逐文件 diff、接受/撤销、增删行统计、任务与来源追踪提交、push、发布是独立风险动作
外部编辑器协作：首期支持将项目、文件、行列和 Diff 定位到 Visual Studio Code；后续通过 EditorAdapter 扩展其他编辑器。月汐保有任务、策略、工具运行和变更证据的权威状态。
模式语义：“协作 / 代码”不是两个割裂产品。切换只改变默认工具集、上下文预算和面板建议，不丢失会话、任务、计划或审批状态。V2.0 右侧工作区权威投影为预览 / 浏览器 / CLI·终端 / 文件管理 / 计划五面板（见第 2 节与 06）；本节文件 / 代码 / 终端 / 浏览器 / 变更五视图为其能力基线，实施以 06 与 M5 细化为准。

3.3 开发交互与权限分级

  1. 用户从对话描述任务，系统绑定项目、阶段、DevTask、来源产物与工作区根目录。
  2. Agent 先读取相关文件并提出计划；文件写入前创建 checkpoint，变更进入 ChangeSet。
  3. 命令、测试和浏览器验证以流式卡片回到对话，完整输出留在工作面板。
  4. 用户逐文件审查；应用到工作区不等于 commit，commit 不等于 push。
  5. 结果绑定 CodeChange、TestRun、ScanRun 和 TraceLink，满足门禁后进入 review/test。
能力默认策略示例
只读工作区内自动放行并审计列目录、读文件、搜索、Git status
可回退写入限定工作区 + checkpoint；按项目策略自动或确认新增/修改源码、格式化
本地执行命令规格/参数白名单；资源和时限约束lint、test、build、dev server
敏感副作用必须审批工作区外写入、安装依赖、联网命令、删除、Git push
高风险外部动作强确认 + 参数哈希 + 过期发布、部署、凭据使用、生产数据操作
与 Engine 裁决的关系：本表是 UI 层权限分级投影；权限投影只隐藏/禁用不可用动作，不构成授权，Engine 仍逐请求按 capability、Policy 与审批状态裁决（见第 1 节冻结规则）。

3.4 基础设置（导航级概述）

低频系统能力不得常驻侧栏，统一收进设置：

  • 常规：启动页（默认新对话）、语言、自动保存、最近项目数量
  • 外观：黑色星空主题、界面密度、字号/代码字体、星闪与减少动态效果
  • 模型与供应商：默认 Provider/模型、上下文策略、流式输出，以及既有自动/协作/代码工作模式
  • 项目默认值：默认目录、索引忽略、文件监视与 Git 行为
  • 连接与代理：接口、MCP、插件与代理；MCP 服务器管理（/settings/mcp，M7 FR-25）与插件管理（/settings/plugins，M8 FR-18）同属本分区并列展示，安装/添加仅经设置内三步确认流（权限清单→来源与签名核对→确认），对话流不出现安装捷径；Provider API Key 在 Host-owned 原生安全控件中默认短时直接显示并可隐藏/更新；其他 secret 仅覆盖式更新
  • 安全与治理：外发边界、风险策略、审批通知和数据保留
  • 数据与记忆：记忆、导入导出、备份恢复与缓存
  • 技能 / 专家 / 快捷键 / 诊断与更新 / 关于
设置中心实施合同：作用域层级（built-in default → application/workspace → project → Mandatory Policy）、保存与权威值（validate → patch 原子保存、draft 不落 localStorage、outcome_unknown 查询）、完成门禁等实施细节由 M3 承载，详见 M3 · 02 技术设计 · 设置中心作用域与权威值。

响应式与无障碍基线

  • 键盘顺序与视觉顺序一致；所有交互都有可见 :focus-visible。
  • 正文不依赖固定高度；360px 宽度不产生页面级横向滚动，宽表格局部滚动。
  • 状态使用文字、图标与颜色共同表达；目标对比度按 WCAG AA 验证。
  • prefers-reduced-motion 下关闭平滑滚动、位移与装饰动画。
  • 流式输出使用克制的 ARIA live 摘要，避免逐 token 朗读。
UI 不替代授权；Renderer 永远不是策略权威。
