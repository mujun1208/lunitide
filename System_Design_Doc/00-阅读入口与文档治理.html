阅读入口与文档治理

定义新版全局文档的阅读顺序、权威关系、状态语言、变更过程与外部验收口径，防止“已实现”等同于“已验收”。

阅读顺序从路线到实现权威层级冲突如何裁决规范用语规范词与优先级链变更治理可审计且可回滚

1. 推荐阅读顺序

  1. 总 PRD：确认阶段结果、依赖、非目标与指标。
  2. 架构与安全：确认生产技术栈和不可绕过边界。
  3. UI/IA：确认普通聊天与项目分离、状态表达。
  4. 矩阵：确认能力借鉴不等于依赖准入。
  5. 追踪：下钻至每个里程碑五件套。

3. 规范用语与优先级裁决

完整继承 v1 PRD 1.1「规范词」、实施基线「命名裁决」与「M4–M7 冲突关闭」的裁决结论，并按 V2.0 的 M0–M9.5 与五件套口径适配；本节是全部文档与实现描述的用语权威。

3.1 规范词表（规范用语与禁用表述）

规范词语义偏离后果
MUST / 必须编码与验收不可省略项缺失即不满足验收
MUST NOT / 禁止违反即阻断合并或发布阻断合并/发布
SHOULD / 应当原则上实现任何偏离必须提交 ADR
MAY / 可以按里程碑选择不选择不构成缺陷
ADR 固化红线：Open / Deferred ADR 未批准前，不得由实现者自行固化或扩展范围。禁用表述示例：对未验收内容使用“已定稿”“已上线”“已外部验收”（与第 4 节状态表冲突）；推荐表述：明确使用“实现基线 / 内部验证 / 正式外部验收”三档状态词。

3.2 命名与优先级链裁决顺序

命名裁决：产品实施阶段统一称 Milestone（v1 基线为 M0–M7，V2.0 权威口径扩展为 M0–M9.5；M9.5 月伴对话为依赖 M2 既有能力的体验层增量，可与 M8/M9 并行）；开发任务（DevTask）紧急度继续使用 priority P0–P3。两者不得混用：Milestone 表达交付阶段与门禁，P0–P3 表达任务内紧急度。M0 是风险 POC，M1 是契约底座，M2 才是首个可安装对话 Alpha；不得把 POC 或静态原型宣传为可用产品。
裁决场景裁决顺序 / 规则来源（V1）
文档间冲突已接受 ADR > 架构（02）> PRD 里程碑边界（01）> 阶段五件套细化文档 > UI 蓝图（06 / 旧版 Mockup）。即 v1 关闭裁决 ADR > Architecture > PRD milestone boundary > Module Detail > S5–S9 > Mockup 在 V2.0 的映射，与第 2 节权威层级一致。lunitide-prd.html「M4–M7 冲突关闭与 ADR 阻断」（已关闭）
策略 / 规则冲突最严优先：多条策略对同一操作给出不同结论时，按“取更严格者”裁决，而非按优先级或时间顺序择一。lunitide-concepts-design.html · Governance 冲突裁决
模型输出 vs 系统策略不可改写红线：模型和 Review Agent 都不能修改系统强制策略；治理规则属于信任根的一部分，任何模型输出、Agent 建议都不得直接写回策略库，必须经由独立的人工治理流程。lunitide-concepts-design.html · Governance 红线

4. 文档状态与工程级 Definition of Done

状态进入条件禁止表述
草案结构与责任人清晰，可评审“已定稿”“已上线”
候选基线链接、术语、路线、架构互相一致“已外部验收”
已接受主代理/指定评审者验收；决策记录可追溯擅自扩大阶段范围
已废止有替代文档和迁移映射；发布工作目录可删除旧文件删除前未确认版本历史与 legacy 清单可追溯
工程级 DoR/DoD 分工：需求项进入实现前（Definition of Ready）与完成时（Definition of Done）的全部工程级条目、M0–M2 早期交付启动清单的权威定义在 01 总 PRD · 2.2 里程碑门禁；本页只承载文档级状态语言与治理定义，避免两处重复维护。
禁止开工方式（v1 工程级基线，完整继承）：禁止先复制 Python 业务到 Go 而不定义领域端口；禁止保留 Electron 作为正式壳；禁止 React 直连 SQLite/模型/密钥；禁止先做全量九阶段 UI 再补状态和数据；禁止把 Open ADR 隐式固化；禁止用单一 happy path 演示代替故障、安全和恢复验收。

5. 冻结决策记录

DR-20260814-01 · M5 开工与 M4 Scope Seal：用户于 2026-08-14 明确裁决 M0–M4 主体代码视同完成、M5 可开工。该裁决不自动证明内部验证、不关闭 M4 Scope Seal 或正式外验。Scope Seal 可在 M5 开发期间并行修复和集成，但在五项隔离证据绑定同一 RC digest 前，M4 不得标记冻结退出、M5 不得对外发布、M6 Child/fan-out 不得启用。

6. 变更流程

提出变更 → 标注受影响需求/ADR/里程碑 → 安全与数据评审
→ 更新全局文档及追踪矩阵 → 更新阶段五件套 → 自动链接检查
→ 验收证据 → 接受/拒绝 → 发布变更记录
  • 路线、生产栈、状态机、数据保留和权限变化必须有 ADR 或决策记录；ADR 索引以追踪表为入口。ADR-011 当前为 proposed / blocked，Architecture Owner 主责、Product 与 Security Owner 会签，未接受前 M9 仅可设计，不得开展 schema/API 开发。
  • 安全边界不得由 UI 开关或“用户已同意”绕过。
  • 依赖许可证未知时状态必须为“待核验、不可引入”。
  • 旧 11 份文件仅作迁移输入；映射维护在 旧版映射。发布工作目录可在替换门禁通过后删除旧文件；历史证据由版本历史与 legacy 删除清单共同保留，不要求工作目录长期双轨。

7. 新入口替换门禁

替换 index.html 前必须全部满足：9 个根级 HTML、M0–M9.5 各五件套（M0–M9 十个里程碑 + M9.5 月伴对话，共 55 份）和 2 个共享资源全部存在且内部链接无断链；页面均引用共享 CSS/JS；M0–M9.5 路线、五件套路径、生产栈和许可证措辞经主代理验收。当前可复现结构校验记录：2026-08-15，基线 4488d8f2aae2，执行 python validate_ui_docs.py：60 个 HTML、821 个引用、0 个断链/结构错误。桌面 Chrome 已实测完整 UI 页首屏、项目三栏工作台及 CLI/终端标签切换；该记录仍不得表述为键盘、读屏、对比度或 WCAG a11y 完整验收通过；浏览器 a11y 仍需独立执行并留证。
