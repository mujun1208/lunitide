用户旅程与信息架构

  1. 首次启动进入对话优先首页，可直接新建普通聊天；不得自动创建或绑定项目。
  2. 左栏只含新对话、最近会话、项目、搜索和设置；九阶段、计划、活动只在进入具体项目后展开。
  3. 用户选择 Provider/模型，发送消息，查看流式输出，取消或在断线后恢复；失败不得丢失已接收内容。
  4. 用户在设置中查看 effective value、来源、继承关系，原子保存或恢复继承。

聊天需求

ID合同
FR-M2-01ChatSession 默认属于 personal 普通聊天域；project_id/stage_run_id 必须为空。项目会话只能在项目路由显式创建，二者导航、列表、搜索 scope 与权限分离。
FR-M2-02Message 以 session_id+sequence 严格递增并 append-only；状态为 accepted→streaming→completed，异常为 cancelled/interrupted/failed。
FR-M2-03取消请求 P95≤2s 到达 Provider；取消后保留已接收 token 并显示 interrupted/cancelled，不伪装 completed。
FR-M2-04关键事件按 streamId+seq 无重无漏；纯 token delta 可合并或丢弃，但重连必须返回权威 messageSnapshot、nextSeq 与 replayBoundary，用快照替换未确认尾部，确保已确认内容和最终持久消息不丢不重；无法继续时提供重试或基于已完成消息新发请求，禁止盲重放不确定副作用。
FR-M2-05安装包需验证版本、AMD64 架构、WebView2 runtime、资源布局和卸载；本阶段是测试/Alpha，不因可安装而宣称正式发布。

Settings 作用域与字段合同

旧 application/workspace/project 映射为新版 global/personal/project；workspace 只有明确绑定项目时映射 project，否则映射 personal。新增 session 只作临时覆盖，不持久扩大权限。

字段规则
SettingDefinitionstable key、value_type/schema、default、allowed_scopes、sensitivity、merge_strategy、apply_mode、policy_mode、aliases、migration。
SettingValuescope_type/scope_id、value 或 SecretRef、version、updated_at/actor；secret 不允许普通 value。
ResolvedConfigSnapshotRun 创建时冻结 effective value、来源 scope、definition version 与 policy version；运行中设置变化不静默改写。
ID需求
FR-M2-06Engine 计算 effective value；allowlist 取交集、denylist 取并集、预算取最小，Mandatory Policy 不能被下级放宽。
FR-M2-07批量 patch 全成或全败，携带 expectedVersion；冲突显示脱敏 diff，不使用 last-write-wins。
FR-M2-08导出默认排除 Secret 正文；导入先 preview/validate，再 commit；别名与迁移可进入 requires_reentry/recovery_required。
FR-M2-09保存与 apply 分离：SaveCommit 对批量设置值全成或全败；其后 RuntimeApply 可为 applied/partially_applied/restart_required/apply_failed/outcome_unknown，运行时失败不回滚已提交设置值，但逐 key 结果必须持久并在恢复前沿用上一 ResolvedConfigSnapshot。

Settings UI 状态与验收

initial→loading→ready↔dirty→validating→saving→saved；分支为 validation_error、version_conflict、apply_failed、restart_required、outcome_unknown。双窗口冲突、原子批量保存、继承恢复、敏感导出、迁移失败和会话覆盖过期均有 GWT；Key 在普通 DOM/日志/导出中为 0。
