流式事件协议（Legacy 基线继承）

来源：旧版架构 CH.08.3 与 CH.07.2。流式事件属于三类事件中的 Wire Event（Renderer 流式展示与状态投影），与 Domain Event（与聚合状态同事务写 outbox、至少一次投递、按 eventId 去重）和 Audit Event（append-only + hash chain + 外置签名 checkpoint）分轨。事件 envelope：

{
  "v": "1.0",
  "kind": "event",
  "streamId": "run_123",
  "seq": 42,
  "type": "delta",
  "payload": { "text": "..." },
  "occurredAt": "..."
}
事件类型语义
start流开始，携带 streamId 与初始上下文
delta增量 token 文本；纯文本 delta 可合并
tool_call工具调用提案/结果投影
usage用量归一化快照
checkpoint可恢复检查点（关键事件，可重放）
done正常终态；终态后不得再有事件
error错误终态；终态后不得再有事件

顺序与去重：seq 从 1 单调递增；消费者按 (streamId, seq) 去重；completed/failed/cancelled 终态 first-wins（与本文合同明细一致），done/error 之后不得再投递任何事件。

ACK 与背压：Renderer ACK 最近已消费 seq；超过缓冲上限时暂停读取上游或合并纯文本 delta，防止内存放大。

心跳：旧版基线未冻结独立 heartbeat 事件类型；静默期活性由 deadline/流超时与周期性业务事件（usage、checkpoint）兜底。若新版需要独立心跳，须新增事件类型并保持向后兼容——同一 minor 中未知字段忽略，未知枚举返回 BRIDGE_SCHEMA_INVALID，不得静默兼容。

取消：stream.cancel 幂等（2s），取消传递至 Go context 与上游 HTTP 连接，迟到事件不得反转已确认终态。

断线重连与恢复语义：断连后可重放已持久化的关键事件（checkpoint、usage、tool_call 等）；纯 token delta 不承诺全量重放，只保证已 ACK 部分与最终消息持久化一致。崩溃中的消息标记 interrupted，已提交消息不得丢失；恢复只重放事件投影，绝不自动重放外部副作用（对账走幂等记录）。

与新版对齐：本文合同明细"流 sequence 单调，completed/failed/cancelled first-wins"即本协议的压缩表述。M2 三分口径（主体代码/内部验证/外验）不变：本节为设计基线，不表示已实现或门禁已通过。

原子 Save / Apply / 恢复

  1. Save：提交 scope、baseVersion、patch、idempotencyKey；Engine 校验并事务写 validated change_set，不产生外部副作用。
  2. Apply：同一事务 CAS 写 value、递增 scope version、登记 intent/outbox；任一 key 失败则整组不生效；需重启项标 pending restart。
  3. 恢复：启动扫描 change_set/journal；未提交丢弃，已提交投影幂等补齐；结果不明进入只读恢复，可 revert 到 backup/base version。
  4. 迁移：先备份/checksum，再 staging 回填、校验、原子切换；失败保持旧 schema 可读并记 journal。

设置 Bridge 合同

settings.describe/getEffective/previewChange/saveChange/applyChange/revertChange/migration.status 均使用独立 request/success/error schema 与 AppError；success 返回 scopeVersion、effective source、changeSet digest、apply status、restart requirement。Renderer 不得直接写 DB 或自行合并继承。

流恢复与 Settings 两阶段原子性裁决

流：关键事件按 streamId+seq 可重放；token delta 是易失投影。重连响应必须包含 messageSnapshot、nextSeq、replayBoundary、terminalState，Renderer 丢弃 boundary 后未确认尾部并以快照重建，终态后迟到 delta 不得反转。

Settings：SaveCommit 只负责 DB 批量值原子提交；RuntimeApply 在提交后执行并记录逐 key 结果，可为 applied/partially_applied/restart_required/apply_failed/outcome_unknown。运行时失败不篡改已提交值，但依赖一致性的功能继续使用上一 ResolvedConfigSnapshot，直至重启或恢复完成。全局 canonical RPC 为 settings.registry/snapshot/validate/patch/override.remove/change.status；本文旧 describe/getEffective/previewChange/saveChange/applyChange/revertChange 仅是 legacy alias，新 Renderer 禁用。
