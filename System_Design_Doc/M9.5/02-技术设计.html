月伴对话技术设计：舞台状态机、SAPI 本地 TTS 与音频驱动发光

复用 ChatBridge 会话内核与 Web Speech 语音输入，新增仅两块：Go 侧 SAPI TTS 服务（3 个 bridge 方法）与前端月伴舞台（SVG 月亮 + CSS 状态机 + Analyser 驱动光晕）。

总体架构与复用边界

能力来源说明
会话/流式回复复用 M2 ChatBridgechat.start → streamId → delta/completed/failed 事件流；月伴不新建消息通道
语音识别（STT）复用 既有 toggleSpeech 链路getUserMedia + SpeechRecognition（zh-CN final-only）+ 麦克风设备选择 + 音量 Analyser + 既有错误码
语音合成（TTS）新建 本里程碑唯一后端能力Windows SAPI 进程内合成 WAV，离线零网络；bridge 方法 tts.voices / tts.synthesize / tts.cancel
月亮舞台新建 纯前端SVG/CSS 实现，沿用月汐设计变量（--moon/--glow/--tide1~3），随明暗主题换色
设置持久化复用 M2 设置域新增 companion 分组键，零新表零 migration
安全与不变量：SAPI 为进程内 COM 调用，无网络出站；音频与字幕不出本机；月伴会话仍为 scope=personal/unscoped；不新增 WebView2 权限（麦克风预授权已交付）；无第二会话引擎、无第二设置存储。

月伴状态机（前端权威）

状态：idle / listening / thinking / speaking

idle     --[话筒激活]-->        listening
listening--[识别 final/发送]-->  thinking
listening--[取消识别]-->        idle
thinking --[completed 且 TTS 开]--> speaking
thinking --[completed 且 TTS 关/降级]--> idle
thinking --[failed/cancelled]--> idle
speaking --[播放完/打断]-->      idle
speaking --[话筒点击]-->         先 cancel TTS → listening（复合迁移，内部先执行 speaking→idle）
态月亮视觉依据事件
idle缓慢旋转（60s/圈）+ 呼吸微光（4s 周期）初始态/回复结束
listening旋转维持 + 12 柱环绕音量环（复用 speech-wave 语言）getUserMedia 流建立
thinking旋转加速（8s/圈），光晕收拢chat.start 已发出、delta 流动中
speaking旋转冻结；光晕强度与月面径向渐变随 Analyser 音量实时波动发光TTS 音频播放中

实现要点：旋转用单层 transform: rotate() + will-change: transform，由 rAF 写入角度变量（speaking 时角度锁存不递增）；reduce-motion 下旋转角恒为 0，四态仅以光强（box-shadow/filter）与 data-state 文字标签区分——状态不得仅靠动效表达（对齐 03 状态与无障碍基线）。

TTS 运行时（Go，Windows SAPI）

模块与接口

文件职责
internal/tts/sapi_windows.gogo-ole 加载 SAPI.SpVoice；SpFileStream 写 WAV（16kHz mono 16bit）；GetVoices 枚举音色（id/name/gender/lang）；rate 映射 [-10,10]、volume 映射 [0,100]
internal/tts/service.go合成队列与取消：单 flight 合成（同一时刻仅一段占引擎）、cancel 置丢弃标志、分段去重；WAV → base64 返回
internal/tts/fallback_other.go非 Windows 构建的空实现：voices 返回空、synthesize 返回 M95-001（保证跨平台可编译）

bridge 方法（经既有 gateway 路由注册，schema 走代码生成管线）

方法请求响应/错误
tts.voices无参数音色数组（voice_id、display_name、gender、lang）；无可用音色 → M95-001（503）
tts.synthesizetext（≤单段上限 500 字符）、voice_id?、rate?、volume?wav_base64、duration_hint；引擎不可用 M95-001（503）；合成失败 M95-002（500）；音色缺失回退默认并在响应 notice 标注（M95-004，200）
tts.cancel无参数（会话级）200 + notice（M95-003）；未在合成时为幂等空操作

分段与文本清洗

  • 清洗：剔除 markdown 语法符号、代码块整体替换为「代码已省略」、URL 替换为域名、表情符号剔除（SAPI 不朗读）。
  • 分段：按句号/问号/感叹号/换行切分，单段 ≤500 字符（超长句按逗号二次切分）；分段在前端完成后逐段请求（串行，前一段播放至 80% 时预取下一段）。
  • 合成上限：单会话单回复分段数 ≤20，超出截断并在末段追加「后续内容请看字幕」。

音频驱动发光管线（前端）

tts.synthesize 返回 wav_base64
    ↓
Blob → URL.createObjectURL → new Audio(blobUrl)
    ↓ （复用单例 AudioContext；每个 audio 元素仅调一次 createMediaElementSource）
Analyser(fftSize=256) → rAF 读取频谱（节流 30fps）
    ↓
计算 gain = 低频段均值归一化 [0,1]
    ↓
写入 CSS 变量 --moon-gain（舞台根元素）
    ↓
光晕: box-shadow/filter:blur 强度 = f(--moon-gain)
月面: 径向渐变 scale + 亮度 = g(--moon-gain)

工程约束（对应方案评审发现的坑）：AudioContext 全局单例复用，禁止每轮 new（泄漏）；同一 audio 元素 createMediaElementSource 仅允许一次；blobUrl 播放结束即 revokeObjectURL；Analyser 读取节流至 30fps 且 speaking 之外不跑 rAF 循环。

降级与故障链

故障表现处理
SAPI 引擎不可用（Windows N/精简/COM 注册损坏）tts.voices/synthesize 返回 M95-001舞台顶部一次性提示「本机无语音合成引擎，已切换字幕模式」；对话/语音输入不受影响；TTS 控件禁用并说明原因
单段合成失败M95-002跳过该段（字幕保留）继续后续段；连续 3 段失败停止本回复朗读并提示
cancel 回执超时bridge 无响应以前端已静音为准，不重试不弹错；下一段合成前引擎侧队列已自然清空
麦克风/识别失败既有错误码沿用现有提示组件与「打开 Windows 语音设置」指引，月伴状态回 idle

性能与观测

  • 合成时延目标 P95 ≤2s（百字单段）；分段预取在首段播放中并行进行，用户感知等待仅为首段合成。
  • 旋转/发光全部走 compositor 友好属性（transform/opacity/filter），不触发布局；rAF 循环仅在 speaking/listening 存活。
  • 观测：bridge 方法计入既有审计日志（方法名、耗时、错误码、分段序号）；无新增埋点上报（音频/字幕内容不入日志，对齐日志最小化基线）。
