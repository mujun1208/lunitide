CHAPTER 01

ADR-001 强制架构决策

状态 Accepted

正式产品使用 Go Core Engine + Windows WebView2 Host + React/TypeScript UI 三层架构。该决策由用户明确确认，为唯一生产架构基线。

1.1 决策内容

Go Core Engine
全部业务规则、授权、事务、模型连接器、规划、治理、领域状态机、审计
WebView2 Host
窗口、单实例、Bridge 边界、密钥服务、安装更新、进程生命周期
React / TS Renderer
渲染、表单、本地临时 UI 状态、类型化 SDK 调用

1.2 禁止列表

生产架构中不得出现以下技术选型，违反即破坏 ADR-001 基线：
  • 不得将 Electron Chromium 描述为 WebView2（两者引擎不同、安全模型不同）
  • 正式安装包不得依赖 Electron、Node Runtime、Python、FastAPI、Uvicorn 或 PyInstaller
  • 不得把核心业务规则放入 React（Renderer 永远不可信）
  • 不得因当前代码可运行而反向修改目标架构

1.3 原型定位说明

Electron + React + Python 0.2.1 是模型供应商、多模型、BYOK、诊断和打包的功能验证原型。其安全隔离、真实诊断、流式事件、错误归一化、备份恢复和测试经验继续吸收，但相关生产结论已失效。

CHAPTER 03

组件职责

MUST 严格边界

WebView2 Host MUST 负责

  • 窗口管理、单实例锁、WebView2 生命周期
  • Bridge 边界校验（origin / frame / schema / deadline）
  • 本机选择器（文件、目录对话框）
  • 密钥服务（DPAPI / Credential Manager）
  • 安装更新、签名验证
  • 进程启动退出与崩溃恢复

Renderer MUST 只负责

  • UI 渲染、表单交互、本地临时 UI 状态
  • 调用 Host 生成的类型化 SDK
不得直接访问文件系统、注册表、密钥、shell、数据库和任意网络。Renderer 永远不可信。

Go Engine MUST 负责

  • 全部业务规则、授权、事务
  • 模型与连接器（Model Gateway、Integration Hub）
  • 规划（Planner / Orchestrator）、治理（Policy / Review）
  • 领域状态机、审计事件

3.1 数据接口、契约与晋级组件

组件职责边界
ConnectionRegistry管理 development / production（test 可选）环境绑定；按 Connector Registry 的动态 schema 生成配置 UI，覆盖 API、MCP、FAST 自定义、SAP RFC、DB、OData凭据仅存 SecretRef；Renderer 不得获得连接串或密钥
ContractInspector只读采集并比对表、字段、类型、PK、索引和约束，生成 DatabaseContract/ContractObject 差异不是完整 DB IDE，不执行任意 SQL 或直接改结构
MigrationAdapter校验 MigrationPackage、按数据库方言执行 journaled migration，并提供预检/恢复证据仅执行 ReleasePackage 内已签名、已审批迁移
PromotionOrchestrator以同一 digest 将 ReleasePackage 从 development 晋级至 test（可选）和 production；编排 Expand-Migrate-Contract 与门禁快照禁止环境重打包；生产副作用必须再授权
CollaborationLeaseServicepresence、base hash/version 校验、三方合并；管理包冻结与环境导入短租约禁止长锁和 last-write-wins；普通编辑不获取租约

Worker MUST 负责

  • 执行高资源或受控工具
  • Job Object 提供生命周期和资源限制
关键约束：不构成完整安全沙箱。Job Object 只提供生命周期和资源限制，不是安全边界。任意第三方脚本 / stdio MCP 在 AppContainer / 低完整性方案通过 POC 前禁止执行；M0–M2 不开放第三方执行，M5 在隔离 ADR/POC 未通过时仍仅允许签名内建工具。
CHAPTER 04

进程拓扑 ADR-002

ADR-002 Accepted

首期冻结双进程模型：lunitide-desktop.exe（Go Host）与 lunitide-engine.exe（Go Engine），受限 Worker 按需启动。

lunitide-desktop.exe
Go Host
⇄ Named Pipe
lunitide-engine.exe
Go Engine
→ spawn
Worker
Job Object

4.1 Named Pipe 通信

  • Host ↔ Engine 使用当前用户 ACL 的 Windows Named Pipe
  • 握手 MUST 校验：当前用户 SID、客户端 PID、会话 nonce、协议版本
  • 消息使用长度前缀，不以换行作为安全边界
  • Secret plaintext 不通过 Renderer；Engine 通过专用 SecretService 请求短暂使用
  • Pipe frame 最大 4 MiB；大文件只传受控 asset reference
  • Host 创建至少 256-bit 启动密钥，通过不可继承的受限句柄/匿名管道传给其直接子进程 Engine，禁止命令行、环境变量和普通文件传递；握手对 Pipe 实例、双方 PID/创建时间、协议版本和 challenge 做 transcript-bound HMAC
  • Host 校验 Engine 映像绝对路径、file identity、Authenticode signer/hash、父子进程关系与 Job membership；同 SID 抢连、PID 复用、旧握手重放和二进制替换全部 fail-closed

4.2 协议版本协商

握手协商 rpcMajor/rpcMinor：major 不同拒绝启动，minor 采用双方较低能力集。未知字段在同一 minor 中忽略，未知枚举必须返回 BRIDGE_SCHEMA_INVALID。

4.3 双进程理由

选择双进程而非单进程的理由：
  • UI 崩溃和引擎任务隔离，互不影响
  • 便于引擎独立恢复与重启
  • 避免所有本机能力暴露给 WebView2 宿主
若后续采用单进程，必须通过 ADR 证明崩溃隔离、安全和长任务恢复不退化。
CHAPTER 05

信任边界

规则 6 条

所有输入数据默认不可信，系统在任何边界都不得放松校验。

#信任边界规则含义
1Renderer 永远不可信XSS 不得升级为本机代码执行；UI 输出必须经过 Host 校验
2模型输出 / 网页 / 上传文件 / MCP 返回均不可信所有外部数据进入系统前必须经过校验、净化和隔离解析
3Skill 包在安装、运行两阶段均不可信安装需签名校验，运行需沙箱隔离，POC 前禁止第三方脚本执行
4Host 是系统能力代理，但只暴露白名单禁止通用 invoke(command,args)、任意文件路径和任意 URL 方法
5Engine 是策略和数据权威所有业务规则、授权、事务由 Engine 决定，Host/Renderer 不得绕过
6外部供应商不可信且可能记录输入使用云模型时提示词和上下文会外发，MUST 在发送前展示数据边界
7连接器与目标环境是独立安全边界动态 schema、接口返回和 DB 元数据均不可信；按 connector/environment 绑定最小权限 SecretRef，日志必须脱敏
8发布包跨环境不可变代码与迁移同包同 digest；生产导入须验证签名、摘要、PromotionGateSnapshot 和短租约
本地优先 ≠ 数据完全不出本机。使用云模型时，提示词、选定上下文和附件会发送给所选供应商。系统 MUST 在发送前展示数据边界，不能承诺"数据完全不出本机"。
CHAPTER 06

生命周期与恢复

Engine 状态机

Engine 状态机定义了从启动到停止的完整生命周期，含崩溃恢复与熔断机制。

6.1 Engine 状态机

starting → migrating → ready → degraded → restarting → circuit_open → stopping → stopped

6.2 启动与重启规则

规则阈值说明
启动超时15 秒超时未 ready 进入 degraded
自动重启上限60 秒内最多 3 次超过进入 circuit_open，需人工介入
启动检查必检项migration journal、SQLite integrity、孤儿 Worker

6.3 退出与崩溃恢复

退出顺序：先停止接收任务 → checkpoint → 取消网络请求 → 再终止 Worker。
  • 崩溃中的消息标记 interrupted；已提交消息不得丢失
  • 外部副作用节点恢复时必须读取幂等记录，禁止盲目重放
  • 只有满足幂等/补偿规则的 interrupted 节点可恢复

6.4 WebView2 Runtime

ADR-003 已裁决：v1 使用 Evergreen Runtime；安装器 MUST 检测最低版本并给出可恢复安装引导。若未来评估随包分发 Fixed Runtime，必须新建独立 ADR，不属于 ADR-003。

7.1 Go-native Agent Kernel

Agent Kernel 是 Go Engine 内部应用内核，不是新进程、不是第六智能内核、不是新增 UI 功能，也不引入 Node/Python/Rust sidecar。它把 Session/Context、Planner、ModelGateway、ToolRuntime、Policy/Review 和 durable recovery 编排为可测试的执行循环。

User Message → AgentRun / Turn
  → ResolvedConfigSnapshot
  → ContextBuilder → ModelGateway
  → ProposedToolCall → PolicyDecision
  → allow | deny | Review
  → Checkpoint → ToolRuntime / Worker
  → Observation / Evidence
  → next turn | completed | failed | cancelled | outcome_unknown
基础组件职责不得承担
AgentRuntimeRun/Turn/Step 生命周期、预算、取消、first-terminal-wins、恢复不得绕过领域服务直接写库或执行副作用
ConfigResolverRegistry、scope、Policy 合并并冻结 ResolvedConfigSnapshot不得让 session/run override 放宽强制策略
AgentProfileRegistryAsk/Architect/Plan/Code/Debug/Review 的 Prompt、候选工具和上下文偏好Profile 不授予权限
ToolRuntime结构化调用、授权、checkpoint、Worker、Observation不得执行模型生成的任意 shell 字符串
RecoveryCoordinatorcheckpoint、EffectJournal、outbox、receipt、对账与恢复无法证明副作用结果时不得自动重试

三轴正交模型

  • Agent Profile只改变角色、Prompt、候选工具和上下文偏好；
  • Automation Level为 Manual / Assisted / Full-Managed，只影响低中风险动作；
  • Business Stage为既有九阶段，决定输入、产物和门禁；
  • Policy Engine始终对规范化的具体动作最终裁决，高风险强制 Review 不因任何轴变化而降级。

7.2 三类事件与恢复事实

类型用途可靠性
Domain EventRun、Session、Plan、Tool、Setting、Artifact 等权威业务变化与聚合状态同事务写 outbox；至少一次投递，按 eventId 去重
Wire EventRenderer 流式展示和状态投影seq/ACK/背压；关键事件可重放，纯 token delta 可合并
Audit EventPolicy、Review、Secret、工具和外部副作用追责append-only + hash chain + 外置签名 checkpoint
副作用恢复：执行前写 EffectJournal{operationDigest,state=prepared}，执行后保存外部 receipt 并转 succeeded；崩溃恢复先向外部系统对账。只有具备稳定幂等键或确定补偿的操作可自动恢复；其他操作进入 outcome_unknown 并阻断后续依赖节点。

8.1 请求 Envelope

应用 Origin 冻结：主 UI 通过 WebView2 virtual host https://app.lunitide.local 加载打包资源，仅顶层主 frame 可调用 Bridge。Host 将消息绑定 CoreWebView2 实例、精确 source URI、navigation/document nonce 与 top-level frame identity；导航即吊销旧 document capability。预览使用独立 UserDataFolder/CoreWebView2Environment，不注册 WebMessage/host object，默认拒绝下载、设备权限和外部导航。副作用 schema 必须 additionalProperties:false，限制深度、字段/数组/字符串长度并拒绝重复 JSON key。

8.3 流式事件格式

事件类型：start / delta / tool_call / usage / checkpoint / done / error。

{
  "v": "1.0",
  "kind": "event",
  "streamId": "run_123",
  "seq": 42,
  "type": "delta",
  "payload": {"text": "..."},
  "occurredAt": "..."
}
流式规则：seq 从 1 单调递增；消费者按 (streamId,seq) 去重；Renderer ACK 最近 seq；超过缓冲上限暂停读取上游或合并纯文本 delta；cancel 使用 stream.cancel 传递至 Go context 和上游 HTTP；done/error 后不得再有事件；断连后可重放已持久化关键事件，纯 token delta 不承诺全量重放。

失败恢复超时、重复 ACK、Host/helper 中途崩溃和重放必须安全重跑。失败删除新 credential、旧数据不变；safeStorage 不可用或密文损坏时仍迁移非敏感配置并标记 credentialState=requires_reentry。成功后做最小真实连接测试，全部完成后由用户选择保留只读加密备份或删除旧数据。

迁移 Golden corpus：CI MUST 覆盖 schema v1/v2、损坏 JSON、重复 Provider、缺失默认模型、缺失/损坏 Key、safeStorage 不可用、确定性 UUID→ULID、重复迁移、部分成功、Host 中途崩溃、helper 重放/伪造/抢连、重复 ACK 和 OData 错误标记。除受控 helper 单条转移窗口外，配置、DB、日志、诊断、dump 和稳定内存 canary 扫描不得出现明文 Key。

type SecretService interface {
    Put(ctx context.Context, scope SecretScope, plaintext []byte) (CredentialRef, error)
    WithSecret(ctx context.Context, ref CredentialRef, fn func([]byte) error) error
    Delete(ctx context.Context, ref CredentialRef) error
}
Secret Lease 机制：Engine 使用 secretLease.acquire RPC 请求包含 providerId、credentialRef、credentialVersion、normalized origin、operation、deadline 和 requestNonce。Host 复用 4.1 的 HMAC 认证会话并校验 Engine 映像身份、Provider-origin 绑定后，返回 TTL≤5秒、单次消费、最大64KiB 的完整性保护 lease frame。lease 绑定 Engine session/requestNonce/origin/credentialVersion，重放或换绑一律拒绝。Engine 只在 connector 调用栈持有 []byte，禁止转换为 Go string，设置 Authorization 后立即覆盖。

12.5 URL 与 SSRF 防护

  • 默认 HTTPS；HTTP 仅显式允许 loopback 本地模型
  • 解析 DNS 后阻止 loopback、link-local、metadata、保留地址和未授权私网
  • 每次重定向重新验证；默认禁止自动重定向
  • 限制端口、代理、响应大小、解压大小和 TLS 最低版本
  • 防 DNS rebinding：连接地址必须属于验证后的集合
  • 所有 Provider、Connector、Skill 下载、更新、ETL、OData 和数据库网络均经单一 EgressBroker；adapter/Worker 不得自行建 socket
  • 规范化 IDNA/scheme/host/port，覆盖 IPv6、IPv4-mapped IPv6、多 A/AAAA、代理 CONNECT 与跨 origin credential；系统/环境代理默认禁用，代理与最终目标都复验
  • 日志只记录脱敏 origin，不记录 query credential

12.6 诊断 TestResult

TestResult 字段：status、stage(dns/connect/tls/auth/request/stream)、httpStatus、latencyMs、testedAt、errorCode、sanitizedMessage、correlationId。
