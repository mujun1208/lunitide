唯一生产基线：Go Engine + Windows WebView2 Host + React/TypeScript + SQLite。Electron/Python 只作为原型功能与迁移经验输入，不进入正式安装包。

2. Bridge 与进程边界

  • 只允许打包应用 origin 和主 frame；每条消息执行 schema、大小、方法白名单、deadline、correlation ID 校验。
  • Host↔Engine 使用当前用户 ACL 的本地 IPC；握手包含协议版本、实例 nonce，防止旧客户端误连。
  • 错误对外归一化，内部详情脱敏写入审计；Renderer 不接收堆栈、密钥或任意本地路径。
  • 仅 Provider API Key 允许在供应商编辑页由 Host-owned 原生安全控件从 OS Credential Store 短时读取并显示，且提供立即隐藏；不得进入 Renderer DOM、公共 DTO/Bridge、Engine、SQLite、日志、审计正文、遥测、崩溃转储或剪贴板历史。失焦、切页、锁屏或租约超时必须清零控件与进程内临时缓冲。其他 MCP secret 与组织 secret 只显示引用、别名或“已配置”状态，任何界面均不得回显明文。
  • Engine 崩溃后由 Host 有界重启；超过熔断阈值进入安全诊断模式，不循环重放副作用。

2.1 Bridge 独立 Schema 与 AppError 合同

每个公开方法必须分别发布版本化的 request、success、error JSON Schema，三者均拒绝额外字段；不得以宽松 union 或仅靠 TypeScript 类型代替运行时验证。

Request={schemaVersion,method,requestId,correlationId,deadlineMs,payload}
Success={schemaVersion,requestId,correlationId,ok:true,result,serverTime}
Error={schemaVersion,requestId,correlationId,ok:false,error:AppError}
AppError={code,category,message,retryable,correlationId,details?,fieldErrors?}

AppError 是 UI 可见的唯一错误 envelope；details 仅允许白名单、脱敏、可操作字段，禁止 stack、SQL、内部路径、Provider 原文和 secret。额外字段、重复 JSON key、error 冒充 success、版本不兼容均 fail closed；deadline 后迟到 success 不得反转终态。

2.2 ConsentSnapshot 外发绑定

任何模型或外部连接器调用前，Engine 必须生成不可变、版本化的 ConsentSnapshot，至少绑定 provider ID、model ID、system prompt digest、拟发送的记忆范围、附件范围、工具声明/权限范围、用户确认事件与 actor、expiresAt、schema/policy version，以及规范化完整内容的 snapshot digest。确认令牌绑定 digest、用户、scope、目标与 expiry；任一绑定项变化即失效并重新预览/确认。Gateway 只接受未过期且复算一致的快照；审计只记 snapshot ID/digest、目标、时间、结果与裁剪摘要，不记正文或 secret。

2.3 日志保留与审计分轨

普通运行日志保留 14 天或累计 200 MB，任一阈值先到即清理，默认脱敏。安全审计使用独立存储、ACL、保留/导出策略与完整性链，不计入普通日志 200 MB，也不得因普通日志清理而删除或降级。

数据与隐私

  • 所有实体带 owner/scope、来源、创建与修改时间；项目、个人、组织 scope 不隐式提升。普通聊天唯一持久模型为 personal/unscoped 且 project_id=NULL；旧隐藏 personal project 仅作为 legacy 导入适配输入，迁移完成后不参与运行时查询。
  • SQLite 启用 foreign_keys=ON、WAL、busy timeout；迁移前备份，迁移 journal 可恢复。
  • 内容资产不可变、SHA-256 寻址；删除通过引用图传播，并处理索引、缓存、备份保留策略。
  • 默认本地处理；M6 云能力显式 opt-in，上传前预览范围，关闭后核心功能仍可用。

本地优先存储原则（Legacy 基线，7 条）

旧版架构文档（V1 CH.09）把本地优先存储冻结为 7 条原则；新版继续继承该基线：

#原则约束
1SQLite WAL + Engine 单写者WAL + foreign_keys=ON + busy_timeout；只有 Engine DB writer 写入，按优先级队列/批处理保持短事务，并定义背压、WAL checkpoint、磁盘满与停机 drain
2ULID + UTC所有业务实体使用 ULID；时间统一 UTC RFC3339，UI 本地化展示
3版本与不变性可变 aggregate root 必须有 created_at/updated_at/version；append-only 实体使用唯一 sequence；immutable revision 禁止 UPDATE；可删除实体使用 tombstone/soft delete
4内容寻址资产资产内容使用内容寻址文件存储，DB 保存 SHA-256、大小、MIME、相对引用；写入走临时文件 + 原子替换
5密钥隔离密钥明文和密文均不得进入普通业务 DB；只保存 credential_ref
6向量 scope向量记录必须带 workspace/project scope、source revision 和 tombstone
7审计 append-only审计事件 append-only，并支持哈希链完整性校验
密钥隔离铁律：密钥明文和密文均不得进入普通业务 DB，只保存 credential_ref。Host 端 DPAPI/Credential Manager 保存后立即清空前端字段；不得存入 Zustand、localStorage 或日志。

数据目录布局（V1 事实口径）：旧版未冻结独立的磁盘目录清单，可继承的落点事实为——业务数据在 SQLite（WAL）；密钥在 OS Credential Store / DPAPI（CurrentUser），不落业务 DB；资产在内容寻址存储（SHA-256、临时文件 + 原子替换）；原型数据源 %APPDATA%/lunitide/providers.json 仅作只读迁移输入。完整目录布局由 M0 存储与迁移实现冻结，届时以追踪表登记为准。

5. Agent 与执行模型

→ Tool Prepare → Execute → Commit Journal → Evidence → Result
                          ↘ crash → Reconcile → resume / blocked

M4/M5 只有单 Root Run，可顺序切换专家 Profile，但不得伪造并行 Child。M6 才引入 Delegation Envelope、Child Run 与 Join Barrier；Child 对主工作区只读，唯一 WorkspaceMutationCoordinator 串行合并 Patch Proposal，并在最终树重跑测试。

7. 原型迁移约束

可吸收：模型供应商契约、BYOK 流程、错误分类、UI 交互意图、测试样例、备份与诊断经验。
不可继承：Electron 安全假设、Python/FastAPI/Uvicorn 运行时、IPC 协议、打包结论、把原型数据库视为生产 schema。

迁移采用行为契约测试：先记录输入、输出、错误和边界，再在 Go 端实现；禁止把 Python 进程作为“临时正式 sidecar”长期保留。

全局治理完整合同：Policy、Review、Consent、分类、审计与诊断

适用范围：本合同从相关能力首次出现即适用，不等待 M9。M9 只叠加组织级主体、层级策略与多人审批。

Policy 输入与输出

每次受控操作规范化为 OperationSnapshot：actor/subject、session/run/project/scope、operation、canonical params、resource identity/version/base digest、data classification、destination/origin、tool/executor version、plan/policy/config version、budget、risk、requested effect 与 expiry。Policy 只返回 allow|deny|require_review、reason codes、constraints、policy version 和 decision id；Prompt、Profile、Skill 或模型文本不能授予权限。

Review、TOCTOU 与 ConsentSnapshot

对象规则
Reviewpending→approved/rejected/changes_requested/expired/cancelled；执行事实另记 executing→executed/execution_failed/outcome_unknown。批准与执行分离。
绑定批准绑定 OperationSnapshot canonical digest、资源版本/base digest、策略/配置版本、风险、有效期和操作者认证强度；任何安全相关字段变化旧批准立即失效。
ConsentSnapshot记录 actor、scope、destination/origin、data classes、purpose、allowed operations、constraints、created/expires/revoked、policy version 与 snapshot digest。低风险重复操作仅在 scope/digest/策略完全相同且未过期时可复用；高风险外部副作用每次即时确认。
运行模式manual/assisted/automated 只影响低风险交互频率，不得绕过 Policy；deny 永不转 allow，require_review 无有效票据不得执行。

数据分类与不可信输入

统一分类为 Secret、Restricted、Internal、Public（产品可显示中文别名）。分类随 Message、Artifact、Memory、Handoff、ToolResult、日志摘要和出口请求传播；组合数据取更严格分类。不可信网页、文件、MCP/Skill 输出必须携带 trust/provenance 标签，不得通过提示注入改变授权、自动晋升长期记忆或扩大出口。

审计、日志与诊断

  • AuditEvent append-only，至少含 event_id、UTC time、actor、action、entity/scope、before/after digest、decision/review/consent id、correlation_id、result；使用 canonical encoding 和 hash chain。
  • 系统使用 DPAPI/TPM 保护的签名密钥周期签发 checkpoint，至少含 workspace/scope_id、chain_id、epoch、last_sequence、head_hash、timestamp，并保存到业务 DB 与普通业务备份之外的受保护位置。恢复时必须与最高已知可信 checkpoint 比对；备份落后、epoch 回退、链尾截断、签名或 head_hash 不匹配返回 AUDIT_ROLLBACK_DETECTED 并进入 recovery_required。在完成独立对账与授权恢复前，必须阻断发布、高风险工具、Secret/Restricted 外发和审计导出签章，而不只是隐藏“审计完整”声明。
  • 日志只记录必要元数据、错误码、大小、时延和脱敏摘要；禁止 Secret、令牌、聊天正文、文件正文、完整请求/响应、模型思维过程。
  • 诊断包生成前展示 manifest 和敏感项，执行脱敏扫描；导出属于受控操作并写 Review/Audit。支持人员默认无内容读取权。

统一错误与恢复

AppError 至少包含 code、message_key、安全的 user_message、retryable、correlation_id、details schema 和 remediation；不得把内部栈或敏感参数直接返回 UI。副作用结果未知使用 OUTCOME_UNKNOWN/EFFECT_OUTCOME_UNKNOWN，先对账再决定 continue/compensate/new idempotency key；不得把超时等同失败后盲重试。

安全验收

  • Review 参数/资源/策略摘要篡改、过期票据、TOCTOU、Consent 越 scope 复用全部拒绝。
  • Secret/Restricted 出口无有效 Consent 的执行数为 0；自动模式高风险绕过数为 0。
  • 旧备份恢复、截断 DB、替换 checkpoint、epoch 回退和签名篡改故障注入均返回 AUDIT_ROLLBACK_DETECTED 并阻断高风险执行；日志和诊断包 Secret canary 命中 0。
  • 提示注入不能改变 Policy 决策、工具 grant、长期记忆确认或数据出口。

信任边界基线清单（Legacy 迁移）

旧版架构把"所有输入数据默认不可信，系统在任何边界都不得放松校验"冻结为 8 条边界规则（V1 CH.05），作为安全治理、审计与权限检查的基线清单继承：

#信任边界规则含义
1Renderer 永远不可信XSS 不得升级为本机代码执行；UI 输出必须经过 Host 校验
2模型输出 / 网页 / 上传文件 / MCP 返回均不可信所有外部数据进入系统前必须经过校验、净化和隔离解析
3Skill 包在安装、运行两阶段均不可信安装需签名校验，运行需沙箱隔离，POC 前禁止第三方脚本执行
4Host 是系统能力代理，但只暴露白名单禁止通用 invoke(command,args)、任意文件路径和任意 URL 方法
5Engine 是策略和数据权威所有业务规则、授权、事务由 Engine 决定，Host/Renderer 不得绕过
6外部供应商不可信且可能记录输入使用云模型时提示词和上下文会外发，必须在发送前展示数据边界
7连接器与目标环境是独立安全边界动态 schema、接口返回和 DB 元数据均不可信；按 connector/environment 绑定最小权限 SecretRef，日志必须脱敏
8发布包跨环境不可变代码与迁移同包同 digest；生产导入须验证签名、摘要、PromotionGateSnapshot 和短租约
本地优先 ≠ 数据完全不出本机。使用云模型时，提示词、选定上下文和附件会发送给所选供应商。系统必须在发送前展示数据边界（ConsentSnapshot），不能承诺"数据完全不出本机"。

8. Artifact-first Harness 全局基线

8. 唯一 AppError 与 RootWriter 跨阶段不变量

AppError v1 唯一公共 schema：{code,category,messageKey,userMessage,retryable,correlationId,remediation?,details?,fieldErrors?}。阶段编号只能作为需求/测试别名或 details.milestoneAlias，不得成为新 wire code；公共 code 使用大写 SNAKE_CASE。本文早期示例中的 message 视为 userMessage legacy alias，correlation_id 视为 correlationId legacy alias；新 SDK 禁止输出 alias。
RootWriter：对任何 Project Final Tree，RootWriter 是唯一可持有写令牌的组件。Child、UI、Bridge、插件、StageService 和 ReleaseService只能提交 PatchProposal/MergeIntent；最终树写入必须持久化 rootId、writerEpoch、fencingToken、expectedHead、resultHead、intentDigest、receipt。M7 CodeChange/Artifact 晋级必须引用该 receipt，legacy 无证明变更标记 legacy_unverified 且不得进入生产 Gate。
架构变更需要 ADR · 安全控制不得由阶段排期豁免
