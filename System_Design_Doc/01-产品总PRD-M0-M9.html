01 · Product Requirements · M0–M9.5

产品总 PRD

月汐是 Windows 本地优先的个人与项目智能工作台：先建立可靠单 Agent 和可审计本地执行，再扩展生态、多 Agent、正式发行、个人长期智能与组织平台。

事实口径：M0–M3 按各自证据区分主体代码与验证状态；M4 拆分记录“主体代码 / 内部验证 / 范围冻结（Scope Seal）/ 正式外验”。2026-08-14 用户裁决：M0–M4 主体开发视为已完成，M5 即刻开工；Scope Seal 转为 M5 期间并行补齐并保留为 M5 发布门禁，正式外验仍为独立未关闭项。不得把主体代码存在表述为全部外验通过。
目标与非目标产品边界阶段路线M0–M9.5 依赖里程碑门禁DoR/DoD 与启动清单不变量与状态跨阶段约束

1. 目标、非目标与用户

目标

  • 同一统一对话 Agent 完成理解、计划、审批、执行和恢复。
  • 项目以九阶段和版本化产物形成可发行证据链。
  • 本地优先、最小权限、可审计、可撤销。
  • 从个人效率演进到组织治理而不破坏边界。

非目标

  • 不是无审批的自主通用计算机控制。
  • 不是 Electron/Python 正式运行时。
  • M5 不开放任意第三方脚本或伪多 Agent。
  • 普通聊天不是项目流程的隐式入口。

核心用户

  • 个人知识工作者与开发者。
  • 需要正式交付的项目负责人。
  • M9 的团队管理员、审计者与平台运营者。

1.1 六大核心价值

以下六项核心价值完整继承自 v1 PRD 1.2，作为 V2.0 全路线（M0–M9.5）的价值基线；每项附 V2.0 主要落点。

连续理解

跨会话记住已确认事实、决策和偏好，不因重启或断线丢失上下文。

落点：M3 上下文基线；M8 个人长期智能。

语义一致

所有专家共享项目本体和版本化产物，避免口径分裂。

落点：M7 版本化产物与评审；M8 Ontology。

计划执行

复杂任务转为可恢复 DAG，不靠单轮提示词硬跑。

落点：M4 durable Run 与计划。

可控自动化

低风险自动，高风险强制确认并留痕，运行模式仅影响中低风险程度。

落点：M4 工具审批；M5 统一执行。

资产复用

模板、底座、技能和接口配置可版本化复用，引用锁定不可静默变更。

落点：M6 生态与 Skill；M7 资产模板。

本地控制

用户掌握密钥、项目存储、外发范围和删除权。

落点：M0–M2 本地优先基线；M8 遗忘与导出。

1.2 首期产品边界：MUST 承诺与不承诺

继承自 v1 PRD 1.3 的首期边界清单。在 V2.0 中“首期”承诺按 M0–M9.5 分阶段验收，M8/M9/M9.5 不属于首期承诺范围；本清单作为产品边界的历史基线保留。

首期 MUST 承诺

  • 单用户 Windows 本地工作台
  • 多供应商、多模型 BYOK
  • 项目、会话、九阶段、产物与版本基础模型
  • 受限 Planning / Governance
  • 模板和底座最小闭环
  • 诊断、审计、备份和签名升级

首期不承诺

  • 真正多人实时协作
  • 无边界全自动生产部署
  • 所有编程语言的完整 AST 本体
  • 任意第三方技能无审核安装
  • 云模型离线可用
  • 任意数据库迁移可自动逆向回退
适配说明：多供应商 BYOK 在 V2 归属 M1；九阶段与版本化产物归属 M7；模板/底座最小闭环归属 M6/M7；多人协作与组织能力显式后移至 M9 组织平台，且在 ADR-011 接受前仅允许设计、不得开展 schema/API 开发。

1.4 三轴模型：智能内核 × 业务主链 × 平台能力

月汐由三条正交轴构成，它们协同支撑九阶段业务主链产出版本化产物（完整继承自 v1 PRD 2.2）。

轴一 · 五大智能内核

Ontology（语义骨架）、Memory（时间连续性）、Skills（能力库）、Planning（认知循环）、Governance（控制层）。五大内核不是五个阶段。

轴二 · 九阶段业务主链

M7 固定九阶段：立项与边界 → 调研与证据 → 需求定义 → 方案与体验 → 架构与计划 → 开发与变更 → 验证与验收 → 发布与交付 → 运营与复盘（旧 S1–S9 阶段名仅作历史输入）。流程非机械全局串行，依赖产物批准且版本锁定时可并行。

轴三 · 横向平台能力

模型网关、模板、底座、接口、开发任务、测试、CR/部署、审计、诊断。

五大内核 → 九阶段主链 → 版本化产物 → Ontology / Memory
横向平台能力 ↘ 九阶段主链 ↙ 用户目标
关键区分：旧版 S5–S9 不是简单等同九阶段编号，而是横向或后半程平台模块专题；九阶段是项目业务流程。V2.0 已按 旧版映射 将 S5–S9 语义归并到 M5–M9 与对应五件套。

2.1 九阶段业务主链与阶段状态（M7 概览）

九阶段业务主链由 M7 权威定义（继承自 v1 PRD 4.1/4.3，旧 S1–S9 阶段名已映射为 M7 固定 key）：

立项与边界 → 调研与证据 → 需求定义 → 方案与体验 → 架构与计划
→ 开发与变更 → 验证与验收 → 发布与交付 → 运营与复盘
并行与依赖：每个阶段输入固定为 StageInputSnapshot；当依赖产物批准且版本锁定时节点可并行。上游已批准产物发生修订时，影响分析 MUST 将下游相关项标记为 stale，禁止静默替换输入。

阶段状态说明

canonical 状态机（M7 权威）：draft → ready → running → waiting_review → approved → completed，支路 blocked / paused / stale / cancelled；驳回回到 running 并创建新 review round。v1 的 not_started / in_progress / rejected 仅作迁移别名。

  • approved：产物经复核可供下游固定引用。
  • completed：阶段所有必需产物和退出条件完成。
  • 上游版本变化可令下游从 approved/completed 转为 stale，但不得删除旧快照。
  • blocked 恢复后回到原执行状态。
  • cancelled 不可直接恢复，需创建新 StageRun。

逐阶段输入/必需产物/准出/异常详表见 M7 阶段 PRD；本页仅保留概览，不重复维护详表。

2.2 里程碑门禁：Definition of Ready / Definition of Done

继承自 v1 PRD 的工程门禁，V2.0 适配为 M0–M9.5 口径：任何需求项进入实现前、任何模块宣布完成时，逐条核对以下清单；文档级与工程级状态语言定义见 00 治理。

Definition of Ready · 进入实现前全部满足

  • 需求有唯一 ID、价值、范围、优先级、验收方法和来源；明确 in/out of scope。
  • 影响的实体、接口、状态机、事件、失败场景、数据分类与外发边界已定义；依赖 schema/ADR 已批准。
  • 上游 Artifact/StageInputSnapshot 已批准并锁版；测试数据、迁移、恢复与安全用例已准备。
  • 功能已分配唯一 M0–M9.5 里程碑；Open ADR 或未通过 POC 的能力不得进入当前实现。

Definition of Done · 完成时全部满足

  • 代码、测试、文档、schema 和迁移同时提交；生成 Go/TypeScript SDK，无手写重复 DTO。
  • 状态机、错误码、审计事件、幂等/并发、可观测性、诊断、回退/恢复均实现并测试。
  • 格式、lint、unit、contract、race、SAST/SCA、secret scan、E2E、故障注入和追踪矩阵通过。
  • 任何偏离 SHOULD 的项有 ADR；无 TODO/TBD；所有 UI 操作可追溯到 capability、RPC、Engine handler、Policy 和验收。

4. 跨阶段不变量

  1. 架构：生产栈固定 Go Engine + Windows WebView2 Host + React/TS + SQLite；Renderer 不可信。
  2. 产品：普通聊天与项目分离；普通聊天唯一模型为 personal/unscoped、project_id=NULL，隐藏 personal project 仅为 legacy 迁移输入；跨域迁移必须显式。
  3. 权威：Engine 是状态、策略、审批和副作用的唯一权威；UI 只表达请求与投影。
  4. 安全：默认拒绝、最小权限、能力按 Run/Workspace/期限绑定；Job Object 不宣称安全沙箱。
  5. 数据：来源、版本、scope、保留期、删除传播可追溯；密钥只在 OS 安全存储。
  6. 执行：先计划/校验，后审批/执行；副作用必须具备幂等键、审计与恢复语义。
  7. AI：不展示私有思维链；展示结论、假设、证据、采用方法和分歧。
  8. 供应链：许可证/来源/版本/摘要未核验的依赖不可引入。

5. 状态边界

Agent Run

draft → planned → awaiting_approval → running ↔ paused
                                   ↘ recovering → running
running → succeeded | failed | cancelled | blocked
终态不可返回 running；恢复创建新 attempt，不改写历史。

项目产物

draft → in_review → approved → released → superseded
           ↘ changes_requested → draft
released 内容不可原地修改；修订必须创建新版本。

审批与工具调用

  • 审批：pending → approved | denied | expired | cancelled；approval 绑定参数摘要、scope 和有效期，参数变化即失效。
  • 工具调用：proposed → authorized → executing → committed | failed | cancelled | unknown；unknown 必须先对账，不可盲目重试。
  • 阶段状态只由满足门禁的事务推进；聊天文本、模型自述和 UI 本地状态均不能推进权威状态。

6. 验收与发布原则

停止线：隔离、许可证、数据删除、跨租户、签名或恢复证据缺失时，相关能力不得通过功能开关“先上线再补证据”。降级应是关闭能力，而非降低安全保证。
