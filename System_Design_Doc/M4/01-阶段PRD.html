MILESTONE 04 / FROZEN SCOPE

Reliable Single-Agent Runtime

唯一 Root、durable Run / Turn / Step / ToolCall、显式工具 manifest、Workspace 与 Review 治理、EffectJournal/receipt 恢复及多维预算。

目标、非目标、依赖与退出

合同冻结内容
目标每个运行仅一个 Root，M4 的 parentRunId/delegationId 恒为空；Run/Turn/Step/ToolCall 跨崩溃持久；16 工具由签名 manifest 声明；高风险 effect 经过 Review；Workspace 规范化授权；副作用以 journal/receipt 对账；预算可暂停/终止且不可绕过。
非目标Child/fan-out/fan-in、MCP、第三方 Skill、通用 Browser 均不属于 M4。不实现任意 shell，不把内置 WebFetch/Search 扩张为网页自动化，不把 Review 等同“弹窗确认”。
依赖M3 durable Session/Message 与附件；Host typed Bridge、Engine 单写者、Worker/Job Object、DPAPI、outbox/audit、SQLite migration framework。
退出唯一 Root 约束、16-tool manifest、durable 状态机、Review changed-after-approval、Workspace 越界防护、effect crash-point 对账、预算矩阵、取消/恢复、安全测试通过；同一 RC digest 的外部证据完成绑定。
边界裁决：plan.run.spawn、child run、delegation、fan-out 等现存入口是超前/历史实现；这些接口当前仍启用；它们不属于 M4 的 16 工具，也不能作为 M4 验收证据，范围隔离切片完成前 M4 不得冻结退出。

GWT

GivenWhenThen

功能需求

  1. FR-M4-01 AgentRun 是唯一 Root；Run→Turn→Step→ToolCall 顺序、状态和终态 CAS 持久化。
  2. FR-M4-02 ToolCall 参数为结构化 schema，descriptor/version/digest 全量记录；模型不能直接执行字符串。
  3. FR-M4-03 工具集合恰为 16 项，按 FS / ChangeSet / Command / Web / Plan / Evidence 六类冻结。
  4. FR-M4-04 CapabilityManifest 签名、版本化、启动校验；未声明、版本漂移或 schema 不符均拒绝。
  5. FR-M4-05 Workspace 由 Host picker + Engine canonical identity 登记；所有路径相对授权 root 且防 symlink/junction 越界。
  6. FR-M4-06 ChangeSet 预览、应用、撤销绑定 base digest 与 checkpoint，不做 last-write-wins。
  7. FR-M4-07 Command 使用签名 CommandSpec，默认无 shell，Worker 受 Job Object、时限、输出和 egress 限制。
  8. FR-M4-08 Web 仅 fetch/search，逐跳 SSRF 检查并保存 URL/time/digest/provenance；无通用 Browser。
  9. FR-M4-09 Review 记录裁决、过期、批准范围；参数/资源/策略变化后旧批准失效。
  10. FR-M4-10 effect 前 prepared、后 receipt+succeeded；恢复按 stable idempotency key/补偿/对账决定。
  11. FR-M4-11 BudgetEnvelope 限 model turns、tool calls、tokens、cost、wall-clock、output bytes、retries、no-progress 和 hard ceiling。
  12. FR-M4-12 Evidence 可列举测试、命令、变更、Web 来源与 Review，全部绑定 Run/ToolCall digest。

冻结合同详述：Reliable Single-Agent Runtime

范围冻结：本节只把已冻结 M4 的权威产品合同写完整，不增加 Child、fan-out、第三方扩展、项目九阶段或云执行。

角色与运行旅程

角色需求
任务发起者启动、暂停、取消、恢复或对账一个 durable Root Run，并理解当前步骤、预算与阻断原因。
审批者查看规范化操作、对象、影响、风险、参数摘要、资源版本和过期时间后决定。
支持人员崩溃后依据 checkpoint、EffectJournal 和 receipt 判断继续、补偿或 outcome_unknown。

实体、状态与转换

对象状态/规则
Runqueued→running；可暂停到 paused_review/paused_budget；终态 completed/failed/cancelled/interrupted；外部结果无法证明时 outcome_unknown。M4 每次仅一个 Root，禁止 Child。
Turn/Step按 sequence 追加，固定输入摘要、策略/配置版本、预算和证据；已完成记录不可原位修改。
ToolCallproposed→policy_check→waiting_review?→prepared→executing→succeeded/failed/cancelled/outcome_unknown；依赖 unknown 时不得继续。
Reviewpending→approved/rejected/changes_requested/expired/cancelled；执行另记 executing→executed/execution_failed。批准不是执行结果。

不可变规则

  • Profile/Prompt/Skill 只影响候选行为，不授予权限；每个 ToolCall 由 Policy 按规范化参数重新裁决。
  • 所有写命令携带 expectedVersion、idempotencyKey、correlationId；同 key 不同 canonical request digest 返回冲突，CAS 禁止 last-write-wins。
  • 命令只接受签名 CommandSpec(exe,args,cwd,envRefs,timeout)，不得执行模型生成的任意 shell 字符串。
  • 工作区使用 workspaceId+relativePath，打开句柄后校验 canonical identity、祖先根和 reparse/symlink/junction；拒绝设备路径与未授权 UNC。
  • 副作用前写 EffectJournal prepared，完成后写 receipt；超时或崩溃无法证明结果时进入 outcome_unknown，自动重试为 0。
  • 聚合、审计、幂等记录与 outbox 同事务；事件至少一次，消费者按 eventId 去重。

预算与验收

预算至少覆盖 model turns、tool calls、input/output tokens、cost、wall-clock、output bytes、retries、no-progress 与 hard ceiling。验收覆盖路径逃逸、review digest 篡改、SSRF、CAS、命令模板拒绝、崩溃 reconcile、同 runId 恢复、取消≤2s 和 outcome_unknown 阻断。关键错误包括 RUN_VERSION_CONFLICT、RUN_NOT_RESUMABLE、REVIEW_DIGEST_MISMATCH、PATH_ESCAPE_DENIED、CHANGESET_BASE_CONFLICT、COMMAND_TEMPLATE_DENIED、WEB_SSRF_DENIED、BUDGET_EXCEEDED、EFFECT_OUTCOME_UNKNOWN。
