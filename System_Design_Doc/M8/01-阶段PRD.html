受治理长期记忆与个人自动化 PRD

让记忆可确认、可追溯、可解释、可撤回、可同步；插件系统（FR-18）让一切能力扩展统一封装、连接即用；专家管理（FR-19）让外部获取与本地创建的岗位说明书式专家按项目九阶段灵活协作。硬约束：不得自动把不可信推断晋升为长期事实。

目标、角色与边界

目标

建设 MemoryCandidate、长期事实、KnowledgeBase、Recall、Handoff、WorkflowBundle、个人自动化、多设备同步，统一插件包 PluginBundle（万物皆插件），以及专家中心（Expert Center，外部 AgentPack 获取 + 六段式本地创建 + 项目九阶段挂载协作）。

用户

个人用户审阅事实；知识维护者管理来源；自动化作者控制权限；隐私支持人员验证删除。

非目标

不在 M8 建组织市场、组织审批或许可判断；不把模型置信度当成用户确认；不实现编排型多 Agent 写协作的执行本体——M8 只交付其评估门禁（FR-17），写协作运行时默认 disabled。

FR-04Recall 解释展示命中原因、范围、来源、新鲜度、裁剪及未采用原因。给定结果被策略裁剪；当展开解释；则说明规则且不泄露内容。

FR-06Handoff只携带任务所需上下文、来源和有效期，接收后生效。给定清单含越权字段；当发送；则裁剪并展示差异。
FR-07墓碑递归删除递归覆盖索引、缓存、摘要、交接、派生物和设备副本。给定根事实删除；当传播完成；则所有派生节点不可召回。

FR-09个人自动化默认草稿；启用前展示权限、数据出口、预算和失败策略。给定高风险动作；当到执行点；则无即时确认不执行。
FR-10多设备同步冲突版本向量检测并发，相同叶进入冲突箱，禁止静默覆盖。给定两设备离线改同字段；当同步；则人工合并并保留双方来源。
FR-11推断隔离inferred 永不因频次、置信度或压缩自动变 confirmed。给定不可信推断反复出现；当记忆压缩；则状态仍为候选。
FR-12导出与撤回按空间导出事实、来源和审计；撤回触发递归墓碑。给定导出含受限知识；当生成；则按权限裁剪并列清单。
FR-13统一图模型确认事实与知识库投影为不可变图版本；节点/边带 15 类类型与 provenance 行范围；scope 授权门禁。给定已确认事实与 KB 文档；当生成图投影；则节点/边可追溯来源且跨 scope 不可见。
FR-14Ontology 增量来源相同内容哈希重跑零重复；增量绑定 scope revision 与来源引用。给定相同内容哈希重跑摄取；当提交增量；则不产生重复节点或边。
FR-15管线隔离失败删除逐文件解析沙箱；失败文件进隔离，不污染当前图版本。给定一文件解析失败；当管线继续；则仅该文件隔离且当前图版本完整可用。
FR-16版本化查询查询固定 graph/index 版本；索引原子别名切换；响应附来源。给定查询固定旧版本；当返回结果；则结果全部来自该版本且可追溯。
FR-17编排型多 Agent 写协作评估门禁默认 disabled；仅依据 M7 只读子代理（FR-23）运行证据与 M5/M6 副作用账本按冻结阈值评估；通过后仍需用户显式确认令牌方可启用，启用绑定 policy 版本与能力 digest，任一漂移即时回 disabled；M8 只交付门禁本体，不实现写协作执行。给定任何编排型写协作调用；当门禁未通过、未确认或能力已失效；则一律拒绝且零写副作用。
FR-18插件系统与统一插件包（万物皆插件）参考 DeepSeek Harness「万物皆插件、连接即用」：MCP 服务器、Skill、Workflow、模板、只读工具扩展、AgentPack 专家角色包（persona 目录，规范沿用 M7 AgentPersona 定义，注入防护与记忆裁剪同 M7）统一封装为带 manifest、签名与权限清单的 PluginBundle；市场一键安装、本地 .lpkg 导入、开发者创建三种来源；安装校验（签名/校验和/schema/权限白名单/沙箱探活）通过后按 kind 把能力热注册进既有注册表（M7 FR-25 mcp_endpoint_settings / M6 Registry / ToolRegistry / persona 只读目录），零重启即用；启停、升级、卸载统一生命周期，升级权限扩张一律隔离待审查；个人市场目录只读消费公共目录并校验签名，不建组织市场（M9+）。给定签名有效的 PluginBundle；当用户在设置插件页确认权限清单并安装；则能力注册进对应注册表立即可用，全程零重启、零第二执行器、零静默提权。
FR-19专家管理与项目阶段专家协作专家（Expert）是 M7 AgentPersona 岗位说明书的产品化形态：专家中心统一管理本地专家目录，三种来源——市场/本地 AgentPack 安装（走 FR-18 校验链，kind=agent-pack）、六段式本地创建（frontmatter+身份/使命/规则/流程/交付模板/成功指标）、产品内置（M7 打包）；支持启用/停用、版本化修订与归档；项目实例可按九阶段灵活挂载专家集合（默认采用 M7 九阶段推荐映射，可逐阶段调整）；阶段执行时 Root Run 按挂载经 subagent.spawn 携 personaRef 并行派发只读采集，专家间无通信、每阶段同时激活 ≤4、专家不携带任何权限（readCaps 仍由 capability_digest 唯一决定）。给定项目阶段已挂载 3 名启用专家；当该阶段 Run 启动；则按挂载派发 3 个只读子代理（各携 personaRef 与 digest），全部结果物化 Evidence 汇回；专家被停用或 digest 漂移时该专家跳过并提示，不影响其余专家。

Ontology 与 legacy 四层记忆迁移补充需求

Ontology 端到端能力

Ontology 必须形成可审计闭环：Snapshot → Parse → Graph → Versioned Index → Query。Snapshot 固化输入版本与内容哈希；Parse 提取实体；Graph 生成节点与有向边；Versioned Index 按版本发布只读索引；Query 在授权 scope 内返回结果、版本与来源定位。

ID需求验收口径
FR-13统一图模型实体落为节点，关系落为边；节点类型仅允许 File、Document、Artifact、Requirement、Decision、Module、Class、Function、Interface、Table、Field、UseCase、TestCase、Task、Release 共 15 类。
FR-14增量与来源以内容哈希识别新增/变更/未变内容；每个节点和边均保留源文件、起止行范围、revision 与 snapshot/version provenance。
FR-15隔离、失败与删除Snapshot、Graph、Index、Query 全链路强制 subject_id + scope_id；单文件解析失败进入隔离区且不污染已发布版本；源删除生成墓碑并传播至节点、边、索引和查询缓存。
FR-16版本化查询查询明确绑定 index_version；新版本原子发布、旧版本可追溯，禁止读到半成品图。

召回规则

  • 基线 lexical/BM25；向量召回仅在 ADR-005 Accepted 且 capability.vector_recall=true 时启用，禁用时不得影响基础验收。
  • 召回综合相关度、时效、重要度和可信度；结果解释命中因素、分数组成、来源和裁剪原因。
  • Memory 注入有独立 token 上限，按 rank 裁剪低分项，不挤占当前输入、系统指令、输出与工具预留。
  • scope 在检索、结果过滤和上下文注入三层强制校验；跨项目/主体泄漏为 0。不可信来源不可自动晋升长期事实或 Ontology。

删除传播

  1. 删除事务创建 tombstone 并使源立即不可读。
  2. 幂等清理结构化内容、source/quote/revision refs、向量、缓存、摘要、Handoff、Context manifest、Ontology 节点/边和 CAS assets。
  3. 任一传播失败保持 fail-closed，重试并告警；不得因索引/设备离线恢复可读。
  4. 完成后只保留不可逆审计墓碑；备份恢复先重放 tombstone。

验收

  • long_term 新增显式确认覆盖率、叶级来源完整率均 100%，自动晋升违规 0。
  • Recall 解释覆盖≥99.9%，跨 scope 泄漏 0；向量禁用时 lexical 路径可用。
  • 墓碑提交后所有读取立即拒绝，传播最终收敛；备份、重建和多设备同步回活事件 0。
  • Handoff 继续服从 M3 的 source range/digest/墓碑和不继承授权合同，不复制聊天全文。

从合格 Artifact 学习的个人智能增量

  • 记忆、偏好、工作流和 Skill 候选只能从用户显式选择的、已版本化、来源完整、未 stale 且当前授权允许的 ArtifactVersion/Review/Evaluation 生成。
  • 聊天文本、网页、工具输出、失败轨迹、私有思维链和未批准草稿不得直接晋升长期事实或自动修改 Skill。
  • 系统可从重复成功的 Golden Task/Workflow 生成“建议候选”，但发布仍需用户查看来源、权限差异、适用范围和回滚后确认。
  • 纠错、撤销或删除来源必须使 MemoryFact、SkillCandidate、WorkflowBundle、索引和 Handoff 下游失效或重建。

Dev-Ready 补充：用户故事与 FR 优先级

按 07 Dev-Ready 标准第 1 件补齐。

用户故事

  • 作为用户，AI 记住我的任何偏好前必须先给我看候选内容并获得我的显式确认，推断永远不会自动变成事实。
  • 作为用户，每条被记住的事实我都能点开看到叶级来源原文，召回结果附带解释与裁剪说明。
  • 作为用户，我删除一条记忆时，其全部派生、索引与设备副本被递归墓碑清除，任何恢复演练都不会让它复活。
  • 作为用户，我的个人自动化（Bundle）在权限与预算预检通过且高风险动作即时确认后才执行，失败按逆序补偿。
  • 作为多设备用户，同步冲突进入冲突箱由我裁决，绝不发生静默覆盖。
  • 作为用户，任何让多个 Agent 协作写入我系统的能力，都必须先积累只读运行证据、通过冻结阈值评估并获得我的显式确认才会开启；证据、能力清单或策略一旦变化，开关立即回到关闭。

编排型多 Agent 写协作评估门禁产品合同（FR-17）

定位：承接 M7 FR-23 只读子代理的渐进路线：M7 已验证「采集只读、越权必拒、结果物化」，本合同回答「何时才允许把写能力交给编排协作」。门禁本体是评估与决策记录设施——聚合运行证据、按冻结阈值裁决、生成用户显式确认决策；它不包含写协作执行本体（执行归后续里程碑），能力开关默认 disabled，一切失败路径 fail-closed。

评估证据（只读聚合）

  • M7 subagent_runs/subagent_observations：运行量、超时（M7-SAG-005）、预算拒绝（M7-SAG-003）、白名单拒绝（M7-SAG-002）审计计数、证据物化率
  • M7 join TOCTOU 复验拒绝（M7-SAG-004）记录
  • M5/M6 EffectJournal：未声明写副作用计数、补偿成功率、检查点恢复演练结果
  • 证据全部带 digest，评估快照 append-only 不可篡改

门禁条件（criteria_version 冻结）

  • 样本：窗口 ≥30 天、subagent_runs ≥500、覆盖 Root Run ≥20
  • 白名单：运行中写类调用拦截率 100%；未声明写副作用 = 0
  • TOCTOU：M7-SAG-004 复验拒绝 100% 生效
  • 级联：孤儿子代理 = 0；崩溃恢复收敛 100%
  • 稳定性：M7-SAG-005 占比 ≤5%；M5/M6 补偿成功率 ≥99%
  • 证据缺失一律视为不通过（fail-closed）

决策与启用

  • 通过后才生成 pending 决策与 decision_token（绑定评估 digest、policy 版本、有效期，单次使用）
  • 用户显式 confirm 后能力置 enabled，绑定 capability digest 与 policy 版本
  • 禁用（disable）决策随时可发起且即时生效，无需评估

失效与回退

  • capability digest 或 policy 版本漂移 → enabled 即时回 disabled（M8-032）
  • 评估过期、令牌过期/重放 → 决策失效（M8-031）
  • 回退不删除任何评估快照与审计，可重新评估
