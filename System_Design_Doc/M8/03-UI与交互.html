关键旅程

  1. 确认候选：打开候选→核对每叶来源→可编辑→选范围/保留期→确认摘要→生成事实→提供撤回。
  2. 解释召回：结果→“为何出现”→命中因子/来源→策略裁剪→反馈；反馈不直接改写事实。
  3. 冲突合并：逐字段选择本机/远端/自定义→预览来源→确认→广播新版本。
  4. 删除：影响预览→强确认→立即隐藏→显示索引/缓存/派生/设备回执→清除证明编号。
  5. 专家挂载：选项目阶段→查看默认映射建议→增删专家（≤4 实时计数）→确认落库→阶段 Run 派发时跳过项显示原因。

设置 · 插件管理页（FR-18）

归属「设置 → 连接与代理」分区（全局信息架构 3.4，与 M7「MCP 服务器」页并列），是插件在 M8 的唯一管理入口；对话流中不得出现“安装插件”捷径，防止绕过来源确认与权限清单审查。

区域内容与交互API 时机
页头与导航标题「Plugins」+ 说明「通过安装插件来增强您的体验」；左侧次级导航四个入口：已安装 / 开发者工具 / 模板 / 浏览市场；右上「创建插件」入口（开发者态）进入页面即 plugin.list；导航切换不触发请求（客户端过滤）
已安装列表每行：插件图标、名称、版本（semver）、publisher、kind 徽标（mcp/skill/workflow/template/tool/agent-pack）、状态色点（绿=enabled/黄=disabled/红=quarantined）、能力绑定数；行内开关启停；行尾「详情」进入 /settings/plugins/:installIdplugin.toggle（开关，即时撤销/恢复全部绑定）；列表数据来自 plugin.list
插件详情页Tab1 概览：manifest（entrypoint、requires、capabilities）、签名状态与指纹、package_hash、来源（market/local/dev）与安装时间；Tab2 权限：按安全/风险分色清单 + 已授权快照 diff；Tab3 升级：可用版本、权限差异（扩张红色高亮）、回滚点；Tab4 卸载：派生影响预览（绑定、凭据、派生物）plugin.market.detail（升级信息）；plugin.upgrade（确认升级）；plugin.uninstall（强确认后）
浏览市场搜索框 + kind 筛选；结果卡：名称、publisher、简介、semver、签名标识、下载量；「安装」进入安装确认流plugin.market.search（输入防抖）；plugin.market.detail（展开卡）
安装确认流（三步）步骤1 权限清单（逐项列出，风险项默认展开说明）→ 步骤2 来源与签名核对（publisher、digest、签名指纹）→ 步骤3 确认安装（黄色警示条「请确认插件来源，甄别风险」+「取消 / 确认安装」）「确认安装」→ plugin.install { origin, source, permissionGrant }；verifying 态显示校验链逐项进度
本地导入「导入 .lpkg」按钮 → 文件选择 → 复用安装确认流（origin=local，警示条加强：「本地包未经过市场审核，请自行确认来源」）plugin.install { origin: 'local', source: localPath }
开发者工具开发者工作区列表、manifest 编辑器（schema 实时校验）、打包预览（生成 .lpkg 与 package_hash）；「创建插件」向导：选 kind → 填 manifest → 选 entrypoint → 预览权限清单plugin.dev.create（默认 quarantined，须手动启用）
隔离横幅存在 quarantined 插件时页面顶部固定横幅：「N 个插件待审查：签名失效/权限扩张」+「查看」；审查页只提供「卸载」与「审查放行」两个动作，放行需逐项勾选新增权限放行 = 重新提交 plugin.install 权限确认（生成新 permissionGrant）

关键旅程与安全交互

  1. 市场安装：浏览市场→搜索→展开详情→安装确认流三步→verifying 进度（签名/校验和/schema/权限白名单/探活逐项打勾）→ installed/enabled → 能力立即可用（零重启提示「插件已连接，可直接使用」）。
  2. 升级审查：详情页升级 Tab→权限差异 diff（新增权限红色）→ 升级→若扩张则 quarantined + 隔离横幅→审查放行逐项勾选→新版本启用；拒绝则保留旧版本可回滚。
  3. 卸载：详情页卸载 Tab→派生影响预览（将撤销的绑定数、将清理的凭据与派生物）→ 强确认（一次性令牌）→ 绑定即时 revoked → 墓碑进度→「已卸载」终态。
  • 所有安装/升级/放行动作必须经三步确认流；对话流与 Agent 不得触发安装 UI（工具面不提供 plugin.install 给模型调用）。
  • 权限清单不得折叠风险项；quarantined 插件的能力在任何入口均不可见不可调（M8-040）。
  • 状态色点必须有文本等价（enabled/disabled/quarantined），开关与「详情」均可键盘操作。

专家中心页（FR-19）

归属能力中心分区（全局信息架构 3.5，位于「资产管理」与「技能中心」菜单之间），是专家目录、创建、启停与项目阶段挂载的唯一 UI 入口；对话流中不得出现「挂载/创建专家」捷径，防止绕过六段式校验与挂载上限审查。路由 /experts（列表）、/experts/:expertId（详情）、/experts/new（创建）、/experts/mounting?projectId=（项目挂载矩阵）。

创建专家向导（三步）步骤1 frontmatter（名称、division 下拉、描述、初始 semver）→ 步骤2 六段式逐段编辑（每段有填写指引与示例，源自 M7 岗位说明书模板）→ 步骤3 校验与创建（frontmatter schema→六段非空→注入防护扫描逐项打勾→digest 预览→「创建并启用」）「创建并启用」→ expert.create；verifying 态显示校验链进度，失败 M8-042 定位到具体段落
项目阶段挂载矩阵选择项目 → 九阶段列（M7 固定 key 与中文名）× 专家行的矩阵视图；每阶段显示默认映射建议（M7 推荐映射，标注「建议」徽标可一键采纳）+ 已挂载专家卡（版本锁定 semver、来源、状态）；「+ 添加专家」打开本阶段可选专家抽屉（enabled 且未挂满）；每阶段实时计数「n/4」，达到上限即禁用添加并提示；专家停用/来源包停用时卡片显示「将跳过」标签与原因expert.mounting.get（进入即拉取）；expert.mount {action:'mount'|'unmount'|'updateVersion'}（增删与版本更新，超限 M8-044 即时拦截）
归档确认详情页「归档」→ 影响预览（活跃挂载数、历史版本数）→ 存在活跃挂载时直接拒绝（M8-048）并引导先解除 → 无挂载时强确认（一次性令牌）→ archived 只读终态，历史版本保留可审计expert.archive（强确认后；409 时回显挂载清单链接）

关键旅程与安全交互

  1. 六段式创建：创建向导→填 frontmatter→逐段撰写（实时段界校验）→校验链三步打勾→创建并启用→列表立即可见、可挂载。
  2. AgentPack 承接：插件市场装 agent-pack→安装校验链通过→专家列表出现来源包专家（source=pack）→直接可用或停用观察；来源插件停用时专家卡片显示「来源包已停用」并从派发跳过。
  3. 阶段组队：挂载矩阵→选项目→某阶段「一键采纳建议」或手动添加（≤4 实时计数）→确认落库→阶段 Run 启动按挂载并行派发→运行详情中每专家 Evidence 独立归集，跳过项显示 M8-047 原因。
  4. 停用与恢复：列表开关停用→提示受影响挂载数→挂载处显示「专家已停用，将跳过」→重新启用即时恢复派发资格。
  • 专家卡片必须同时展示「不携带权限」说明：专家只影响子代理提示词身份，readCaps 由能力 digest 唯一决定，任何六段文案不构成授权。
  • 「六段式」编辑不得允许内嵌工具调用指令绕过注入扫描；扫描失败段标红并阻止提交（M8-042）。
  • builtin 专家允许停用但隐藏「归档」入口；archived 专家仅详情只读，不提供任何恢复按钮。
  • 状态色点必须有文本等价（enabled/disabled/archived/source-disabled），开关、矩阵单元格与抽屉均可键盘操作；计数 n/4 使用 aria-live 播报。

写协作评估门禁页（FR-17，P2 可延期）

路由 /memory/collab-gate，是 FR-17 能力开关与评估决策的唯一 UI 入口；任务卡 T-8.8.5、测试 GT-06 与 05 门禁切片 G2 均以本节为冻结规格。页面仅当 M7 FR-23 切片 6 上线且证据窗口 ≥30 天后可用；延期期间整页显示 disabled 固定态说明，不提供任何评估入口。

区域组件与状态关键交互与安全约束
能力状态卡（页头固定）capability 大徽标（disabled 灰 / enabled 绿）、effectiveAt、decisionId、policyVersion、capabilityDigest（截断+复制）；状态：disabled、enabled、drifted_disabled（漂移回退横幅）进入页面即 collabGate.status 快照读；disabled 态零编排细节暴露——不显示任何子代理运行统计、证据来源明细或阈值细节，仅显示「写协作未启用」与启用前置条件说明；enabled 态展示绑定四元组供对账
评估发起区评估窗口（windowStart/windowEnd 只读，默认最近 ≥30 天）、criteriaVersion 冻结单标识、「开始评估」按钮；状态：idle/computing/insufficient_evidence/pass/fail「开始评估」→ collabGate.evaluate；证据源不可用时显示 fail-closed 说明（M8-033）且不产生部分结果；同窗口重复点击幂等返回原 evaluationId（按钮置灰并显示已完成评估链接）
评估报告outcome 结论、五类门禁条件逐条达标/未达标（运行样本、白名单拦截、TOCTOU 复验、级联取消、稳定性）、evidenceDigest（可复制）、failedCriteria 列表（fail 时逐项列出）报告数据只读、不可编辑（快照 append-only，M8-034）；每项条件显示证据来源类型与是否可复算；insufficient_evidence 时逐条说明缺失项，不显示任何部分通过暗示
决策确认区（仅 pass 后出现）决策摘要（评估快照 digest、policyVersion、capabilityDigest、有效期）、decisionToken 输入框、「确认启用」强确认按钮；状态：pending/confirmed/expired/revokedcollabGate.confirm；令牌单次使用，过期/重放显示 M8-031 明确文案并指引重新评估；确认后刷新 status 卡显示 enabled 与生效时间；无任何「强制启用」「跳过评估」路径
漂移与失效反馈全局横幅：能力绑定漂移已即时回 disabled（M8-032）、决策已撤销/过期；横幅附 evaluationId 关联号漂移横幅出现时禁用启用按钮直至重新评估通过；用户主动 disable 同样经决策令牌流程，无免确认关闭捷径

关键旅程与无障碍

  1. 首次评估：status 卡（disabled）→ 核对前置条件说明 → 开始评估 → 等待 computing → 查看 insufficient_evidence 报告（或 pass）。
  2. 启用决策：pass 报告 → 核对决策摘要四元组 → 输入 decisionToken → 确认启用 → status 卡转 enabled 并展示绑定对账信息。
  3. 漂移处置：enabled 使用中发现漂移横幅 → 页面自动回 disabled 展示 → 重新评估 → 重新确认。

全程键盘可达、焦点可见；confirm 决策与令牌输入支持读屏逐项播报（GT-06）；状态变化 aria-live；200% 缩放不遮挡确认按钮；漂移/过期等失败态提供可复制关联号而非堆叠细节。

迁移文案与确认边界

  • working → Run context：标明“仅当前运行，按 TTL 清理”。
  • short_term → MemoryCandidate：标明“尚未成为长期事实”，由用户显式确认。
  • long_term → confirmed MemoryFact：仅显示可验证的历史确认凭证；inferred 或无凭证项显示“已降级为候选”，不得提供批量自动晋升。
  • semantic → KnowledgeBase + Ontology projection：区分原文事实源与可重建图投影。
  • episodic 不是第五层：只作为事件视图/标签展示，必须显示其实际归属层。

关键旅程与无障碍

  1. 排查解析失败：摄取页→选择 quarantined 文件→查看脱敏错误与 revision/行范围→修复后重试→校验新版本→原子发布。
  2. 追溯图结果：查询结果→节点/边详情→版本与 provenance→在授权范围内跳转源文件行范围。
  3. 审阅迁移：选择 scope/批次→核对四层计数与降级项→抽样来源→启用 canary；暂停/回滚不改 legacy 源。
  4. 删除与回活处置：查看传播 ACK→恢复演练→若节点/边/缓存回活则页面保持阻断，提供关联号而不泄露其他 scope。

新增页面延续键盘、读屏、aria-live 与 200% 缩放要求；图关系不得仅靠颜色表达，提供可聚焦的节点/边列表等价视图。
