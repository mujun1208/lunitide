功能需求与规则

ID合同
FR-M0-01唯一生产基线为 Go Core Engine + Windows WebView2 Host + React/TypeScript Renderer；正式包不得依赖 Electron、Node Runtime、Python 或 FastAPI。
FR-M0-02Renderer 只可调用生成的 Bridge SDK，不得直连文件系统、注册表、Secret、shell、数据库或任意网络。
FR-M0-03Host↔Engine 使用当前用户 ACL 的 Named Pipe、长度前缀帧和认证握手；单帧≤4MiB，大内容只传内容寻址引用。
FR-M0-04握手绑定 SID、PID、进程创建时间、nonce、协议版本、Pipe 实例与 HMAC transcript；密钥不得经命令行、环境变量或普通文件传递。
FR-M0-05Bridge 请求、成功响应和失败响应使用独立 schema；请求至少含 v、kind、id、traceId、method、sentAt、payload、deadlineMs，可写命令另含 idempotencyKey。
FR-M0-06流事件以 (streamId,seq) 去重，seq 从 1 单调递增；done/error 后禁止继续发事件；关键事件可重放，纯 token delta 可合并。
FR-M0-07SQLite migration 只前向新增、事务执行；失败不得半应用。启动诊断必须区分 Host、Engine、IPC、数据库迁移、Renderer 资源装载故障。

状态进入条件允许动作

验收

  • 未知协议 major 拒绝启动；minor 只启用双方共同能力集。
  • 同 SID 抢连、旧握手重放、替换 Engine、设备路径和超大帧均被拒绝并审计。
  • Renderer 注入脚本无法获得本机特权；迁移断电恢复不产生半版本。
  • 诊断包可定位失败阶段且敏感正文、Key、令牌出现数为 0。
