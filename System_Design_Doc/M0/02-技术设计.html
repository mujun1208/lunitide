IPC 握手协议（Legacy 基线）

Host ↔ Engine 握手在 Named Pipe 建立后、任何 RPC 之前完成，失败一律 fail-closed。以下细节转录自旧版架构 ADR-002（V1 CH.04），作为 M0 可构建基线的设计合同。

阶段强制契约
启动密钥传递Host 创建至少 256-bit 启动密钥，通过不可继承的受限句柄/匿名管道传给其直接子进程 Engine；禁止命令行、环境变量和普通文件传递
实体认证握手 MUST 校验当前用户 SID、客户端 PID、会话 nonce、协议版本；并对 Pipe 实例、双方 PID/创建时间、协议版本和 challenge 做 transcript-bound HMAC
映像校验Host 校验 Engine 映像绝对路径、file identity、Authenticode signer/hash、父子进程关系与 Job membership
帧格式消息使用长度前缀，不以换行作为安全边界；Pipe frame 最大 4 MiB，大文件只传受控 asset reference
失败处理同 SID 抢连、PID 复用、旧握手重放和二进制替换全部 fail-closed 拒绝启动
版本协商握手协商 rpcMajor/rpcMinor：major 不同拒绝启动；minor 采用双方较低能力集；同一 minor 中未知字段忽略，未知枚举必须返回 BRIDGE_SCHEMA_INVALID
密钥通道Secret plaintext 不通过 Renderer；Engine 通过专用 SecretService 请求短暂使用（租约合同见 M1 技术设计）
与新版对齐：新版第 02 篇只要求"握手包含协议版本、实例 nonce，防止旧客户端误连"；本表为旧版完整细化，作为设计基线继承。M0 状态按三分口径记录（主体代码/内部验证/外验），本节不表示已实现或门禁已通过。

Engine 状态机（Legacy 基线）

旧版架构（V1 CH.06）冻结的 Engine 生命周期状态链：starting → migrating → ready → degraded → restarting → circuit_open → stopping → stopped。

状态语义
starting进程启动、Pipe 握手与初始化
migrating执行 schema migration journal（有序、事务回滚、重复启动幂等）
ready就绪，可接受 RPC
degraded启动超时或部分能力不可用，降级运行
restarting有界自动重启
circuit_open熔断：超过自动重启上限后停止自动重启，需人工介入（对应新版安全诊断模式）
stopping退出序列执行中
stopped终态

启动与重启规则：

规则阈值说明
启动超时15 秒超时未 ready 进入 degraded
自动重启上限60 秒内最多 3 次超过进入 circuit_open，需人工介入
启动检查必检项migration journal、SQLite integrity、孤儿 Worker

退出与崩溃恢复：退出顺序为先停止接收任务 → checkpoint → 取消网络请求 → 再终止 Worker；崩溃中的消息标记 interrupted，已提交消息不得丢失；外部副作用节点恢复时必须读取幂等记录，禁止盲目重放；只有满足幂等/补偿规则的 interrupted 节点可恢复。

与新版对齐：新版第 02 篇"Engine 崩溃后由 Host 有界重启；超过熔断阈值进入安全诊断模式，不循环重放副作用"即本状态机的压缩表述，两者一致。

原型迁移契约：Electron/Python 0.2.1 → Go（Legacy）

原型定位不变：React 设置交互意图、Provider 领域规则、模型列表和诊断分类可迁移；Electron/Python/FastAPI/electron-updater 技术实现一律重写。迁移前原型保持可回退，失败不得修改原目录，也不得生成明文 Key 导出文件。旧版把该契约排在 M1 冻结、M2 完成真实用户迁移验收；M0 只承载契约本身。
步骤强制契约
来源探测冻结对原型 provider schema v1/v2 的迁移契约；来源仅为 %APPDATA%/lunitide/providers.json 和用户显式选择的备份。以内容 schema version + 结构校验为准，不信任 README/package.json 展示版本。启动前记录 source path、schema version、safeStorage backend availability、file SHA-256、记录数和损坏状态
非敏感配置只读解析 providers.json，迁移 name/protocol/origin/models/defaultModel 到 SQLite staging；校验数量、唯一性和默认模型后事务提交。old UUID 通过持久 journal 确定性映射到固定 new ULID，重复运行复用映射
签名 helper一次性迁移 helper 必须来自已签名旧安装上下文，仅作迁移工具而非生产依赖。Host 创建随机 Pipe 名和 256-bit nonce，通过受保护的继承句柄传递；Pipe ACL 仅当前用户，Host 校验 helper 签名、file identity、PID、父子关系和 nonce；协议固定为 migration.secret.v1，frame ≤128 KiB
Key 转移用户先确认 provider 清单；helper 每次只解密一条 safeStorage Key，经一次性 Pipe 发送；Host 端立即以 DPAPI CurrentUser 重加密并清零缓冲。禁止临时文件、日志、剪贴板和 Renderer；每条以 oldProviderId + sourceFileHash 为 journal 主键并逐条 ACK
失败恢复超时、重复 ACK、Host/helper 中途崩溃和重放必须安全重跑。失败删除新 credential、旧数据不变；safeStorage 不可用或密文损坏时仍迁移非敏感配置并标记 credentialState=requires_reentry。成功后做最小真实连接测试，全部完成后由用户选择保留只读加密备份或删除旧数据

冲突规则：同名但 origin 不同的 Provider 不自动合并；相同 protocol + normalized origin 只提示合并，默认保留两条；默认模型不存在时取消默认并要求用户选择；旧配置把连接串称为 OData 时，仅迁移为 DatabaseConnector 候选并要求确认，禁止静默转换为 OData endpoint。

迁移 Golden corpus：CI 必须覆盖 schema v1/v2、损坏 JSON、重复 Provider、缺失默认模型、缺失/损坏 Key、safeStorage 不可用、确定性 UUID→ULID、重复迁移、部分成功、Host 中途崩溃、helper 重放/伪造/抢连、重复 ACK 和 OData 错误标记。除受控 helper 单条转移窗口外，配置、DB、日志、诊断、dump 和稳定内存 canary 扫描不得出现明文 Key。协议枚举冻结 openai_compatible | anthropic：旧 openai→openai_compatible；旧 UUID 保存为 legacy_id；旧 checkedAt→testedAt；旧 ok/detail→status/errorCode/sanitizedMessage。
