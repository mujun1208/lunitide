角色与关键旅程

角色旅程结果
模型使用者新建 Provider→输入地址/协议/Key→测试→同步模型→选择模型。失败可定位到地址、认证、模型或网络策略，不泄露 Key。
凭据所有者编辑、显示、隐藏、覆盖或删除已保存 Key。默认隐藏；显式显示有本地交互确认和审计；覆盖后旧版本立即失效。
安全审查者检查 Secret 生命周期与出口策略。配置文件、DB、日志、dump、普通 Renderer DOM 中 0 明文 Key。

Provider 数据与业务规则

对象字段/规则
Providerid、name、protocol(openai_compatible|anthropic)、base_url、credential_ref、status、origin_fingerprint、version；name 与地址必填，地址必须 HTTPS（显式本地开发例外需策略允许）。
ModelProfileprovider_id、remote_model_id、display_name、context_window、max_output_tokens、capabilities、tokenizer_ref、fetched_at；同步单次≤50 个模型。
ProviderTestprovider_id、config_version、started_at、ended_at、result、latency_ms、redacted_error、correlation_id；不得保存响应敏感正文。
ID需求
FR-M1-01Key 由 Host 使用 DPAPI CurrentUser 保存，只向 Engine 发放绑定 session/nonce/origin/version 的单次 Secret lease；TTL≤5 秒、载荷≤64KiB。
FR-M1-02供应商编辑页按用户明确要求默认直接显示已保存 Key并提供隐藏，但只能由 Host 原生受保护控件短时解密显示，需本地用户交互确认，失焦/超时/切页立即清除；不得进入普通 WebView DOM、剪贴板历史、日志、遥测或导出。
FR-M1-03origin（scheme+host+port）变化不得复用 credential；必须重新确认或录入。
FR-M1-04所有外部请求统一经过 EgressBroker：DNS/IP/端口/重定向逐跳重验，拒绝 loopback、私网、link-local、metadata endpoint 与 DNS rebinding。
FR-M1-05流开始后遇到不确定网络结果默认不自动重放；可证明未产生副作用的幂等请求才可在预算内重试。
