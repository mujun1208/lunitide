CHAPTER 01

数据与接口中心总览

Configuration First

数据与接口中心以 Integration 为治理根实体，以可扩展 Connector Registry 装载协议适配器，并将数据库环境绑定、接口配置、契约比对、迁移包、测试与审计收敛到一个配置优先工作台。各类型保留协议原语，但共享 注册 → 配置 → 测试 → 启用 → 调用 → 审计 生命周期。

1.1 Integration 根实体与 Connector Registry

IntegrationROOT ENTITY
  • id / project_id / name — 项目内稳定标识与展示名
  • connector_key — 指向 Registry adapter，不在根实体硬编码协议类型
  • direction inbound | outbound — 传入 / 传出
  • role consumer | provider — 我调用 / 我提供
  • environment_bindings — 开发、测试、生产各自端点、数据库与 CredentialRef
  • config / mapping / status — 连接器配置、字段映射及 draft / enabled / disabled

Connector Registry 通过版本化 adapter schema 提供配置表单、连接测试、契约测试、调用与日志脱敏钩子；新增类型不修改 Integration 根表。下表是目标类型目录，不等于 M0–M2 全部内置：

1.2 配置交互与字段映射

简易模式

字段表单选择来源字段、目标字段、类型转换、必填、默认值与空值策略；支持逐行增删、即时校验和示例预览。

复杂模式

可粘贴 JSON、YAML 或请求 / 响应示例，由 adapter 解析并建议 schema 与映射；保存前执行大小、语法、敏感值与危险引用检查。

方向与角色必须同时展示：我调用（consumer）通常为传出，我提供（provider）通常为传入；允许事件回调等组合，但 UI 必须解释数据流并纳入权限评审。

1.3 凭据管理原则

只存引用，不存明文

所有集成类型的凭据（API Key、Token、连接串、密码）一律以 CredentialRef 引用形式保存。v1 的 SecretService 位于 WebView2 Host 信任边界内，以 DPAPI CurrentUser 托管；明文永不下沉到集成配置表、Renderer 或日志中。

  • 引用而非值：Integration 实体只持有 cred_ref_id；Engine/Connector 禁止使用通用 Resolve 取得长期句柄
  • 作用域限定：Host 内部可使用 WithSecret；Engine 只能通过绑定请求的短时 Secret Lease 使用凭据
  • 轮换无感：凭据轮换不影响 CredentialRef 本身，引用保持稳定
核心原则：凭据仅存引用，不存明文。任何将明文凭据写入配置、日志、错误消息的行为均视为安全违规。

1.4 健康状态模型

健康状态不得只依赖最后一次结果，应由滑动窗口（sliding window）综合计算。窗口内采样按权重聚合，避免单次抖动导致误判。

→

→

状态含义触发条件

CHAPTER 02

API 集成

HTTP / REST · OpenAPI

API 集成支持 OpenAPI 3.0 / 3.1 规范导入，自动生成操作清单。导入阶段强制执行安全限制，避免恶意规范触发 SSRF、资源耗尽或无限引用解析。

2.1 OpenAPI 导入

支持的规范版本

  • OpenAPI 3.0 consumer 子集：M6 支持 servers、paths、parameters、requestBody、responses、components/schema、API Key/Bearer/Basic；回调、links、复杂 discriminator 明确报 unsupported
  • OpenAPI 3.1：后续里程碑；需冻结 JSON Schema 2020-12 vocabulary、dynamicRef/webhooks 支持矩阵和兼容 corpus 后启用
  • Swagger 2.0：后续兼容导入；转换必须输出差异/丢失项，禁止静默声称完整等价

2.2 导入前安全限制

在解析任何外部 OpenAPI 文档前，必须强制执行以下限制：

限制项默认值说明
URL 限制SSRF 白名单 + 私网段拒绝导入源 URL 必须通过 SSRF 校验，拒绝 127.0.0.0/8、10.0.0.0/8、169.254.0.0/16 等私网与元数据端点
文件大小限制≤ 5 MB超出直接拒绝，避免内存耗尽
$ref 深度限制≤ 10 层防止循环引用与深层嵌套导致的栈溢出
$ref 解析范围同源 + 白名单跨源 $ref 仅允许指向预先批准的 registry 域名
操作数量上限≤ 500 paths单规范导入操作数上限，防止规范膨胀
结构总量版本化安全预算限制总节点、ref 数、展开后字节、YAML alias、解析时间和内存；重复 key、alias bomb、循环图与超预算全部拒绝
导入安全：URL 限制、文件大小限制、$ref 深度限制必须在解析前强制执行。任何一项超限即终止导入，不进行部分加载。远程 $ref 解析复用与 API 调用相同的 SSRF/TLS 控制通道。

2.3 认证方式

认证类型协议字段凭据存储
API Keyheader / query / cookieCredentialRef → SecretService
BearerAuthorization: Bearer {token}CredentialRef → SecretService
BasicAuthorization: Basic {base64}CredentialRef（用户名与密码分项引用）
OAuth2授权码 / 客户端凭证 / 密码分阶段支持，token 刷新由 SecretService 托管

2.4 配置要求

以下四项必须显式配置，不接受隐式默认：

  • 分页（Pagination）：必须声明分页策略（offset / cursor / page-token）与单页上限
  • 重试（Retry）：必须声明重试次数、退避策略、可重试状态码集合
  • 幂等（Idempotency）：必须声明幂等键来源（header / body field）与有效期
  • 响应映射（Response Mapping）：必须声明响应字段到内部模型的映射规则

2.5 ApiOperation 实体

ApiOperationENTITY
  • method string — HTTP 方法（GET / POST / PUT / PATCH / DELETE）
  • path string — 操作路径模板，含 {param} 占位符
  • auth CredentialRef — 认证凭据引用（不存明文）
  • headers map[string]string — 静态请求头与模板化请求头
  • body_mapping FieldMapping — 请求体字段映射（请求模型 → 外部 API 字段）
  • response_mapping FieldMapping — 响应字段映射（外部 API → 内部模型）
  • pagination PaginationSpec — 分页策略
  • retry RetrySpec — 重试策略
  • idempotency IdempotencySpec — 幂等键配置
CHAPTER 03

MCP 集成

P0/P1: remote + built-in only

MCP（Model Context Protocol）集成分两类：本地 stdio server（子进程）与远程 MCP（Streamable HTTP / SSE）。两者共享工具发现与授权流程，但安全控制重点不同。P0/P1 仅允许远程 MCP 与随产品发布、由产品 signer 签名且 manifest 固定的内建 stdio 工具；第三方 stdio 只能导入、检查和隔离展示，runnable 必须为 false。

3.1 stdio Server 要求

本地 stdio server 以子进程方式运行，是最高风险的集成类型之一，必须满足：

可执行文件信任验证

  • P0/P1 可执行文件必须属于产品签名内建清单；用户哈希白名单不能把第三方文件升级为可执行
  • 第三方二进制即使签名或 hash 已知，也只能进入 quarantine，直到隔离 POC 与 ADR 获批
  • 信任清单变更属于高危操作，需独立 Review 并更新信任根

argv 结构化

  • 命令行参数必须以结构化数组形式声明，不接受 shell 字符串拼接
  • 禁止通过 argv 注入 shell 元字符或环境变量展开

工作目录与环境白名单

  • cwd（工作目录）必须显式声明，不得继承调用进程的 cwd
  • 环境变量采用白名单机制；PATH/PATHEXT 也由系统构造且禁止当前目录搜索。exe 必须解析为绝对规范路径，以已打开文件句柄的签名/hash/file identity 校验后启动，防止校验后替换
发布红线：P0/P1 构建不得注册任何第三方/用户本机 stdio executor。未来开放必须先通过读取用户目录、局域网访问、子进程、Named Pipe、junction/ADS 全部拒绝的隔离 POC，并以独立 ADR 冻结能力；用户确认或 hash 白名单不能替代沙箱。

3.2 远程 MCP 安全

远程 MCP（Streamable HTTP / SSE）采用与 API 集成完全相同的 SSRF / TLS 控制通道：

  • SSRF 白名单校验目标 URL
  • TLS 证书校验强制开启，不支持跳过
  • 请求超时与连接数限制复用 API 通道配置

3.3 工具发现流程

MCP 工具发现结果不直接可用，必须经过隔离与授权：

tools/list 发现
→
隔离 registry
→
用户授权
→

隔离 registry：工具发现结果先进入隔离 registry，经用户显式授权后才可被调用。授权绑定工具指纹（名称 + schema 哈希），工具 schema 变更后旧授权自动失效。

3.4 McpServer / McpTool 实体

McpServerENTITY
  • transport stdio | http | sse — 传输类型
  • command string — stdio 模式下的可执行文件路径
  • argv []string — 结构化参数数组
  • cwd string — 工作目录（显式声明）
  • env_whitelist map[string]string — 环境变量白名单
  • endpoint string — 远程 MCP 的 URL
  • cred_ref CredentialRef — 远程 MCP 认证凭据引用
  • trusted bool — 是否通过信任验证
McpToolENTITY
  • server_id string — 所属 McpServer
  • name string — 工具名称
  • schema JSONSchema — 输入输出 schema
  • fingerprint string — 名称 + schema 哈希
  • authorized bool — 是否经用户授权
  • registry_state isolated | authorized | revoked — registry 状态
CHAPTER 04

ETL 集成

Batch Pipeline · Watermark

ETL 集成处理批量数据管道，核心是水位（watermark）机制：水位标记已成功同步的数据边界，仅在目标事务成功后推进。交付语义为 at-least-once；只有目标支持唯一键/幂等账本且写入实现去重时，才可称为 effectively-once，禁止对跨系统事务作绝对 Exactly-Once 承诺。

4.1 EtlJob 定义

EtlJobENTITY
  • source IntegrationRef — 源端集成引用（API / Database / OData）
  • target IntegrationRef — 目标端集成引用
  • schedule CronSpec — 调度表达式
  • mode full | incremental — 全量或增量
  • watermark WatermarkSpec — 水位字段与类型（timestamp / sequence）
  • timezone string — 调度时区（IANA，如 Asia/Shanghai）
  • mapping []FieldMapping — 字段映射规则集
  • batch BatchSpec — 批次大小与并发
  • deletion_policy retain | soft_delete | hard_delete — 源端删除时的目标处理策略

4.2 EtlRun 记录

每次执行生成一条 EtlRun，保存完整可审计信息：

EtlRunENTITY
  • job_id string — 所属 EtlJob
  • input_range {start, end} — 本次拉取的数据范围
  • watermark_before any — 执行前水位值
  • watermark_after any — 执行后水位值（仅成功时更新）
  • stats {rows_read, rows_written, rows_skipped} — 执行统计
  • errors []BatchError — 批次级错误明细
  • state EtlRunState — 状态机当前状态

4.4 关键规则

水位推进规则

  • 水位只在目标事务成功后推进：目标端写入事务 commit 成功后才更新 watermark_after
  • 部分失败不得提前推进水位：即使 99% 批次成功，只要有任一批次未确认，水位不得前移到失败批次覆盖的范围
  • 重试使用 source key + batch id 去重：重试时以源端主键与批次 ID 联合作为幂等键，避免重复写入
水位推进规则：水位只在目标事务成功后推进。重试使用 source key + batch id 去重。部分失败不得提前推进水位——未确认批次所覆盖的数据范围必须保留在水位之前，等待下次执行重新拉取。

4.5 FieldMapping 实体

FieldMappingENTITY
  • source_field string — 源端字段路径（如 $.user.email）
  • target_field string — 目标端字段路径
  • transform TransformSpec — 转换规则（cast / format / lookup / expr）
  • required bool — 是否必填（缺失时拒绝该行）
  • default any — 缺失时的默认值
CHAPTER 05

OData 集成

OData v4 HTTP Client / Service

OData 集成的正式定义为 OData v4 HTTP Client / Service Integration。它是基于 HTTP 的标准数据服务协议，不是数据库直连。

5.1 核心概念

概念说明
service rootOData 服务的根 URL，所有 entity set 与 singleton 的入口
metadata$metadata 端点返回的 CSDL（Entity Data Model）描述
entity sets可查询的实体集合，对应 OData 的 EntitySet
query options$filter / $select / $orderby / $top / $skip / $expand / $count
分页server-driven pagination，通过 @odata.nextLink 链式翻页
ETag并发控制与条件请求（If-Match / If-None-Match）

5.2 读写策略

OData 集成默认只读：仅允许 GET 操作。POST / PUT / PATCH / DELETE 必须在 entity set 级别显式开启，并绑定独立凭据与审计策略。

修正声明：OData 是 HTTP 服务协议，不是数据库直连。不得将 OData 集成与 Database Connector 混为一谈，也不得将数据库连接串直接包装为 OData endpoint。两者的安全模型、权限模型与审计要求完全不同。

5.3 ODataService / ODataEntitySet 实体

ODataServiceENTITY
  • service_root string — OData 服务根 URL
  • version string — OData 版本（默认 v4）
  • metadata_cached_at timestamp — metadata 缓存时间
  • cred_ref CredentialRef — 认证凭据引用
  • read_only bool — 默认 true
ODataEntitySetENTITY
  • service_id string — 所属 ODataService
  • name string — entity set 名称
  • allowed_query_options []string — 允许的查询选项白名单
  • writable bool — 是否允许写操作（默认 false）
  • etag_enabled bool — 是否启用 ETag 并发控制

5.4 发布本地数据为 OData 服务

若需将本地数据发布为OData 服务（即 Lunitide 作为 OData Server），必须额外满足：

  • 服务端认证：单独定义，不复用消费侧凭据
  • 字段脱敏：发布前必须声明字段脱敏规则，敏感字段不得透传
  • entity set 白名单：仅发布显式声明的 entity set
CHAPTER 06

数据库绑定、契约与迁移

DatabaseBinding · Contract · MigrationPackage

数据库能力服务于环境绑定、只读结构扫描、期望结构契约与受控迁移交付；Database Connector 仍是独立高风险连接器。首期明确不是 DB IDE，不提供自由浏览器、可视化任意改表或任意生产 SQL 编辑执行。

6.1 项目环境数据库绑定

  • 最低要求：每项目至少绑定 development 与 production 两套独立数据库；未满足时阶段五不可完成。
  • 推荐项：可选绑定 test，推荐用于迁移预演与契约测试。
  • 环境隔离：每套绑定独立保存 driver、host/port、database/schema、只读策略与 CredentialRef。
  • 连接配置与测试：表单录入非秘密元数据，秘密进入 SecretService；测试仅执行握手、身份与最小权限校验，不读业务数据、不写入。
  • 生产默认：生产强制只读扫描账号；迁移凭据与日常扫描凭据分离并按审批短时租用。

6.2 Database Connector 安全规则

  • 默认只读：连接器初始权限为只读，写操作需显式提升
  • 参数化查询：所有查询必须使用参数化接口，禁止字符串拼接 SQL
  • schema / table / column 白名单：仅允许访问白名单内的对象
  • 行数限制：单次查询返回行数上限，防止全表扫描
  • 执行时间限制：单次查询执行超时阈值，超时自动终止
  • 写操作强制 Review：任何 DML / DDL 操作必须绑定 Review 审批
警告：写操作（INSERT / UPDATE / DELETE / DDL）强制 Review。写操作不得在全托管模式下自动执行，必须由人工 Review 显式批准后方可执行。参数变化后旧批准失效。
类型边界：不得将连接串直连错误称为 OData。Database Connector 是直连协议（JDBC / ODBC / native driver），OData 是 HTTP 服务协议——两者不可互换命名，不可混用安全模型。

6.3 DatabaseConnector 实体

DatabaseConnectorENTITY
  • driver string — 数据库驱动类型（postgres / mysql / mssql / oracle ...）
  • cred_ref CredentialRef — 连接凭据引用（连接串不存明文）
  • read_only bool — 默认 true
  • schema_whitelist []string — 允许的 schema
  • table_whitelist []string — 允许的 table
  • column_whitelist map[string][]string — 表级列白名单
  • row_limit int — 单次返回行数上限
  • timeout_ms int — 执行超时（毫秒）
  • write_review_required bool — 写操作是否需 Review（默认 true）

6.4 DatabaseContract：期望结构与只读比对

DatabaseContractEXPECTED SCHEMA
  • project_id / version / source_ref — 项目、契约版本与仓库来源
  • tables / columns — 期望表、字段名、数据类型、nullable、default
  • primary_key / indexes — 主键、唯一及普通索引期望定义
  • constraints — foreign key、unique、check 等约束期望定义
  • scan_snapshot — metadata/catalog API 只读扫描的结构摘要，不抓取业务行

契约只描述“应当是什么”，不直接改变数据库。只读扫描与契约逐项比对，输出缺失、多余、类型不兼容、索引 / 约束差异及风险级别，形成可审计的 Schema Drift 报告。

6.5 MigrationPackage：仓库产物的受控交付

MigrationPackageIMMUTABLE PACKAGE
  • 来源 repository_tool | sql_files | orm_migration — 仓库工具、版本控制 SQL 或 ORM migration
  • repo_ref / commit_sha / checksum — 固定仓库路径、提交与校验和，审批后不可变
  • contract_from / contract_to — 迁移前后 DatabaseContract
  • plan / rollback_ref — 预演计划、顺序、超时、回滚或前滚策略
  • approvals / executions — 分环境审批、执行身份、结果与不可变证据
首期禁止：不提供任意生产 SQL 在线编辑执行，不把粘贴 SQL 当作 MigrationPackage。生产只能选择已校验、固定 checksum、经 Review 的仓库包，并优先在 test / development 预演；参数或内容变化后旧批准失效。

6.6 三类验证与漂移闭环

验证输入行为与输出
连接测试DatabaseBinding只读握手、身份、版本、权限探测；输出脱敏诊断
契约测试DatabaseContract + 只读扫描比较表 / 字段 / 类型 / PK / index / constraint，禁止自动修表
迁移验证MigrationPackage + 环境校验 checksum、顺序、预演与审批；执行后重扫验证目标契约
漂移检测最近快照 + 当前快照区分已登记迁移与带外变化，告警、阻断发布或发起 Review
CHAPTER 07

凭据管理

CredentialRef · SecretService

凭据管理是所有集成类型的共同安全底座。CredentialRef 只保存引用；SecretService 仅位于 Host 内部，Engine/Connector 通过经认证 Named Pipe 请求短时、单次 Secret Lease，禁止通用 Resolve。

7.1 CredentialRef 机制

CredentialRefENTITY
  • ref_id string — 引用 ID（稳定不变，凭据轮换不影响）
  • backend string — v1 固定为 dpapi_current_user；未来后端须经 ADR 扩展
  • origin_fingerprint string — 规范化协议、主机与端口的绑定摘要
  • version string — 凭据版本指针（可选）
  • scopes []string — 允许使用此引用的集成 ID 白名单
核心原则：凭据仅存引用，不存明文。CredentialRef 中不包含任何明文密钥、密码或 token，仅包含指向 SecretService 后端的定位信息与权限范围。

7.2 Host 内部 SecretService 接口

Go · secret_service.go
// 仅限 WebView2 Host 内部；不得暴露给 Renderer 或作为 Engine 公共接口
type SecretService interface {
    Put(ctx context.Context, meta SecretMeta, plaintext []byte) (CredentialRef, error)
    WithSecret(ctx context.Context, ref CredentialRef, fn func([]byte) error) error
    Delete(ctx context.Context, ref CredentialRef) error
}

7.3 Engine Secret Lease 契约

Go · with_secret.go
// Engine → Host，经认证 Named Pipe；不是 Renderer Bridge API
type SecretLeaseRequest struct {
    ProviderID, CredentialRef, NormalizedOrigin string

使用规则

  • 禁止通用解析：Engine/Connector 不得调用 Resolve 或取得可长期持有的 Secret 对象
  • 强制清零：Connector 只在出口调用栈短暂持有 []byte，设置认证头后立即覆盖
  • 禁止日志：任何日志、错误消息、trace span 中不得出现明文
  • 禁止序列化：明文不得被序列化到配置、缓存或持久化存储
  • 拒绝重放：lease 过期、二次消费、PID/SID 或 origin 换绑一律拒绝；崩溃时自动失效
CHAPTER 08

健康监控

HealthSample · Sliding Window

健康监控基于滑动窗口模型计算集成健康状态，不依赖单次调用结果。每次调用或探测产生一条 HealthSample，窗口内样本按权重聚合为最终状态。

8.1 HealthSample 实体

HealthSampleENTITY
  • integration_id string — 所属集成
  • timestamp timestamp — 采样时间
  • success bool — 是否成功
  • latency_ms int — 响应延迟
  • status_code int — HTTP 状态码或等价错误码
  • window string — 所属窗口标识

8.2 滑动窗口计算

计算规则

  • 窗口大小：最近 N 次采样或 T 时长内的采样
  • 成功率权重：窗口内成功比例为主要权重
  • 延迟权重：P95 延迟相对基线的偏离度为次要权重
  • 时间衰减：旧采样权重随时间衰减，新采样权重更高
反模式禁止：健康状态不得只依赖最后一次结果。单次成功不应将 unhealthy 直接跃迁为 healthy，单次失败也不应将 healthy 直接降为 unhealthy。状态跃迁需窗口内多数样本支撑。

8.3 健康状态说明

状态窗口条件自动调度行为
unknown采样不足窗口下限不参与自动调度，触发首次探测
healthy成功率 ≥ 99%，P95 延迟 ≤ 基线正常调度
degraded成功率 90%–99% 或 P95 延迟 > 基线降频调度，告警
unhealthy成功率 < 90% 或连续失败超阈值停止自动调度，需人工介入
paused人工或策略主动暂停不参与任何调度
CHAPTER 09

统一清单、测试与调用日志

Inventory · Test · CallLog

所有 Integration 无论 adapter 类型均进入同一清单和详情编辑体验，并使用统一的启停、测试、健康与审计动作。所有实际调用产生 CallLog；日志严格脱敏：不记录凭据，origin 信息脱敏处理。

9.1 统一清单与详情编辑

界面必备能力约束
统一清单按项目、环境、adapter、方向 / 角色、状态、健康度筛选；展示最近测试与调用数据库、API、MCP、FAST、SAP RFC、OData 等不拆成孤立入口
详情编辑基本信息、环境配置、认证引用、字段映射、JSON/YAML/示例、测试与日志标签页adapter schema 驱动；秘密字段不回显
启用 / 停用草稿校验后启用；停用阻止新调度并保留历史生产启用需权限与 Review；配置变化触发重新测试
测试连接测试、接口样例调用、契约测试；展示脱敏请求 / 响应摘要默认使用当前环境最小权限，不将测试等同生产放行

9.2 CallLog 实体

CallLogENTITY
  • integration_id string — 调用的集成 ID
  • connector_key string — Registry adapter 标识（支持 api / mcp / fast / custom / sap_rfc / odata / database 等扩展）
  • operation string — 操作标识（API path / MCP tool / ETL job / OData entity set / SQL hash）
  • cred_ref_id string — 使用的凭据引用 ID（仅 ID，不含明文）
  • origin string — 调用来源（脱敏后）
  • started_at timestamp — 开始时间
  • finished_at timestamp — 结束时间
  • status success | error | timeout — 调用结果
  • status_code int — 状态码或错误码
  • request_size int — 请求体大小（字节）
  • response_size int — 响应体大小（字节）
  • error_redacted string — 脱敏后的错误摘要

9.3 记录规则

  • 脱敏 origin：调用来源信息脱敏后记录，移除可能包含敏感数据的查询参数与 header 值
  • 不记录 credential：日志中不得出现任何明文凭据、token、密码；仅记录 cred_ref_id
  • 错误脱敏：错误消息中的凭据、内部路径、堆栈详情需脱敏后存入 error_redacted
  • 不可变：CallLog 写入后不可修改，仅可追加补充注释
  • 保留期：按合规要求配置保留期，到期前不得删除
审计底线：记录脱敏 origin，不记录 credential。CallLog 是安全审计与合规追溯的不可变证据链，任何对凭据明文的记录行为均视为安全违规。
