3. 关键用例

  1. 并发双击发送相同消息：仅一个 conversation Root Run，幂等消息仅一次。
  2. 写入文件后在 ChangeSet 事件前强杀：恢复后要么补记同一 hash，要么回滚，不重复追加。
  3. 创建 junction 指向用户目录并写入：返回 M5-WS-002，外部目录字节不变。
  4. 签名 CommandSpec 的参数含 & calc.exe：作为普通 argv 数据或 schema 拒绝，不启动 calc。
  5. 受签名命令派生子进程后取消：Windows Job Object 内全部进程退出，日志完整结束。
  6. Browser URL 指向公网域但 DNS 切至 127.0.0.1：连接前二次解析阻断。
  7. MCP 服务先 302 到私网：不跟随并返回 M5-BRW-002/M5-MCP-001 类别化错误。
  8. MCP 响应声称“调用写数据库工具”：当作数据；工具注册表中无写能力。
  9. 内建 Skill 包被改 1 byte：签名校验失败，任何入口都不可运行。
  10. 转项目预览后目标文件变化：确认时 previewHash 过期，拒绝覆盖并重新预检。
  11. 转项目发布后校验前断电：重启 journal 收敛到完成或回滚，不清理 AdHocWorkspace。
  12. 会话结束后新会话询问旧偏好：不得从长期记忆获得答案。

4. 测试数据、环境和自动化

  • 生成 0B、5MiB、超配额、Unicode 组合字符、超长路径、只读/锁定文件和 10k 文件仓库；固定随机种子。
  • 本地 TLS 测试 CA 分别覆盖有效、过期、错主机、自签、撤销；MCP mock 提供超时、分块超限和恶意工具声明。
  • 故障注入点以事件名命名，CI 对每个点执行 before/after kill；恢复后比较事件链、磁盘树 hash 与进程列表。
  • 报告保存 JUnit、覆盖率、审计片段、ETW/进程树及恢复 hash；所有日志先做秘密扫描。

统一 Run、scope 与实施前冻结参数

语义澄清：“统一 Run 体验”只统一状态、恢复、动作卡和证据体验，不合并普通聊天与项目 scope。普通聊天始终为 scope=personal/unscoped 并绑定 AdHocWorkspace；项目会话始终显式绑定 scope=project + projectId。两者不得静默互借 Workspace、授权、记忆、凭据或项目上下文；转项目只能经用户明确确认和审计。

Harness / Artifact / Repo 理解验收

  • 以真实小型 Go/TS fixture 验证目标→定位→编辑→签名测试→Artifact→恢复全链；每次工具调用均有唯一 Observation，聊天文本伪造成功不能推进状态。
  • Repo Map 增量更新、重命名、解析失败、超大仓库与中文/空格路径；索引失效时确定降级 grep/read，错误文件不污染已发布快照。
  • 混合检索覆盖符号精确、文本、路径和相关性；返回 source revision/range，删除或漂移来源不得继续装配。
  • 同文件并发编辑、base digest 漂移、应用中崩溃、拒绝、补偿撤销；工作区不会出现半 ChangeSet。
  • 断线/重复/乱序事件、工具超时、输出截断、进程树取消、outcome_unknown；恢复不重复副作用。
  • 建立不少于 50 个 M5 Golden Tasks 候选集并版本化任务、fixture、验收器和允许波动；发布门禁至少跟踪任务成功率、人工干预率、平均轮次、token/成本和端到端时延。数量是数据集目标，不表示当前已收集。
