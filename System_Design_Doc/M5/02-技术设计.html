Durable Root Run 技术设计

复用 M4 执行核，不复制调度器；以单 Root Run、能力化 Bridge 和持久事件流统一对话与本地执行。

概览详细状态面板
M5 权威边界：本阶段只交付 durable 普通聊天 Root Run、AdHocWorkspace、文件/Git/Artifact、产品签名命令、受限独立 Browser、HTTPS 远程 HTTP MCP 只读子集、产品签名内建 Skill、后台任务和用户显式转项目。这不等于 M6：不包含第三方生态、stdio、完整 MCP 或强隔离 Worker。

1. 架构决策与复用边界

复用 M4

  • 复用状态机、事件日志、幂等键、租约/心跳、取消令牌、日志流、恢复扫描器与 Artifact 存储。
  • M5 增加 ChatRootRunAdapter、AdHocWorkspaceProvider、CapabilityBridge、ChangeSetService。
  • 执行核只接收结构化动作，不解析自然语言，不直接拥有 OS 权限。

硬约束

  • 一个对话只对应一个 Root Run；无 Child、fanout 或九阶段。
  • CommandSpec 和 Skill 必须产品签名；拒绝 shell 字符串。
  • Browser 独立低权限；HTTP MCP 仅 HTTPS 只读最小子集。
  • 业务 DB 不写；运行元数据写 M4 本地 durable store 不属于业务 DB 写能力。
UI → ChatRootRunAdapter → M4 Execution Core → CapabilityBridge
                         ↘ Event Store      ├─ File/Git/Artifact
                                            ├─ Signed CommandSpec/Skill
                                            ├─ Low-privilege Browser
                                            └─ HTTPS Read-only MCP

3. Bridge 合约

type BridgeRequest = {
  runId: string; actionId: string; capability: Capability;
  resource: string; args: unknown; idempotencyKey: string;
};
type MethodResult = { eventSeq: number; changeSetId?: string; artifactIds?: string[] };
// Bridge 顺序：验签/能力 → schema → canonicalize → policy → execute → hash → event
  • FileBridge：句柄相对根打开，拒绝 reparse point/symlink 穿越、ADS、UNC、设备名和大小超限；临时文件+原子替换。
  • GitBridge：调用固定 libgit/已签名子命令模板，禁 hooks、外部 diff/credential helper；远端写不在 M5。
  • CommandBridge：签名链锚定产品证书，argv 逐项编码，环境变量 allowlist，Job Object 限制进程树。
  • BrowserBridge：AppContainer/低完整性进程、临时 profile、DNS/IP 双检查，禁 loopback/RFC1918/link-local/file。
  • McpBridge：TLS 1.2+、系统信任链、主机 allowlist、禁止重定向到未授权域；过滤声明，仅 GET/只读语义工具，响应限 4 MiB/30 s。

4. 关键流程

  1. 发消息：事务性 get-or-create RootRun → 追加 UserMessageAccepted → 启动/续租 → Agent 规划结构化动作。
  2. 本地变更：解析规范路径 → 快照基线 → Bridge 执行 → 计算补丁与 hash → 持久 ChangeSet → UI 收到序列事件。
  3. 后台任务：校验 CommandSpec 签名 → M4 创建任务记录 → Windows Job Object 启动 → 增量日志 → 完成事件；取消终止整棵进程树。
  4. 转项目：扫描源空间和目标 → 生成带 hash 的预览 → 用户确认 → 加目标锁 → staging copy/冲突处理 → 原子发布 → 校验 → 标记完成；源空间延迟清理。

5. 安全模型

信任边界

Agent 输出、网页、MCP 响应、仓库内容均视为不可信数据；不能改变系统策略或授予能力。产品签名清单是唯一可执行来源。

凭据与审计

凭据只通过系统凭据库句柄注入，不进入 argv、环境快照或日志。审计保存决策和摘要，正文单独加密并按保留期删除。

6. 故障恢复与一致性

故障恢复算法
事件已落盘、动作未执行扫描 PendingAction，以幂等键重试。
动作完成、结果事件未落盘读取结果标记/hash；匹配则补记，不重复写。
写文件中断丢弃同卷临时文件并由 baseSnapshot 回滚；不暴露半文件。
后台进程仍活校验 pidToken/Job handle 后重连日志；无法证明身份则标 Orphaned 并安全终止。
转项目崩溃依据 phase journal 继续 copy 或删除 staging；发布点仅一次原子切换。
事件损坏校验链断裂即隔离 Run，保留只读导出，不猜测续跑。

以上组件和迁移已实现；feature flag 按合同默认策略执行（Child/fan-out 由 Scope Seal 永久封禁）。

统一 Run、scope 与实施前冻结参数

语义澄清：“统一 Run 体验”只统一状态、恢复、动作卡和证据体验，不合并普通聊天与项目 scope。普通聊天始终为 scope=personal/unscoped 并绑定 AdHocWorkspace；项目会话始终显式绑定 scope=project + projectId。两者不得静默互借 Workspace、授权、记忆、凭据或项目上下文；转项目只能经用户明确确认和审计。M6 扩展/能力上下文的 ad_hoc scope 即映射自「绑定 AdHocWorkspace 的 personal/unscoped Run」，root_run.scope 本身只有 personal/unscoped 与 project 两值，映射权威定义见 M6/02「Scope、stdio 交付门禁与 M7 交接」。
参数当前设计默认冻结要求页面状态

7. 旧版 S5 合同边界（M5 冻结子集）

阶段边界：M5 只提供产品签名的内建 Skill 与 HTTPS 远程 HTTP MCP 只读子集；不接收第三方 Skill、不导入 OpenAPI、不创建 Integration 数据面，也不包含 FieldMapping、Credential 管理、健康历史、调用日志、ETL、OData 或 stdio。上述受治理扩展由 M6 承接。

内建 Skill Manifest 最小合同

schemaVersion、skillId、name、version、publisher、description、entrypoint、inputSchema、outputSchema、permissions、runtime、minHostVersion、artifactDigest、signature、license、sbomRef 均为必备字段；签名覆盖规范化 Manifest 与 artifactDigest。匹配/推荐只产生候选，不构成授权；执行仍须 CapabilityGrant、资源 scope 与用户/策略决策。

Remote HTTP MCP 只读合同

仅 HTTPS、TLS 1.2+、系统信任链、主机 allowlist、SSRF/DNS 重绑定复查；认证枚举仅 none | apiKeyHeader | bearerToken | oauth2ClientCredentials，敏感值只能由 SecretRef 解析。只允许 GET 或声明且经策略验证的只读工具；禁止重定向越界、写语义与凭据回显。M6 必须复用同一 Gateway 扩展，禁止另建旁路。

Legacy deferred

旧 S5 的 ETL/OData 未进入新版冻结路线，均为 legacy deferred / 非目标。未来兼容摘要仅保留：ETL 采用 at-least-once 投递，checkpoint 成功后推进单调水位，重放必须依赖 sourceKey+watermark/幂等键去重，失败不得越过未确认水位；OData 未来若恢复，仅考虑只读 metadata/query 子集、分页 continuation、字段投影与服务端过滤，禁止写入/batch action。该摘要不是排期或已纳入声明。

8. 右侧工作区面板技术设计（预览 / 编辑器 / CLI·终端）

与全局五面板蓝图的衔接：全局 03/06 文档冻结右侧工作区为「预览、浏览器、CLI·终端、文件管理、计划」五面板。M5 只承载其中可执行子集：预览、编辑器（文件管理面板的文件/代码视图）与 CLI·终端三个面板的技术实现；浏览器面板在 M5 仅为受限 Browser（见第 3 节 BrowserBridge 合同），计划面板复用 M4 执行核的计划投影，M5 不新建任何面板或第二套工作区模型。V1 Mockup「一个面板、多视图互斥切换」的交互基线保留：视图互斥切换，不形成常驻多栏重型 IDE。
面板通信通道安全约束会话管理

会话管理公共不变量

  • 所有面板会话都绑定 (runId, workspaceId)；一个对话只对应一个 Root Run，面板不新建 Run，也不产生 Child Run。
  • 面板的每个动作（渲染、编辑、命令）都产生进入同一 RunEvent 流的序列事件，(runId, seq) 单调唯一，可审计、可回放。
  • 恢复顺序与 M4 执行核一致：先重放事件日志与 PendingAction 扫描，再重建面板 UI 投影；UI 投影只是派生状态，不是事实源。
  • 面板能力受 CapabilityGrant 约束：默认拒绝、最小范围、按 run 过期；转项目前后面板沿用各自 scope，禁止跨 scope 静默复用会话。

与 V1 S6 工作区运行实体的关系

V1 S6 定义的 WorkspaceBinding（项目与本地受信目录绑定）、DevSession（任务/对话/工作区/计划/恢复点串联）、DevServerSession（受管本地预览服务）与逐文件 ChangeSet 交付语义属于 M7 项目开发工作区；M5 不实现它们，只以 AdHocWorkspace + RootRun 提供对等最小语义（临时根、唯一 Run、ChangeSet、可恢复日志）。EditorLink（外部编辑器关联）在 M5 仅作为用户偏好保存，不授予编辑器任何 Bridge 能力。V1 Mockup 的三条设计规则——「一个面板、多视图互斥切换」「月汐轻编辑、VS Code 深编辑」「所有执行可解释、可回退（命令、文件写入、联网均绑定任务、策略、checkpoint 与审计证据）」——原样继承为 M5 面板交互基线。

本节面板与通道均已实现；M4 Scope Seal 已按 ADR-018 能力级收口（2026-08-16），受控子代理执行仅存在于 M7 subagent.*。
