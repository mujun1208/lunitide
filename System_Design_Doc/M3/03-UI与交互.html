长会话仍然是普通对话体验

沿用现有 React 三栏项目工作台与星空主题；项目聊天和普通聊天在信息架构、路由、列表及数据 scope 上明确分离。

状态：交互实现已有；RC 外部无障碍、长会话性能与删除传播证据尚未完全绑定。

信息架构

表面React 路由不变量
普通聊天/chat/:sessionId不显示项目阶段、项目产物或项目附件；提供“移入项目”显式流程。
项目聊天/projects/:projectId/sessions/:sessionId左栏项目/会话，中栏对话，右栏上下文与附件；projectId 全链路固定。
上下文检查器右侧 panel / 窄屏全屏 route显示逻辑总量、当前窗口、装配来源、摘要版本与可追溯链接。
续接dialog → 新 session先预览 Handoff 覆盖范围、来源和待办，再创建；可返回源会话。

核心交互

  1. 会话采用双向虚拟列表；“加载更早消息”使用 sequence cursor，列表底部不出现“已达会话上限”误导。
  2. 上下文胶囊同时显示“逻辑 742K / 当前请求 27.4K / 32K 窗口”，避免把 1M 误解为单次模型窗口。
  3. 达到 70% 显示后台摘要草稿状态；85% 自动模式可激活；95% 阻止发送并提供“压缩并重算”，不丢失编辑框。
  4. 手动压缩对话框展示源范围、保留项、摘要 diff、claim 来源覆盖和旧 active 版本；“预览”与“设为活动版本”分离。
  5. Handoff 卡展示版本、source sequence、摘要 digest、附件状态、目标/决策/约束/未完成事项；导入后显示源会话链接。
  6. 删除确认列出消息、附件、摘要、索引、Handoff 的影响；提交墓碑后立即移出召回，后台状态仅为传播中/完成/失败且失败不恢复内容。

状态与组件合同

状态呈现操作
加载/分页锚点 skeleton，不跳动滚动位置取消、重试；重复结果按 id/sequence 去重。
压缩验证失败保留旧 active，显示失败码与来源范围重试生成、缩小范围、查看诊断。
预算仍超限发送禁用，解释窗口与预留压缩、切换更大窗口、续接新会话。
附件不可用不可读占位与原因，不展示缓存正文移除引用或重新授权。
墓碑传播失败红色“不可读 · 清理待恢复”仅重试清理/导出审计，不允许恢复正文。

可访问性与响应式

  • 使用现有 React button/dialog/list/feed 组件；消息流使用稳定可访问名称，新增消息用克制 live region，不逐 token 宣读。
  • 键盘可打开上下文、分页、摘要版本和来源；dialog 焦点陷阱，关闭后回到触发器；IME composition 时 Enter 不发送。
  • ≤960px 左栏为 drawer、右栏为全屏 route；320px、200% scaling、400% zoom 不隐藏删除、来源与续接。
  • 颜色不是唯一状态；进度提供文本和数值；reduced-motion 下停用星闪和滚动动画。
禁止：不得把普通聊天放在虚构项目下；不得让虚拟列表卸载导致草稿丢失；不得将“压缩”描述为删除原文。
