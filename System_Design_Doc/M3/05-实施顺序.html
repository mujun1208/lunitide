依赖与合并纪律

  1. S1 合并前冻结 schema 与 Bridge v1；S2 不得用分页上限替代容量设计。
  2. S2 冻结 tokenizer 后 S3 才可生成可比较摘要 token count；artifact 变化必须升版本。
  3. S3 的所有派生物必须先支持墓碑校验接口，S4 才接入传播，不允许事后补安全过滤。
  4. 每片 migration 都先在真实 legacy fixture 演练；任何 destructive down 必须有前置引用检查。
  5. 功能开关按数据库兼容 → Engine 双读 → Bridge → React → 停旧写顺序启用；回滚按逆序，墓碑不可回滚为可读。

每片交付物

固定交付：schema/migration checksum、Bridge JSON Schema、Go domain/store、React 状态与错误稿、contract/integration/security/e2e、性能样本、恢复演练、证据 manifest。评审者必须能从 RC manifest 定位到实现路径、测试运行与外部报告。

停止条件：tokenizer 未冻结、migration 无法安全重跑、摘要来源覆盖不足、删除后任一路径仍可读或 RC 证据 digest 不一致时，后续切片可以开发但 M3 不得退出。
