设置中心实施合同

权威衔接：设置实体、继承链与原子 Save/Apply/迁移框架以 M2 设置领域模型 为唯一权威；本节承接 V1 PRD 3.5.1「设置中心实施合同」中作用域层级、保存语义与权威值（authority）、覆盖顺序、迁移与默认值四项实施规则。V1 的 application/workspace 术语分别映射为 V2 的 global/personal；本节不复制 M2 合同，冲突时以 M2 与全局 Policy 为准。

每次 AgentRun 创建不可变 ResolvedConfigSnapshot，记录 registry/policy/profile/model/tool-set digest；运行中普通偏好变化不静默改写已执行步骤，高风险策略收紧则在下一动作前强制重验。

保存语义与权威值（authority）

  • 普通字段在 Renderer 内存形成 draft，先 settings.validate（无写入），再 settings.patch(expectedVersion, idempotencyKey, digest) 原子保存；禁止用 localStorage 保存业务设置。
  • 每项 effectiveValue 由 Engine 计算并返回 source、inherited、overridden、managed/locked、version、applyMode；Policy 来源、版本和理由由 Engine 返回，不接受 Renderer 伪造。外观允许可撤销即时预览，保存后才持久化。
  • applyMode 取值 live / renderer_reload / app_restart / command_only；语言与运行时项必须准确显示 pending 状态，不得虚称已完全生效。
  • merge_strategy 取值 replace / min / max / set-intersection / set-union：allowlist 取交集、denylist 取并集、预算上限取最小，安全约束只能更严格。
  • 危险操作分流：Key、删除、恢复、导出、更新和安全策略不进入通用 patch，继续使用专用安全对话框、Command RPC、Policy、影响摘要与执行前重验；凭据保存只返回 configured 状态，origin 变化触发重授权。
  • 断线导致结果不明时进入 outcome_unknown，UI 必须按 idempotencyKey 经 settings.change.status 对账，禁止直接重复保存或执行。
  • 客户端状态机：initial → loading → ready ↔ dirty → validating → saving → saved/applying；saving → conflict | error | outcome_unknown；applying → applied | partial | restart_required；任一可读态可转 refreshing | stale | offline | permission_denied。

迁移、默认值与完成门禁

  • 默认值随 setting_definition 版本化；default_value 变更只影响无本地 override 的 scope，不得回写已有覆盖。
  • sensitivity 取值 public / internal / sensitive / secret_ref；secret 明文与密文禁止进入 setting_value，只允许专用 SecretService 引用。
  • 迁移状态机 detected → preview → staging → validating → committing → completed | requires_reentry | failed | recovery_required；先备份/checksum 再 staging 回填、校验、原子切换，失败保持旧 schema 可读并记 migration journal（M2 合同）。
  • 设置错误码：SETTINGS_KEY_UNKNOWN、SETTINGS_SCOPE_NOT_ALLOWED、SETTINGS_VALIDATION_FAILED、SETTINGS_VERSION_CONFLICT、SETTINGS_POLICY_LOCKED、SETTINGS_APPLY_PARTIAL、SETTINGS_IMPORT_CONFLICT、SETTINGS_MIGRATION_REQUIRED、SETTINGS_STORAGE_FULL、SETTINGS_OUTCOME_UNKNOWN；全部使用统一脱敏 AppError 与 correlationId。
完成门禁：每个公开设置必须有稳定 key、类型/schema、默认值、允许 scope、敏感级别、存储位置、merge/继承策略、applyMode、Policy 约束、RPC、事件、错误码、迁移和 E2E；仅在原型出现菜单或静态控件不算实现完成。

安全、删除与恢复

  • Project scope 在 SQL、向量 filter、blob authorization 和 Bridge 四层强制；普通聊天使用独立 scope。
  • 附件先隔离读取，限制 MIME、大小、压缩炸弹、解析时限；外链不是 1M 可重建内容。
  • 墓碑与“不可读”状态同事务；outbox 至少一次传播并按 tombstone key 幂等，派生物失败时仍 fail-closed。
  • 压缩 checkpoint 记录 source digest、draft ref、验证游标；崩溃后从最近安全边界恢复，不替换 active。
  • SQLite 损坏或 migration checksum 异常时禁止写入，导出诊断与只读备份；不得自动重建并覆盖用户数据。
