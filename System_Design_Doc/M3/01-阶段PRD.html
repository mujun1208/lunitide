MILESTONE 03 / PRODUCT CONTRACT

会话持久化与百万 Token 逻辑上下文

冻结 Project / Session / Message 的持久化合同，让长会话在 32K、128K、200K 模型窗口间可重建、可压缩、可续接、可删除传播。

状态：实现已有；正式候选（RC）的外部退出证据尚未完全绑定。本文只定义候选合同，不把已有代码、演示或内部测试虚报为阶段退出。
01 / SCOPE

目标、非目标、依赖与退出

合同冻结内容
目标单会话累计至少 1,000,000 canonical tokens；消息以 cursor 分页且分页不是总量上限；摘要与 Handoff 均版本化并可追溯到叶级来源；附件纳入计量、授权、内容寻址与删除传播。
非目标不承诺单次向模型发送 1M；不在 M3 引入 Agent 工具执行、Child Run、MCP、Skill；不把摘要当原文替代品；不允许跨项目召回。
依赖M0 本机身份/安全存储、M1 Provider 能力声明与 tokenizer artifact、M2 普通聊天、Bridge 与 SQLite WAL；项目域只提供显式隔离标识；共享 blob store、审计与迁移框架可用。
退出固定 corpus 达到 1M；32K/128K/200K 窗口矩阵全通过；分页越过 200 条仍可遍历全量；压缩崩溃可恢复；摘要 claim 叶级来源覆盖率 100%；删除后所有读取立即 fail-closed；RC 外部证据完成签名绑定。

03 / FR

功能需求

  1. FR-M3-01 Project 是隔离边界；普通聊天使用独立 Personal/Unscoped 区域，不伪装成项目。
  2. FR-M3-02 Session 归属 Project 或普通聊天域；Message 以 session_id + sequence 唯一、append-only。
  3. FR-M3-03 MessagePart 支持 text、structured、tool-result-ref、attachment-ref，并保存 ordinal、digest、token count。
  4. FR-M3-04 canonical tokenizer 的 ID、版本、artifact SHA-256、NFC、换行和序列化规则必须冻结。
  5. FR-M3-05 逻辑上下文容量至少 1M；RPC 每页最多 200 条仅是传输预算。
  6. FR-M3-06 ContextBuilder 支持 32K/128K/200K，按 provider limit、输出预留、工具预留与安全余量重算。
  7. FR-M3-07 70% 预生成 draft、85% 可 CAS 激活、95% 强制压缩重算；仍超限则拒绝模型调用。
  8. FR-M3-08 Segment/Rolling Summary 不可变、版本化；事实、状态、决策、约束、任务、证据 claim 绑定叶级来源。
  9. FR-M3-09 Handoff 不可变、可验证、同项目导入幂等；不复制或删除源消息。
  10. FR-M3-10 附件内容寻址、MIME/大小受限、解析结果版本化；权限与删除状态在装配时复验。
  11. FR-M3-11 删除以墓碑驱动结构化记录、blob、向量、摘要、Handoff、缓存传播。
  12. FR-M3-12 每次 ContextBuild 保存 manifest、窗口、tokenizer、摘要版本和来源范围，支持复盘。
发布裁决：“实现已有”只说明代码路径存在；只有 migration、Bridge、1M corpus、窗口矩阵、恢复、删除传播和 RC 外部证据均绑定同一构建 digest 后，M3 才可标记退出。

预算、摘要与 Handoff 规则

  • requiredTokens=system+tool schema+当前输入+装配上下文+最大输出+tool continuation reserve；超过 effective window 必须拒绝，错误 CONTEXT_BUDGET_EXCEEDED。
  • <70% 正常；70–85% 预生成 draft；85–95% 自动模式可在 fidelity 验证后 CAS 激活；≥95% 强制压缩并重新预算。手动压缩必须 preview 后 commit。
  • 摘要固定覆盖 goal/state、decisions、constraints、open tasks、code refs、tool/evidence、risks/unknowns；每个事实/状态/决策/约束/任务/证据 claim 绑定叶级来源。
  • 摘要状态 draft→validating→validated→active，验证失败到 rejected；压缩失败保留上一 active，原始消息永不因压缩删除。
  • Handoff 创建时对闭区间一致性快照计算 digest；导入重验 scope、range、digest 与墓碑，重复导入幂等。默认拒绝跨项目，且不继承审批、Secret、临时 capability 或过期工具权限。

删除与失败恢复

删除事务提交墓碑后，源消息/附件及其摘要、Handoff、索引、缓存、ContextBuild manifest 立即不可读；物理清理异步重试但始终 fail-closed。备份恢复必须先重放墓碑再开放读取。错误至少包括 COMPACTION_GENERATION_FAILED、FIDELITY_REJECTED、BASE_VERSION_CONFLICT、SOURCE_DELETED、BUDGET_STILL_EXCEEDED。

验收矩阵

  • 固定 1M corpus 可累计、分页、索引和重建；每页≤200 只是传输限制。
  • 32K/128K/200K 窗口分别重算；关键 claim 与硬约束来源覆盖 100%，无静默截断。
  • 压缩中崩溃不替换 active；Handoff 可回到原文；删除传播和备份恢复后回活事件为 0。
  • 普通聊天与项目会话列表、搜索、Handoff 和权限无隐式串域。
