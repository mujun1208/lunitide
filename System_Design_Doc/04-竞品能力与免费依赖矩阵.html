竞品能力与免费依赖矩阵

本页用于能力研究和依赖准入，不构成法律意见。当前未附逐项许可证证据，因此所有外部依赖的许可证状态统一标记为待核验、不可引入，不得凭印象填写许可证。

硬门禁：“免费”“开源”“GitHub 可见”“竞品正在使用”都不等于允许引入。必须锁定具体组件、版本/commit、源码与二进制许可证、NOTICE、传递依赖、商标/服务条款和分发方式后，才可改变准入状态。

3. 核验与引入流程

提出能力槽位（不得先指定“喜欢的库”）
→ 至少两个候选 + 自研/平台能力选项
→ 锁定源码来源、精确版本/commit、digest、lockfile
→ 收集 LICENSE / NOTICE / COPYRIGHT / 传递依赖 / 二进制来源
→ 安全评审：维护活跃度、漏洞、更新通道、执行面、SBOM
→ 法务/授权评审：使用、修改、链接、分发、商标、云服务条款
→ ADR 接受 → 依赖清单与构建可复现 → 才可引入

准入字段

每条依赖记录必须具备：owner、用途、阶段、源码 URL、精确版本、SHA-256、直接许可证证据、传递许可证报告、NOTICE 义务、是否分发、是否联网、数据去向、漏洞响应 SLA、替代/退出计划、批准人和复核日期。

竞品研究边界：仅观察公开能力、工作流和用户价值，不复制代码、受保护素材、品牌、未公开接口或规避访问控制；竞品能力变化快，进入具体需求前必须以官方当期资料重新核验。

4. 外部 Artifact / Harness 蓝图融合与 Clean-room 边界

外部机制融合方式依赖/许可裁决
文本流与工具/产物流分离、统一 Artifact Card、Diff 审查转写为月汐自有 Event/Artifact/ChangeSet 合同与 UI；不复制示例代码和视觉通用机制可独立实现
Agent 循环、Repo Map、混合检索、上下文分层、Golden Tasks转写为 Go Engine 端口、状态机、评测集和验收指标通用机制可独立实现；tree-sitter/向量库等具体依赖待核验
MCP / JSON-RPC / Provider API 兼容优先 clean-room wire 兼容与契约 corpus；M5 仅 HTTPS 只读子集协议、SDK、Server、服务条款分别核验；协议兼容不授权 SDK
OpenHands、Cline、Goose、Agent SDK 等仅作为候选能力研究，不预设 fork 或 vendor二手“开源/Apache/MIT”描述不是证据；锁定仓库/版本/LICENSE/NOTICE 前不可引入
Codex、Claude Code、TRAE Work 等专有产品只记录公开可观察输入、输出、状态和用户价值，形成中立行为合同不得复制源码、提示词、规则文件、UI、品牌、素材或私有接口

Clean-room 记录

  1. 观察方仅记录公开行为、官方公开规范版本和证据日期，不记录反编译、私有端点或泄露材料。
  2. 规格方转写为月汐自有术语、RPC、状态机、风险与验收，不复用专有表达。
  3. 实现方只依据已接受规格与已核验开放标准开发；若引入库，重新走依赖准入。
  4. 兼容由自建 corpus 与黑盒契约测试证明；不得用“能连接”替代安全、许可和恢复验收。
当前证据：两份外部蓝图正文及其示例代码均未附可授权复制的完整许可证链；其中本地 Mermaid bundle 也缺顶层完整 LICENSE/NOTICE 材料。因此本次只融合机制，不复制外部代码或打包其依赖。
当前结论：矩阵中的外部依赖许可证均未在本页核实，因此不可引入。
