# M9 威胁模型 4/6：市场签名、供应链与许可审查

> 阻断期产物（T-9.0.2）。概念威胁模型，不是生产合同；不含 DDL/API 决策。
> 范围：FR-07 共享能力市场（发布、签名、审核、安装、撤回、隔离；复用 M6 Registry/SkillInstall）。
> 映射用例：T-10（篡改包体/manifest）、T-11（市场撤回传播）、T-12（许可未审不得标通过）。

## 1. 资产
- CapabilityPackage（org_id、manifest、signature、permissions、license_evidence）
- 签名根与签名链（D-6 未决，此处仅威胁面）
- Registry 注册条目、Broker 路由表、Runner 本地缓存
- 安装钉住的版本引用与依赖闭包

## 2. 威胁主体
- 恶意发布者（注入后门/过度权限清单）
- 中间人篡改包体或 manifest（传输/镜像/缓存投毒）
- 被攻陷的审核通道（审核结论与实际包体脱钩）
- 许可未审即宣称兼容的发布者（法律风险面）

## 3. 攻击面（STRIDE）
| # | 攻击场景 | 类别 | 影响 |
|---|---|---|---|
| S1 | 包体与 manifest 签名后内容寻址不符（篡改任一） | Tampering | 恶意代码入场 |
| S2 | 签名根轮换窗口内旧根签发新包（或根私钥泄漏） | Spoofing | 假签名包 |
| S3 | 权限清单声明小于实际行为（安装后越权） | Elevation | 数据外泄 |
| S4 | 撤回未传播至 Broker/Runner 缓存，旧包继续派发 | Tampering | 已知恶意分发 |
| S5 | 审核结论绑定旧 digest，包体更新后结论沿用 | Tampering | 审核失效 |
| S6 | 法务未审却展示"许可通过"（或工程文档替代法律意见） | Repudiation | 合规违约 |
| S7 | 安装不钉版本：撤回后已装实例被静默升级 | Tampering | 供应链劫持 |
| S8 | 签名验证失败被降级为告警继续安装 | Elevation | 验签形同虚设 |

## 4. 缓解措施
1. 内容寻址（sha256）+ 全量验签：包体、manifest、审核结论、权限清单各自独立 digest 且互相绑定（S1/S5）。
2. 验签失败即隔离（M9-015/016），绝不降级安装（S8/T-10）。
3. 签名根轮换方案属 D-6 批准条件；根清单版本化，旧根只验证历史不复签新包（S2）。
4. 安装钉住版本；升级视同新安装重走验签+审核+审批（S7）。
5. 撤回向 Registry、Broker、Runner 缓存传播 tombstone；UI 隐藏安装入口并显示撤回原因编号（M9-017，S4/T-11）。
6. 许可字段只记录正式审查结果；未完成审查 → LICENSE_REVIEW_REQUIRED（M9-018），工程文档不作法律推断（S6/T-12）。
7. 市场生命周期复用 M6 Registry/SkillInstall，禁建第二套（唯一内核约束）。

## 5. 可验证断言（解封后落入测试）
- T-10：篡改包体或 manifest → 验签失败、隔离、零安装（M9-015/016）。
- T-11：市场撤回 → 传播注册表、Broker、Runner 缓存（M9-017）。
- T-12：未完成法务审查 → 不得显示许可通过（M9-018）。
- 签名根轮换、Runner 离线缓存故障注入 → 旧包不再派发。
- 市场验签率 100%（成功验签/安装尝试，PRD 成功指标）。

## 6. 残余风险与移交
- 权限清单小于实际行为的检测依赖运行时观测（M5/M6 EffectJournal 对账）→ 解封后接入市场安装后遥测。
- 根私钥托管与轮换仪式属 D-6；未决前任何签名实现均为原型。
