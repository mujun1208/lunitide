## 4. 本轮验证规则

1. 先转化已确认反例为产品包内“正确行为”回归，再跑受影响包和界面测试。
2. 共享目录并行修改时，中途编译失败只记录为集成检查点，不把未落盘字段误判成已发布缺陷。
3. 全量 Go/前端、Bridge 生成、类型、lint/build 和扫描作为合并前门槛；失败逐项追因，相关修复后重跑。
4. 包内测试数、子测试数、测试文件数分开记录；跳过场景仍计入未验证矩阵。
5. 新迁移同步 embedded hash、schema 精确指纹与历史升级夹具；不修改已发布迁移的字节内容。

原始本轮日志位于 [实施证据目录](evidence/)。后续最终摘要会列出可核对的通过/失败数量与代码快照；进行中的日志不是最终成绩单。

## 6. 4.9 分的实证判定

评分公式保持初版：24 模块、每模块五个维度 /5、重点模块加权。`scorecard.csv` 保留整改前分数；本轮按已落地代码和专项证据做一次工程暂评，写在 `scorecard-current-provisional.csv`，加权 **3.5594，展示为3.6/5**。未深入整改的模块保留原分；移除虚假完成不会提高功能分。暂评不是发布认证，最终仍须对同一支持矩阵重新评估：

- 功能：正常路径与异常路径都闭环；界面状态对应持久事实。
- 数据：重复请求、冲突、中断、重开、回滚不丢失已确认内容；外部效果不确定时不自动重试副作用。
- 权限：批准对象/载荷/版本一致；停用、撤权、越范围的请求拒绝；真实副作用前再次校验。
- 恢复：崩溃、断网、超时、设备移除、磁盘异常有可见恢复；不把永不报错作为虚假承诺。
- 可维护与验证：职责边界清楚、复用统一契约、关键回归进入 CI，日志定位到具体操作且不泄露凭据。

**当前不能给产品发布级 4.9 分。** 已实现部分解决了确定缺陷，但上述产品闭环与真实环境门槛尚有未完成项。下一次复评分必须引用最终集成结果及实际验收证据。

技术依据：Mermaid 的 `securityLevel`、`maxTextSize`、`maxEdges` 使用[官方配置契约](https://mermaid.js.org/config/schema-docs/config.html)。本轮实际锁定版本与漏洞扫描以 `npm-audit-after.json` 和锁文件为准。
