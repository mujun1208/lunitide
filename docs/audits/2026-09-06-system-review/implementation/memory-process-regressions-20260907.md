# 记忆串入、反复确认与对话过程回看修复（2026-09-07）

## 根因与实际修复

1. 旧 `maybeAutoNominateTurn` 把“用户：原话 + 要点：助手全文”作为全局偏好候选；专家 `writeExpertLastMemory` 又每轮将专家摘要提到同一全局候选池。这会把“@PPT专家 在吗 / 在的，给我主题”当成普通月伴的偏好。
   - 新自动采集只读取用户本轮原话，明确的稳定个人事实、输出偏好通过保守规则筛选。跳过临时任务、引用、专家提及、角色扮演、问题和敏感内容。不调用模型猜测偏好，不把助手回答当成用户事实。
   - 明确否定、相近但不同的偏好暂不做语义合并；相同文本（忽略句末句号等）跨会话/重启去重。人工拒绝后不重复生成同一候选，隐藏后不重建。
   - 专家摘要保留在原专家工作层；停止自动晋升全局偏好。旧数据库候选和证据不删除，注入时过滤旧专家来源及助手摘要。
2. `feedback.candidates` 返回全局最新候选，切换会话重置前端忽略状态，因而旧候选再次出现。
   - 新可选 `sessionId` 请求仅返回当前会话来源的人工待确认候选；自动/关闭模式返回空。无 sessionId 的记忆管理页面保留完整候选查看和人工管理。
   - `memory.settings` 增加 `captureMode=auto|manual|off`，默认自动。设置页使用三档选择，替代功能重叠的旧“自动提名”复选框；旧 AutoNominate 数据仍保留以兼容旧客户端。
   - 总开关关闭时不再注入已确认偏好。单独选择 off 只停止新用户偏好采集，历史仍可调用。
   - 迁移0142仅增加设置列；已关闭的总开关、观察期、旧候选和会话内容不变。CAS版本、身份迁移、导出均包含该设置；旧客户端省略 captureMode 不覆盖已保存选择。
3. `session:last` 是项目级跨表面对话摘要，之前每轮无条件注入，普通月伴初次进入也会收到上次专家工作。
   - 只在用户明确说“继续/接着/刚才/上次”等继续意图时注入此共享摘要。专家自己的工作桶仍按当前专家隔离。每周月伴归档、历史工具与原会话内容不改动。
4. 已隐藏/封存的事实仍有 confirmed 候选，旧注入直接读取候选绕过事实状态。
   - 自动偏好快照、检索、按ID读取均要求候选证据仍连接到 active 且未 hidden 的事实。事实管理隐藏/恢复立即影响新注入，候选证据保留可审计。
5. `runStream` 在发送 completed 前用 `context.Background()` 同步写三类记忆，回答文字输出后仍可能等待数据库/专家查询。
   - 消息、turn checkpoint和队列收据仍先持久化；随后发送终态并释放流，非关键记忆交给单worker。队列上限32、每项8秒、按入队顺序，关闭引擎时取消并join后再关闭数据库。队列不可用只记录日志，不撤销已保存回答。
6. 成功对话的流式思考未保存；旧失败回合把【思考过程】拼进消息正文，后续模型也会读到。
   - 新 `message.process` 读取独立过程元数据； `MessageDTO.hasProcess` 仅提示可展开，历史列表不附长文本。
   - `runStream.rawSend` 在同一发送锁内记录实际生成并发出的 thinking/equip/工具状态；每个callId保留最后状态，无完整参数、工具原始响应、产物内容或可执行审批token。历史审批只作状态记录，不能再次执行。
   - 过程在实际助手消息保存后、终态之前写入 `.message-process/<sessionId>/<messageId>.json`，与 `.turns` 同级，位于会话工作区之外，不改变工具冻结时的workspace digest。
   - 正文只保留真实回复或真实失败提示；成功空正文不制造助手消息。过程文本上限64KiB、工具64条，总JSON上限127KiB并标明截断，给桥接信封留余量；读取再次校验类型、数量、字符串长度和状态。
   - RPC验证会话/消息归属和消息仍存在；删除/回退后的消息不能凭遗留元数据文件读取。现有没有过程文件的历史消息返回空过程，不虚构历史。

## 明确边界

- 自动记忆是保守的确定性筛选，不宣称“理解所有偏好”或通过模型自评分达到4.9。无明确稳定语义时宁可不自动保存；用户仍可在管理中心人工管理。
- 同一句对多个会话并发提交时，候选创建受互斥保护；最终晋升在数据库事务内执行，同一候选只创建一份事实。语义相似但文字不同的偏好不强行合并。
- 非关键记忆任务若排满、超时或应用退出会跳过，原对话正文仍完整保留。后台不阻止终态，也不会自动重放外部工作。
- 思考帧分配序号并记入过程后，无论发送端是否报错都消费该chunk，后续flush不重复记入；新增一次thinking发送失败后恢复、最终记录仍只有一份的集成回归。
- 过程文件写入失败只记录日志，历史列表不会虚报hasProcess；不会让回答失败或自动重放动作。磁盘不可写时，消息与辅助过程文件没有跨存储原子保证；UI仅显示实际存在的记录。
- 最终全库复测发现旧 `TestChatStartWritesSessionLastBeforeCompleted` 仍要求记忆同步保存；已改为真实 channel 屏障：阻塞后台 worker 时完成终态先到，释放后等待实际 `session.last` 写入和队列完成，确认跨入口仍可继续工作记忆。生产保存代码未改变，不用 sleep 猜等待时间；定向 race 通过（1.236 s）。
- 过程文件只保存本版本实际收到的事件；被截断的尾部不会伪造。旧消息和纯成功空输出没有可恢复的过程文件。删除/回退后的残留元数据不可经RPC访问，完整应用数据清理仍由原数据目录管理负责。
- 本次未改动用户真实数据库、未删除旧数据、未运行用户真实自动化或发送外部消息。语音设备、真实会议、第三方API时延仍属于真机验收范围。


## 多子任务进度的历史兼容补充

- 过程记录仅对 `subagent.spawn/join` 的合法结构化 `tool_output` 接收真实子任务编号、状态、阶段；其它工具输出不增加落盘内容。
- 并发子任务可能先发progress再收到本轮tool_started；迟到的started不再覆盖已收到的任务身份与进度。已完成状态不被迟到的运行进度覆盖。
- 最终报告先解析完整JSON，再保留真实id/status以及已有purpose/profile，使用完整JSON编码器裁剪可选描述，总量不超过512 UTF-8字节，不直接截断JSON字符串。
- `subagent.join` 可能没有任何前置progress，因此在runStream的子任务结果分支，将展示摘要和模型上下文摘要分开；展示摘要在原始完整结果上规范化，再送事件流。给模型的原有摘要与预算策略保持原样。
- 若旧上游结果已经被裁坏且之前有合法progress，则保留最后完整进度。没有合法身份证据时不猜测或伪造子任务编号。
- 新回归覆盖spawn/join长报告与转义、迟到started、非法progress拒收、长报告已被截坏的终态恢复、没有progress的join最终事件、两个子任务关闭后重新读取仍分别指向原真实编号。

- 验证：过程/成功失败回合整组race通过39.961秒；补最终展示分支之后，子任务过程专项race通过39.607秒。测试仅使用临时数据库和本地构造事件，没有执行真实子任务或外部操作。
