## 已确认的代码问题与修复

| 现象 | 可验证原因 | 实现 |
| --- | --- | --- |
| webp 等图片破图 | `web/index.html` CSP 图片仅允许 self/data，输入及历史缩略图生成 blob URL；有的回退甚至是空 base64。 | 使用有大小限制的真实图片 data URL，不放宽 CSP。历史缓存丢失时从持久化 attachment.get 读取图片。错误图片显示可点击文件入口，不再展示永久破图。 |
| 文件/文件夹卡在读取或上传 | 浏览器文件读取、图片解码/压缩未覆盖超时与取消；原生 readChunk 不核对 nextOffset/eof，异常零进度可以无限循环；失败清理等待 abort，可让上传永远不返回。 | 读取/解码/压缩分别有界；原生分块严格核对尺寸、偏移、EOF；上传32KiB块遵守桥接大小限制；取消后停止下一块，迟到 begin 最佳努力清理，abort 只后台清理且最多等待2秒。 |
| 上传后不能继续或不知道状态 | 准备图片和原生读取期间没有进度/取消入口；失败附件无法重试。 | 从文件选择开始显示处理状态；可取消、失败可重试/移除；已保存附件保留并显示待发送；发送按钮、无正文发送及队列携带附件由主线配套修复并有交互回归。 |
| 后台提交/终止请求等待不退出 | CommitUpload/AbortUpload 等待同一正在提交任务时直接阻塞 channel，不响应 ctx。 | 等待者支持 context 取消；原提交的成功结果保留，取消不重复写入或删除已保存文件。 |
| @ 没有本轮内容 | 同事联系人请求控制整个候选状态，本地消息也被 loading/error 隐藏；附件先按项目取有限条后才筛会话，可能漏本会话附件；键盘按附件数量循环。 | 本地消息立即可选；远程故障不隐藏现有候选；attachment.list 可按 sessionId 在存储层先筛选，再核 projectId；键盘按当前候选数量操作。 |
| 产物不能作为真实上下文引用 | 原 @ 只有附件、消息和人，没有消息持久化产物；显式消息引用只注入正文，不含产物路径。 | 本会话持久化产物显示来源消息引用；后端从该会话产物回执取路径，作为不可信引用证据交给文件工具，不虚构流式消息ID，不自动执行产物。 |
| 明确选技能仍可能被遗漏 | 芯片已随正文发送，但技能目录限制12条，英文 name|ID 包装可能无匹配分，被其他推荐挤掉。 | 按本轮显式稳定skill ID优先排列，仍保留目录字节预算和 skill.invoke 执行授权。专家的当前引用优先旧挂载逻辑保留。 |
| 附件无法直接点开 | 历史消息只有 img/span，无点击处理。 | 上传完成文件名和已发送图片/文件可打开独立预览，支持图片与已解析文本、失败重试、关闭；缩略图缩小并用既有主题变量。 |
