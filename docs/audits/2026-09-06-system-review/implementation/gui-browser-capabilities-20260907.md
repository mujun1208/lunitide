## 路线判断

现有本机路线适合继续增强：文件/应用操作优先已有系统能力，应用界面优先 Windows UI Automation 与已观察的元素 ID，必要时使用带坐标和帧校验的鼠标键盘，再用截图核对；网页任务继续走本机 Playwright MCP 的结构化元素操作。无需为了这些基础操作另接收费桌面服务。库/工具本体开源或系统自带不等于模型调用、所访问第三方服务全部免费。

官方资料支持的是方法选择，不能替代本机验收：Playwright 推荐按角色/标签等可访问属性定位，并在使用时定位最新元素；OpenClaw 强调真实快照 ref、明确目标与浏览器 profile；Hermes 官方同时提供本机浏览器/CDP 和收费云端模式，并非只能靠云服务。来源：[Playwright locators](https://playwright.dev/docs/locators)、[OpenClaw browser](https://docs.openclaw.ai/tools/browser)、[Hermes Browser Automation](https://hermes-agent.nousresearch.com/docs/user-guide/features/browser/)。

## 本轮已落实的三个改动

### 1. 浏览器操作按已安装服务的真实协议执行

- 原逻辑找到工具名包含 `browser` 的第一个 endpoint 就把它当 Playwright：即使只是 browser_metrics，或工具集不全，也会截断正确浏览器的路由。现在按实际操作匹配工具，在尚未选择浏览器时优先完整工具集；已有目标后，点击/输入不静默换另一浏览器。
- 原 click/type/select 一律传 `selector`；经典 Playwright 版本使用 `ref`，当前官方版本使用 `target`。现在读取已准入工具 schema，在 target/ref/selector 中选实际声明的字段，去除未声明参数并检查必填项。保留旧服务兼容，不强迫升级或重装。
- 原 `wait` 把毫秒值放进 MCP 的秒参数，1500ms 变成 1500s；现在正确转换为 1.5 秒。
- 原输入文本 `TrimSpace` 导致首尾空白和换行改变；现在原样传递内容。
- MCP `isError:true`、空对象或 null 不再作为浏览器成功回执；错误保留给上层反馈，不能用追加快照掩盖失败。

协议来源：[Microsoft Playwright MCP 官方仓库工具说明](https://github.com/microsoft/playwright-mcp)。其当前说明中 target 接受快照元素引用或唯一选择器，browser_wait_for.time 单位为秒；运行时以实际安装服务返回的 schema 为准。

### 2. 同一浏览器动作和快照保持连贯，等待可取消

- 操作后快照固定读取同一 endpoint；多个 MCP 安装并存时，不混用另一服务的页面树。
- 移除引用操作之前隐式再取一次快照：模型拿到的 ref 可能因此失效，但原逻辑仍用旧 ref 执行。成功操作后继续返回新快照，保持原有下一步观察能力。
- 首次准备浏览器的等待响应 context 取消；已取消调用不会再进入 MCP。原有 navigate 的首次准备入口保留，click/type 不触发自动安装。
- 保留原有父轮次执行权限、MCP 准入、鉴权、熔断和网页敏感操作边界，没有放宽它们。

### 3. 元素点击保留按钮、次数、修饰键及实际目标

- 原 computer.act 命名/ID 点击统一进入 UIA Invoke，忽略右键、双击、Ctrl/Shift。因此“打开右键菜单”“双击打开”“多选”可能变成普通点击。
- 现在普通名称单击保留 UIA/Win32 优先路径；右键/多次点击/修饰键使用已解析元素坐标及命中检查，真实发送指定按钮/次数。明确 ID 也保留该节点位置，不再按同名文字调用第一个节点。
- 命中检查放在动作前，避免成功点击关闭/替换原控件后，反而被判成点错并诱导重复执行。动作后截图核对仍保留。
- 元素解析得到的是桌面原生坐标，现在按虚拟桌面原点和边界判断，允许左侧副屏的负坐标及合法的 x=0/y=0。
- 按键组合遇到失败仍反向释放，避免 Ctrl/Shift 残留。

## 用户本机验收步骤

以下使用新建测试内容。每项都检查实际结果，不仅看助手说“已完成”。失败时保留操作、错误码和页面/窗口状态用于定位。

1. 新建一个临时测试文件夹，放两个测试文本文件。要求助手按名称找到目标，右击打开其菜单；关闭菜单后双击该文件。应出现菜单及正确文件窗口，不应两次都只是普通选中。
2. 在该测试文件夹要求 Ctrl 选择两个文件，随后普通点击空白处。确认多选有效，后续鼠标/键盘不处于 Ctrl 持续按下状态。
3. 将测试窗口移动到左侧副屏，重新观察后点击控件、输入测试文本。显示缩放或屏幕连接改变后应重新观察，不能沿用过期坐标。
4. 在新建记事本输入 `身份证号码：2100040404301`，核对数字、光标位置和保存文件。此数字仅作用户给出的测试字符串，不作证件格式真实性判断。
5. MCP 页面确认所用浏览器服务已连接，在一个无需真实账号的测试网页上导航、点击、输入含前后空格及换行的测试文字、选择下拉选项、滚动；每步应看到对应页面结果。不得用真实下单或付款按钮作测试。
6. 请求浏览器等待约 1.5 秒再读页面，应接近秒级而非长时间卡住。浏览器首次准备期间取消任务，确认不会取消后才继续自动点击或输入。
7. 多个浏览器 MCP 同时存在时先导航再点击，确认两次操作在同一个浏览器。停用当前服务后再点击，应给出连接/准备失败，不能悄悄操作另一浏览器里的账号页面。
8. 在测试页面连续两次根据刚返回的元素引用操作，确认第二次不会由于额外隐式快照更换引用而报错。测试页面实际改版使引用过期时，应明确重新观察。

本轮完成的是可隔离验证的代码改进；上述真实软件、显示器布局、Windows 权限和登录态验收完成前，不给出“任意软件 100% 成功”或“六类能力全部满分”的结论。

## 全量复核补记：SQLite 点击夹具

后端全量测试发现旧 `TestCcNamedClickByObserveIDInvokesAccessibilityName` 仍要求 ID 点击转成按名称调用，而且隔离 host 没有实现 `HitTest`。这与前述“ID 保留实际节点位置”规则冲突，不能通过放宽生产命中校验解决。Windows 生产 host 已实现 `HitTest`。

已将该测试替换为 `TestCcObservedIDClickUsesExactNodeWithVerifiedHit`，仅为此测试附加隔离命中检查 host：两个同名按钮中选择 B2，核对每次命中检查和唯一鼠标点击都指向 B2 原生中心 `(230,40)`，禁止调用按名称的 `InvokeUI`；另覆盖命中变为 Cancel 时在移动和点击之前失败关闭。没有修改生产点击逻辑，也没有给全部旧夹具隐式增加命中能力。

专项 `go test -race ./internal/storage/sqlite -run 'TestCcObservedIDClickUsesExactNodeWithVerifiedHit|TestCcNamedClickFallsBackToCenterWhenInvokeFails|TestCcOpenClawParityTools' -count=1` 通过（37.574 秒），差异空白检查通过。完整 SQLite 包由主线继续复核；此专项结果不代替全量结果。
