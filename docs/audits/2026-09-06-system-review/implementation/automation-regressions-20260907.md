# 自动化执行回归修复（2026-09-07）

范围：本轮截图 5。保留自动化原布局、黑白主题、任务模板、绑定/独立会话、定时/手动执行及原权限规则；未触发用户任务、未发送通知或消息给外部联系人、未改用户数据。

## 真实证据与根因

只读本机 `Local/Lunitide/automation/runs.jsonl`，仅提取状态、时间、错误及摘要长度：

| 字段 | 记录 |
| --- | --- |
| 手动执行启动 | 2026-09-07 08:55:24.4747586（上海时间） |
| 执行终止 | 2026-09-07 08:57:24.4806072（上海时间） |
| 错误 | `context deadline exceeded` |
| 实际耗时 | 120.006 秒 |
| 已收到摘要 | 199 字 |
| 最终状态 | failed，outcomeUnknown=true |

1. `AutomationHeadlessExecutor` 将 `chat.start` 的 120 秒启动请求期限，错误地套在**整次任务**上。调度器原本给任务 20 分钟，聊天内核也保留 10 分钟累计模型生成预算，但提前被外层 120 秒截断。该次失败先于 08:59 的 RPC 断连，是独立且可复现的缺陷。
2. 页面失败分支仅显示错误，完全隐藏已经收到的 199 字摘要；独立会话只存绑定会话 ID，缺少查看实际执行对话的入口。
3. 顶部“调度器运行中”是后台定时服务开启状态，并非这次任务仍执行；每 30 秒刷新也使终态反馈延迟。
4. 页面先等待默认模型/自动化会话初始化，才读取已有任务与历史；初始化请求缓慢时，列表也被无关请求拖住。

## 已落地修正

- 启动 envelope 仍为 120 秒；整个运行继承调度器生命周期与原 20 分钟上限，模型累计生成预算、各工具自身超时、退出取消均保留。没有无期限放开执行，也没有缩减回答或关闭深度思考来制造“更快”的表象。
- 运行回执保留摘要、终止时间、实际执行会话 ID；`automation.run.list` 在已有范围校验后返回可选执行会话 DTO，支持直接打开独立会话及产物，不受普通对话列表过滤或条数限制。
- 确定没有启动的校验失败标记为执行失败；已开始执行、断连或超时的副作用仍保守标记待核对。失败任务保持停用，不自动重复可能已经发生的操作。
- 顶部区分“定时调度已开启 · 当前无任务执行”和“正在执行 N 个任务”；历史明确“执行已停止 · 结果待核对”。超时/取消转为明确中文说明，同时保留原错误用于排查。
- 失败也展示已生成的内容；可点击“查看完整对话与产物”，不会因此再次启动任务。已有成功摘要保持原展示方式。
- 首次列表读取与创建任务所需的模型准备独立进行；有任务执行时约 3 秒刷新、空闲约 15 秒，前次轮询完成后再安排下一次，页面卸载和连接切换会丢弃迟到结果。
- 中心页及工作区自动化面板复用状态与结果呈现逻辑，保留各自原布局。

## 公共聊天链路独立复核补充

复核 root 的装备提示事件有序发送、客户端 guidance/equip 验证、Host 超时分类及能力包滚动修复后，发现流事件在启动回执之后发生部分写入失败时，仅返回错误、未立即关闭连接。消息流会记录该错误并继续执行；若连接随后恢复可写，后续帧可能接在损坏帧正文后面。已在 IPC 统一写出路径上，针对设置写期限或实际写帧失败立即关闭连接并返回原错，保留执行结果处理策略。

新增 `internal/ipc/partial_event_write_test.go`：真实 `net.Pipe` 完成认证及启动回执后，注入只写长度前缀和 8 字节正文的失败；验证读端立即获得截断 EOF，第二个事件不得写入。整个 `internal/ipc` 包 race 回归通过（1.788 秒）。其余只读复核未发现新的连接序号/响应排序错误。多专家展示标签超出客户端原限额时可能丢失装备提示，已提交 root 作展示边界修正，不改变真实装配能力。
