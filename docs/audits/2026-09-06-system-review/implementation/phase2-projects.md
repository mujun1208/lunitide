## S07 MRO 当前证据、组织隔离与原子业务写入

迁移 `0139_mro_scope_receipts.sql` 已登记 manifest、模板 schema、历史夹具。27 张既有私有 MRO 表增加组织归属；旧行保持个人空间，机尾和航材自然键改为组织内唯一。所属组织不可变，手册分册、工具借用、化工批次父子及使用、套件、工作包任务、部件寿命事件均有同组织父记录约束。新增请求回执、发布凭据及 MRO 操作审计表。

所有生产服务入口通过同一 context 携带 SQLite 事务，嵌套业务复用事务；错误、panic 和 commit 失败均 rollback。请求键按组织+方法隔离，保存规范化全载荷 SHA256、完整响应及审计；同键同载荷不再调用业务，同键不同载荷明确冲突。回执和业务记录不存在各自成功的窗口。

发布链路现为：工作包真实来源引用 → 当前组织机尾与排程、工时、到期/AOG、套件/航材、受控手册检查 → 当前证据摘要 → 套件/航材待办与发布凭据同事务提交。无排程窗口、零/缺少技能容量、过期/无效/重叠窗口、超过机尾到期日、未知本组织机尾、来源不存在/未就绪均拒绝。工作包保留实际任务和到期条目引用，不再只记录四个分类标签。重复发布同一证据返回原两条待办；来源变化后原成功请求重放也必须重新校验，不能重复生成待办或继续沿用旧成功。

受控手册核验包括 writer 事务外的真实文件读取与 SHA256，复用 doctext 的本地受限读取；同源分册每个路径只读一次。发布只读取当前间隔规则引用的受控手册，手册登记只读取本次传入的文档，无关或已替代资料不消耗发布的文件校验预算。事务内再核对同一文档 version/SHA、latest ready 与 KBSourceCurrentPredicate。磁盘变更但索引尚未同步、来源失效、新文档版本抢先写入，均不能使用旧证明发布。证明只在单次请求上下文中有效，并绑定 Store 和组织。不会在持有写事务时启动解析或做外部请求。

工具借出会复查当前状态，两个并发请求只有一个成功；借用账和工具状态同时提交。归还不能把隔离状态改成 ready。化工品父库存、子批次、用途记录整笔提交；拒绝新建父子环，历史环的追踪会终止并去重。套件载荷按完整快照替换，删除的旧物料不残留，载荷错误恢复旧快照。故障确认状态和 CHECK 到期项、工作包头和任务、利用率和所有受影响到期数据、容量/间隔替换及其他多步写入均复用同一事务。
