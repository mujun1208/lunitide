# 语音与会议转写回归整改（2026-09-07）

对应用户本轮图 1（火山会议段落反复出现）、图 6（月伴完整用户句变成尾字），以及追加的静音 1.2 秒提交、多轮不回复、首段朗读延迟、口头澄清和重复完成反馈。本次保留原录音、历史逐字稿、月伴会话和界面风格；按追加要求移除语音选择卡，澄清改为口头问答。已有错误历史不会被自动改写；新录音使用修正后的路径。

## 已确认的代码原因

1. 火山 SAUC 配置了 `result_type=full`。返回的是全文快照，旧会议适配器却用 `absorbHeldTranscript` 合并每次快照。一旦早先字词被改写，前缀匹配失败，整个旧段落会再次拼入；后面的字符串去重无法稳定补救。
2. `pickResultText` 只要看见任一历史分句 `definite=true`，就将整个结果判为结束，忽略当前最后分句仍在识别。缺少聚合 `text` 时还只拿第一句，遗漏后续分句。
3. 原公共桥接只转发 text/final，丢弃 start_time/end_time，无法区分历史修订与真正新说的相同句子；旧 text 最大 4096 字，长会议全量快照可能超过返回契约。
4. 火山结束路径优先使用 commit 的文本，即使只剩已完整显示句子的一个尾字也会覆盖整句。系统 Web Speech 同一 resultIndex 的最终短尾也存在类似覆盖风险。
5. 本机 sherpa 将同分句的非前缀修订追加到既有文本；而 Go 的 Latest 原来会在每次轮询反复返回同一 final，放大重复风险。结束精修的短结果还会再次进入拼接兜底。
6. 实际有声停止后，文字修订仍会触发额外稳定等待；火山当前分句未 final 还会再等 2.3 秒。系统识别的有声时钟原来混入了文字到达时间。长时间没有新文字时还会停止更新真实有声时间，可能把仍在说话误判为静音。
7. TTS 首段无标点时只按最后一个字到达时间计时；模型持续产字会把首段等待反复后延。系统识别通过静音提前提交 interim 后，没有退休该 resultIndex，迟到的 final 会再次进入下一轮。
8. 语音默认工具包含打字用的 `user.ask`，可打开无声的选择卡并留下审批等待；桌面任务结束判断没有处理已经验证的关闭结果，导致正确关闭后仍被要求继续执行。

## 修正后的路径

- 火山协议只使用最后非空分句的结束标志；没有聚合文字时组合全部分句。新 `voice.append.utterances` 是可选返回字段，包含 text/startMs/endMs/final，旧本机、旧 Engine 的 text/final 返回继续可用。
- 同一音频起始位置的文字替换修订，提交后用音频位置游标排除历史重放；更晚位置的相同文字作为新一句保留。旧分句改变字词、长度，不会再被追加到当前轮。最近 64 个分句组成返回窗口，避免每个音频帧都搬运整场历史。
- 火山 ASR 适配器统一输出当前轮文字；会议、月伴上层不再重复切除历史前缀，也不把全文修订当新增段落。有真实有声计时时，完整月伴句停顿 1.2 秒即提交；无能量样本时仍沿用 final/文字稳定兜底。
- 结束返回是当前假设的修订：短且确属已显示原句的一部分时保留完整原句，其余修订替换原假设，禁止拼成第二个段落。识别取消后返回的旧响应不能再提交对话。扬声器回声按现有回声判定丢弃，同时退休对应识别片段。
- 本机区分已结束分段和当前假设：当前分段修订替换，确实结束后才接下一段；保留原有跨端点完整句修订兼容。Go 轮询每个新识别结果只交付一次，仍保存最后文字供 Finish 兜底。
- 系统 Web Speech 继续使用 resultIndex/consumedResultCount 管理结果；同一 resultIndex 的短尾 final 不再覆盖完整 interim，不把其他索引的文字错误拼入。
- 会议行缓冲接收已经归一的轮次，不再按文字内容删去用户真正重复说的话；实时展示保留实际保存的分段内容。
- 本机/火山的完整实时句在实际静音 1.2 秒后发起模型，不再叠加文字稳定、排空或离线精修等待；会议仍使用较长停顿和结束精修。退休当前识别归属先于异步操作；旧 append/尾字不能污染新句，取消期间打开的新识别会话会被关闭。
- 系统模式将真实声音计时与文字回包分开；静音提交的 interim 同时退休结果索引，晚到 final 不会再次开一轮。所有模式每轮重新建立有声时钟，不复用上一轮静音时长。
- 首段朗读按首批文字等待最多 350ms 后尝试形成可朗读块，持续新字不重置这次等待；标点完整的句子仍立即交给 TTS。后续文字保持现有连续音频队列，已经读过的片段不重读。
- 语音不再声明 `user.ask`。即使模型仍返回这个工具，后端也只发出首个口头问题、正常结束当前轮，不生成审批、不提前执行并列工具；普通必要信息问句也不触发任务完成兜底。打字选择卡保持原逻辑。实时 talk 已复用同一语音身份/回答规则。
- 默认口头回答 1–3 句，详细回答按用户需求展开；工具进度不逐步朗读，成功与失败给真实结果。已验证的单一关闭任务正确结束；失败、画面未验证和包含后续动作的任务不能被误标完成。相同完成字幕重放八次的回归确认只朗读一次。

## 模式与验证边界

| 路径 | 本轮结论 | 未验证部分 |
| --- | --- | --- |
| 火山返回音频分句边界 | 以时间位置隔离历史、当前修订和下一轮；已通过协议与前端真实序列回归 | 用户真实 seed-asr 账号、现场声学环境、长时间真机录音未由自动测试代替 |
| 旧火山仅返回 text/final | 快照替换、完整句保护仍生效；保留旧版兼容隔离逻辑 | 无分句边界时，无法完全判别历史改写与用户真实重复；旧 fallback 的文本去重仍有歧义，不能宣称达到时间边界模式同等保证 |
| 本机 sherpa | 同分句修订不重复追加；轮询 final 不重放；精修短尾保留整句 | 原生模型识别率、不同说话速度和连续长段落仍需真机抽验；旧接口未携带段号，跨端点完整句兼容仍包含文字判断 |
| 系统 Web Speech | 基于结果索引修订，新增完整句防短尾覆盖；原多轮回归通过 | 微软在线识别服务及设备实际返回行为依赖用户机器和网络 |

1.2 秒指客户端在已获得完整实时字幕、实际有声输入停下后的提交时机（火山/本机检查间隔 60ms），不是承诺公网模型或 TTS 在这个时刻已返回。尚未识别出文字、句子明显未说完整、工具执行时间、CPU 忙碌和网络时延各自需要处理，不能伪装成已经回答。系统能量表在浏览器正常渲染帧中检查；休眠/后台调度时可能晚于预期。

为满足完整字幕停顿即答，本机实时对话此路径不再等待离线精修，采用当前完整实时句；会议和手动结束继续精修。迟到的精修结果不会改写已经开始执行的指令。这是延迟与最终精修的明确取舍，不能据此声称专有名词/数字的真机识别率已达满分。

没有删除、重录或自动纠正旧纪要；没有更换用户选择的模型。没有用文本样例通过来声称真实语音准确率满分。
