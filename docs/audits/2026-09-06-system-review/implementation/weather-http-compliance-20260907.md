## 实际接线

- `bootstrap` 为天气单独安装传输回调；初始地址必须是配置中的 MET HTTPS 预报接口。请求标识为 `Lunitide/<实际 buildinfo.Version> (weather; contact: <用户授权邮箱>)`。
- 通用网页搜索、页面读取和视频读取继续使用原回调，不携带天气邮箱。不新增任意请求头透传能力。
- `networkpolicy.FetchOptions` 仅增加受控 `UserAgent` 与 `IfModifiedSince`，限制长度、可打印 ASCII 和合法 HTTP 日期；CR/LF、NUL 等在解析地址和联网前拒绝，错误不回显头值。
- 自定义头只保留于初始同源重定向链。域名、端口或协议改变即清除，后续即使返回初始源也不恢复；每一跳仍执行原网络地址与 DNS 策略验证。
- `FetchResult` 增加 Last-Modified 原值。原有无参数 `Fetch`、测试假响应和 `SetWebFetcher` 调用方式保留；天气额外支持可选条件传输。

## 200、缓存与 304 的真实语义

1. 初次成功 200 保存完整预报、原 Last-Modified、服务 Expires 和实际取得时间。正常 Expires 到期前只读缓存，不提前请求；已缓存地点也不会被另一地点的慢请求挡住。
2. 到期后，仅在存在相同坐标缓存且原 Last-Modified 有效时发送 If-Modified-Since。不推算、伪造或重格式化日期。
3. 304 必须与本地对应缓存及本次已发送的条件头相匹配，否则明确失败，不能凭空生成天气。返回地址仍需通过原域名、路径与坐标核对。
4. 304 继续使用原预报，保留 `retrievedAt` 与上游 `updatedAt`；新的 `checkedAt` 表示成功再验证时间，`cached=true` 表示数据正文来自已有缓存。根据新 Expires 更新有效期，不能把核验时间说成新的预报发布时间。
5. 无效/未来 Last-Modified 不发回服务端；取消、坐标变化、异常超长 Expires 的 304 不延长缓存。服务故障不自动把过期数据包装为成功结果。

本轮仍保持最大 64 个天气地点缓存、12 秒天气调用预算、响应/采样数/输出 JSON 预算，以及“预报采样而非实测、今天可能只有剩余时段”的原说明。

## 边界

该改动关闭“没有联系身份”“没有条件请求”两个代码缺口，不增加 MET 的服务等级承诺，也不保证每个网络环境永远能连通。浏览器渲染、股票或票务供应商权限不属于本次天气传输改动。
