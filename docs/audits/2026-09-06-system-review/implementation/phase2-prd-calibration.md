## 不漂移的实施规则

全部修正仍属于原 40 个任务、24 个模块和 56 组验收场景。保留 Go Host/Engine、React/WebView2、SQLite 和既有执行器；追加迁移，不篡改已发布迁移。组织范围为当前本地桌面产品的可信绑定，共享本机设置/参考目录的范围在支持矩阵说明；没有扩张成新的多租户云平台。

当前摘要只保存当前结果的一份准确输入快照，旧结果被替换后不虚构不存在的摘要历史。知识库当前提供受控本地普通文件来源；MCP 的 HTTPS 适配器保留项目实际协议；项目开发/预发发布为已实现的本地文件目标。范围外能力在界面和文档中明确，不用假成功提高评分。

## 评分与验收如何复核

代码升级、自动化验证、文档和构建工具由实施方完成；真机、真实供应商/数据库、签名和安装矩阵、72h/14天业务观察由用户完成。此分工来自用户明确指令。尚未实现的代码、可自动化的故障回归不得记为“等待用户真机”。

工程交付评分按用户约定，在适用代码工作关闭、最终门禁通过且没有已知核心阻断后评定。系统实机得分保留待验，不能由测试数量或工程分数推导出来。主 PRD 第10节的真实体验、业务质量和观察指标继续保留，不预填任何未实测数值。

最终可复查材料包括需求到实现/测试的台账、支持矩阵、六组门禁回执、源码摘要、迁移与故障测试、构建候选身份、人工验收表和逐模块五维评分。任何一项门禁失败或源码在验证期间变化，均不能生成“已通过”的最终汇总。

## 最终校准与关闭

2026-09-06：同一最终源码的六组门禁全部通过，完整开发候选完成构建及独立校验。主 PRD 定稿为1.5，当前工程交付按用户约定评审为4.9/5，逐模块见最终评分表；真实环境指标不代填。最终交接复核发现 `user-acceptance.json` 仍写8小时观察，已与PRD统一为72小时混合负载、14天受控观察及至少3000次有效核心操作，避免缩小用户验收门槛。
