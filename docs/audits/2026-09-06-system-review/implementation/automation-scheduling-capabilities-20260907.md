## 已补齐的两项能力

### 1. 停止指定一次执行

- 新增 `automation.run.cancel`，必须携带当前任务 ID 和当前运行 ID，经现有任务所属范围校验后才取消。旧运行的按钮不会取消同一任务的新一次执行，也不会取消其他任务。
- 中心页与工作区任务卡、展开的执行历史提供“停止本次”；与原“停用”区分。重复点击有前端互斥；旧请求返回不会覆盖新运行的卡片状态；请求失败可再次尝试。
- 取消向统一聊天执行上下文传播；等待执行器退出后记录 `cancelled` 终态，保留已经生成的摘要、执行会话和产物，并标明可能已经发生的操作需要核对。
- **周期任务**取消当前这次后仍保持启用，按未来时刻继续；不会自动重放取消掉的这次。**一次性任务**仍消耗当前发生时刻并停用，避免重启后重放过去的时间点。
- 手动重试是新运行 ID，不是恢复旧运行；已经发生的外部操作不回滚。取消请求成功仅表示已发出请求，实际终态以执行回执为准。若底层外部组件暂未响应取消，界面继续显示运行，避免虚报已停止。
- 原失败、超时及异常恢复仍保守停用并保留待核对结果，不改变既有恢复规则。

### 2. 明确任务时区，保留旧实际时间

- 任务新增可选 IANA `timezone`。旧数据未填写时区继续按 UTC，未批量迁移或覆盖用户已有时间；旧客户端编辑省略字段时，后端保留已有时区。
- 新建任务和模板默认系统时区；编辑旧任务明确显示 UTC；可在界面选择系统时区、Asia/Shanghai、UTC，以及已有其他 IANA 时区。后端接受有效 IANA 名称；不接受 Windows 注册表式名称或不稳定的 `Local` 别名。
- 周期计划在指定时区计算，再以绝对时刻发布下一次运行；`at:` 继续保持 RFC3339 中的绝对时刻，不受时区字段二次偏移。
- 使用 Go 标准库内置 `time/tzdata`，Windows 成品不依赖用户安装 Go 或配置外部时区文件；没有新增服务、账号或依赖库。
- 遵循现有 cron 的真实分钟语义：春季夏令时中不存在的本地时刻跳过；秋季重复的本地时刻对应两个不同真实时刻，可以触发两次。Asia/Shanghai 当前无此切换。未加入“秋季只运行一次”的另一种产品规则。
- 同时修复原来把小时 `0` 当空值的两个位置：午夜 `00:15` 在改变频率后保持午夜，不会悄悄变成 `09:15`。启停与编辑不会重置任务时区。

## 用户验收指令与操作

1. 在“自动化 → 手动新建”，新任务的时区应显示电脑所在时区。在上海电脑选择每天 `08:00`，确认下一次运行显示为本地早上八点。旧任务仍标为 UTC；只编辑名称或停用再启用，确认计划时刻不改变。
2. 创建午夜 `00:15` 的安全测试任务，把“每天”改为“每周一”，时间应仍为 `00:15`。
3. 用不会操作外部账号的测试任务手动执行，例如“仅分析并整理一个详细的本地项目检查清单，不发送消息、不操作外部系统”。执行中点击“停止本次”；历史应结束为“已停止本次执行”，保留已有内容，可打开实际执行对话。该周期任务仍启用；需要未来都停止时另外点击“停用”。
4. 若同时有两个安全测试任务，只停止其中一个，另一个应正常运行。前一个结束后手动再次运行，旧记录不能停止新一次。
5. 黑白主题各检查中心页与工作区：时区选择和停止按钮使用已有组件与主题色，没有改原布局或增加固定色块。

## 明确未实现/未实测范围

本轮没有新增入站 webhook 事件服务、Windows 关机/休眠唤醒、数日续跑、模型无费用保证或无人值守语音定时播报。调度本身本地运行不新增费用，真实执行仍可能调用已配置的收费模型。Windows 通知、实际供应商延迟和真实任务的外部副作用仍需用户实机验收；没有用回归测试通过替代这些事实。
