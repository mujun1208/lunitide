# 第二阶段：系统与数据闭环（持续实施）

本阶段按用户最新分工执行：真机、现场服务与长期运行验收由用户负责；代码、自动化故障测试、文档及发布工具链由实施方继续完成。第一阶段的分数与证据属于历史基线，不据此宣称第二阶段完成，也不将待实现项改写成已完成。

## B04：显式本机数据库写入

- `datasource.query` 保持只读。新增 `datasource.write.prepare/commit/get/list`，设置页提供待写 SQL、目标连接预览及独立确认，操作历史可恢复。
- `0127` 持久保存请求键、请求摘要、目标凭据指纹、十分钟确认有效期及结果。只准一次本机数据/表/索引操作，拒绝远程或 host 覆盖、多语句、管理命令、程序体等。实际驱动仍验证有效连接目标和拨号地址。
- 执行前同一事务写 executing 意图及审计，执行后用独立上下文保存结果。丢 ACK 时同 ID 读取旧结果；未知结果不重放。`RecoverDatasourceWrites` 在生产启动接线，将上次未决意图标成 unknown。
- 禁用、准备与执行串行；执行前复核连接、凭据及确认摘要。运行中页面取消不会阻止已完成数据库操作的回执落盘。
- 定向 SQLite 测试覆盖十并发确认、准备键冲突、审计先于执行、丢回执、未知结果、重启、取消、意图写失败、停用和凭据轮换。Bridge 真实接线测试通过；界面三项确认/重试/历史恢复测试通过，原数据源界面四项回归通过。

## S05/B05：同事可靠送达

- `0132` 同一事务提交本机消息、不可变发送内容、每位收件人的 outbox 和永久请求键；仅收到目标身份的已落盘 ACK 才标 delivered。重启重新读取未确认队列；并发最多四个发送任务，失败退避，关闭取消连接并等待工作退出。
- 加密握手绑定预期 subject/public key，发送前再读取权限；避免地址被另一已配对同事占用时泄漏消息。双向 AES-GCM 使用不同的 nonce 计数范围。
- 接收端同消息 ID 重试校验主体/线程/种类/正文，幂等确认；文件在校验大小、序号和摘要并同步文件、提交消息后才 ACK。修复表情接收与中文长度单位不一致；空文件走完整收尾。
- 本机专家消息保留本机专家身份，向真实同事发送时使用本机用户的认证身份并明确专家来源；发送快照固定，专家改名不会改变同 ID 重放内容。本机虚拟专家不进入网络收件队列。
- 界面显示实际送达计数。传输重试复用同一请求键；手动重试保留同一未完成尝试；迟到发送结果不进入已切换的会话。历史按时间/消息ID游标向前读取，每页最多200条且总正文有512KiB预算；界面可查看更早消息并回到最新页。历史页暂停刷新，连接与会话切换递增generation，迟到分页/发送/轮询不覆盖新上下文。
- 已通过真实临时 SQLite 与本机回环网络测试：丢 ACK 后关闭数据库再打开、重复请求不重复消息、两位收件人的中文表情、错误目标身份拒绝。丢 ACK 代理还检查双向 nonce 不重用。

## S01：设置版本与生效状态

角色策略以完整六角色表和版本摘要做同事务CAS；读取不完整或存储不可用时拒绝写入。命令/钩子策略采用严格64KiB JSON、受控原子文件替换和desired/applied版本，失败明确可见。前端保存冲突保留草稿，支持读取最新版本。浏览器、电脑控制、记忆设置的持久版本和生效状态见各专项。

## S03：实际能力诊断

设置页新增系统诊断入口。后端对23个模块区分未配置、已注册、可检查、不可用及配置失败，检查真实数据库readiness、审计链连续性及已装配能力。检查总时限5秒、单项最多1.5秒，只允许一个在途诊断。返回关联标识和脱敏原因；供应商配置存在不等于在线调用成功。SQLite关闭、审计篡改和依赖缺失都有正式回归。

## S07：自动化执行和可靠任务账本

定时任务在全部依赖就绪及恢复后才启动。运行前必须保存意图，退出必须等待实际对话流终态，不能把启动ACK当成功。重复触发有在途互斥；取消、审批等待、模型失败、持久化失败分别返回真实结果。崩溃遗留running记录收敛到outcome_unknown并停用，人工核对后才可恢复，不自动重放。

任务创建按请求标识持久幂等；编辑按完整配置版本CAS，时钟回退仍推进版本；运行时间更新不使正常配置编辑误冲突。修改cron立即重算计划。run历史、任务和目标会话按可信组织过滤，隔离子会话成功保存后才开始工作。文件账本原子替换、容量有界，通知调用有并发和时间限制；Windows通知正确使用Unicode并等待子进程回收。

二次复核修复两个存储边界：任务 JSON 的读写共同限制为8MiB，覆盖100条合法8000字符任务的最大JSON转义体积；写入前检查预算，失败保留原文件。单次任务及结果不确定任务必须先持久停用，再提交终态回执；停用失败保留running意图并阻止该版本自动调度，重启恢复为unknown并停用。正式回归覆盖at单次、cron单次、周期任务未知结果、最大合法容量和超预算写入；scheduler全包race通过。

旧automation.dispatch保留预检/投影语义，明确executionStarted:false；拒绝状态和审计提交后再返回领域错误，同一请求重放同一结果，改变bundle/trigger/budget/actor会冲突。常驻automation.job路径负责真实执行。两处界面均保存未知ACK的原请求尝试，避免重试新建任务。

## C01/S08：排队补充的事务边界

复核新增发现：排队输入原来的容量/速率/重复检查在事务外，相同请求未绑定正文，消费后按时间戳重查也无法证明属于本次消费。现准入、完整payload去重、5条容量和每分钟10条限制、顺序号、审计在同一写事务；消费在事务中捕获实际变更行。消费审计失败原消息保持pending，重放不重复审计。所有旧execWithAudit入口补panic时的rollback，连接可继续使用。

上述原子消费仍不足以覆盖消费后丢ACK。后续0140已补持久交付批次、永久用户消息幂等、启动CAS、checkpoint先行和unknown显式恢复；生产入口统一走该链。详见[排队补充交付](phase2-queue.md)，不把仅有事务消费当作端到端完成。

## E08：知识库解析预算

真实Engine的Office/PDF/文本解析接独立子进程：32MiB本地文件输入、2百万字符、ZIP单part16MiB/总64MiB/2048项、PDF500页、10秒和512MiB Windows Job上限、最多2个解析进程。私有临时文件随子树退出清理；超过限制返回可查询失败，不发布截断后的成功索引。源文件必须为本地盘普通文件，网络共享/设备路径不在此导入支持范围。

知识投影不持有数据库写锁；发布重新检查版本，较晚解析不能覆盖先提交者。正式测试在第一解析阻塞时完成另一个数据库写入与索引提交，再验证旧解析CAS失败；长Markdown逐字符核对未丢失。解析子进程正常、错误、超限、取消后的槽位和文件清理已通过race。完整来源查新见知识库专项。
