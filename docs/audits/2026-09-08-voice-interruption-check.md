# 三条语音链路检查记录

检查时间：2026-09-08，更新测试版时间：15:45。

## 结论

截图中的句首缺失有系统侧原因，不能简单归因于用户说话方式或模型能力。本次修复了识别生命周期、打断提交和恢复监听问题。自动化回归通过，但尚未用用户真实麦克风完成三路线真人验收，不能宣称识别率或拾音距离达标。

## 三条路线的实际区别

| 产品路线 | 实际识别 | 打断方式 | 本次覆盖 |
| --- | --- | --- | --- |
| 云端 | 自动设置优先已安装的 sherpa；也可能使用系统 Web Speech | 按钮或 Tab | 本机分支的恢复采集、系统分支的识别器重复重建、共享暂停恢复 |
| 火山 | seed-asr；启用实时通话时有独立通话路径 | 支持语音打断，也支持按钮或 Tab | 打断半句不再提前发送；保留触发打断的假设和后续修订；停止后立即收音；暂停关闭通话并作废旧回调 |
| 本地 | sherpa，本次健康检查为 streaming-zipformer-zh-14m | 按钮或 Tab | 停止后立即收音；保持识别会话；暂停后可继续；旧回调不能提交 |

“云端”是产品路线，不代表听写一定走云端。顶部“听”的标识用于判断本轮实际识别器。此处没有把本地改为上传音频，也没有修改用户的模型选择。

## 已定位并修复

1. 语音打断被当作句子结束。原先打断回调拿到第一段临时文本就发送，后面的城市、动作或对象仍在识别中。现在只停止旧回复并展示临时文本，完整提交交给正常结束逻辑。
2. 触发打断的文本被丢弃。识别回调进入播音分支后无条件返回，即使打断已同步解除播音状态，也不保留这一段。现在重新检查状态并继续处理它。
3. 播音停止后仍屏蔽麦克风。80/450 毫秒的保护期直接丢弃新音频，容易只剩“的天气”。现在立即恢复音频采集，保护期只约束提交，回声文本过滤保留。
4. 系统 Web Speech 重复重建。短保护期切回常规保护期时，重复状态同步重新创建识别器，清空正在到达的文本。现在同一播音状态不重复重建。
5. 暂停缺少明确继续入口，旧识别回调可迟到。现在暂停显示“继续”，清理待发送内容、关闭当前识别/通话；新会话使用独立代次，旧连接和结果不能重新打开监听或提交到新轮次。
6. 新识别器复用了旧状态同步缓存。现在接管新识别器时重新同步状态，确保它真正进入当前的监听模式。

## 灵敏度与准确性边界

- 音频采集保留回声消除、自动增益，关闭浏览器降噪；没有本次盲目调低阈值或放大音量。
- 普通环境活动提示阈值为 0.03，嘈杂环境为 0.08。这不是本地/火山音频上传的过滤阈值：未静音时，低于阈值的音频也会进入识别器。
- 新增 0.005 峰值模拟帧测试，确认静音解除前后的低音量帧仍被传输。这只能证明代码没有过滤弱音频，不能证明真实轻声已经识别准确。
- 测试确认完整结果才提交、迟到结果不串轮；没有用模拟识别结果代替真实模型准确率测量。
- 当前本机装有轻量中文识别模型。没有在未经对比的情况下更换权重或声称其识别率已改善。
- 系统 Web Speech 在按钮打断后仍有自身启动时间；本次消除了多余重建，但不能承诺它零延迟。

## 真人联测

每条路线分别测试普通音量和轻声。记录顶部实际“听”的引擎、完整字幕、是否只发送一轮、最终答案和工具结果。

1. 正常说：“帮我打开汽水音乐，随机播放一首歌曲。”核对完整字幕后，再核对实际播放与简短结果是否一致。
2. 回答中打断，立即说：“查一下今天合肥的天气。”火山先测直接语音打断，再测按钮；另两条测按钮或 Tab。不能只识别成“的天气”。
3. 回答中点“停止”，立即给出不同任务，核对不会执行上一轮残留任务。
4. 聆听时点“暂停”，确认不提交新语音；点“继续”后给出完整问题，连续重复三轮。
5. 任务结果必须依据实际工具回执。程序测试不能替代音乐实际播放、编辑器可见内容或实时查询结果的验收。
