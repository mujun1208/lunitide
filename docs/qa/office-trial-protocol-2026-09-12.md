# Office 试验包脚本（2026-09-12）

对照规格：`docs/superpowers/specs/2026-09-12-office-trial-ready.md`  
对照计划：`docs/superpowers/plans/2026-09-12-office-trial-ready.md`

这是一份**可走完的试验包**，不是整份 HTML PRD 的产品验收。装机若仍显示 0.4.75，说明尚未用本工作区重新编译并重启，不能把旧包表现当成这次试验结论。

## 开始前

1. 用当前工作区编译并重启桌面端后再试。未重启时，下列界面改动不会出现。
2. 打开办公工作台，阅读页面上的试验范围说明。应看到：不声称设计师已检 36 变体、校准 85 分、PowerPoint/WPS 实机通过、竞品盲评或企业模板审批。
3. 准备一组真实数字（例如订单 1280 单）。不要让模型编节约率或「供应商已通过」。

## 主路径

### 1. 简报

1. 新建任务，看任务概要：空白时应为「未填写 / 页数未填写」，不应自动写成「管理层 / 经营汇报 / 12 页」。
2. 填写受众、用途、目标页数、可选密级（例如「内部」），保存概要。
3. 刷新或重新打开任务：已填内容还在；未填密级时文件里不应出现「机密」。

### 2. 生成四种格式

在对话中要求生成 PPTX、DOCX、XLSX、独立 PDF，并带上已核对的 factId 与数值。

通过条件：四种文件都能生成；已填受众/用途/密级出现在独立 PDF（或 Word 页眉）中；未填密级不虚构。

### 3. 检查与修改

1. 打开「检查」，看每条回执的状态和说明。
2. 对一处正文做局部修改，应生成新版本，历史版本仍在。
3. 打开「版本」。若质量不是「已通过」，「作为正式交付」应禁用，并写明原因（检查未过或硬阻断）。此时「接受为草稿」和「导出副本」仍可用。

### 4. 导出

1. 未通过检查的版本按草稿导出。
2. 成套导出时，未通过的文件应标明草稿。
3. 本机打开副本，核对自己填过的数字，不要核对准不存在的竞品得分。

## 这些结果不算本包失败

| 现象 | 原因 |
|---|---|
| 目标软件 / PowerPoint / WPS / LibreOffice 显示尚未验证 | 本机未做实机矩阵，诚实缺口 |
| 视觉模型、PDF/A 显示不支持 | 没有视觉模型或 PDF/A 验证器 |
| 规则视觉分写明未校准 | 不能当作 85 分认证 |
| 正式交付按钮禁用 | 检查未过或硬问题仍在；缺 LibreOffice 时目录/公式刷新会失败并说明原因 |
| 没有 Gamma / Plus AI / Beautiful.ai 得分 | 盲评表为空，禁止虚构 |
| 企业模板审批、在线协同不可用 | FR17 / FR18 本期不做 |
| 36 个模板变体未标设计师已检 | `designerReviewed` 仍为 0 |
