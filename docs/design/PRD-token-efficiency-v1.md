# 准确优先的 Token 效率模块 v1

日期：2026-09-07。范围：本轮产品整改追加项；使用原 Go Engine、上下文分层、模型适配器与 Bridge，不建立第二套对话系统。文章截图是方案参考，节省比例不是验收依据。

## 1. 产品目标与边界

在不削减任务语义的前提下，减少重复输入、无意义的结构空白和重复前缀计算。工作、开发和文件制作的完整性优先于费用；保留用户要求、授权边界、未完成事项、来源、版本、代码、数字和错误。保持用户选择的模型、专家、技能、工具能力和既有思考/语音模式。

每次模型请求经过同一准备层；没有可证明的冗余时原样通过。不能为了让“每次都有节省数”成立而删除必要输入。

三个指标必须分开：

1. **输入量减少**：实际少发送了哪些结构字符、重复来源；本地估算不是模型账单。
2. **缓存复用**：输入仍然发送，但供应商可能复用前缀计算、采用缓存价格；不能把缓存输入直接从实际 inputTokens 中扣掉。
3. **回答与交付质量**：约束是否满足、工具是否真的执行、文件是否有效、来源是否可追溯。输入更少不等于这些指标一定更好。

不承诺消除模型幻觉，也不使用文章中的乘法把不同前提下的节省率相乘。自动测试证明确定性处理没有丢值，不等价于真实模型在所有任务上表现相同。

## 2. 原有架构复核

现有 `contextapp` 已按系统规则、工作区/任务、检查点、固定事实、近期会话、当前用户和证据分层，保留最近完整轮次及工具配对；`compactionapp` 已存在带校验和检查点的历史压缩。技能目录按任务加载元信息，完整技能在调用时读取。Anthropic 适配器已经配置前缀缓存断点。

本次不重复建设上述系统。复核发现并修复的关联缺陷：预算不足曾静默切成最小系统提示，丢掉所选技能/专家；空历史回退可能丢掉首轮附件；长技能可能被通用工具摘要截断。它们优先于节省输入处理，不能以“省 Token”掩盖。

## 3. 独立分层与接入

| 层 | 文件/职责 | 保留的边界 |
|---|---|---|
| 纯转换 | `internal/tokenefficiency/json.go` | 仅 JSON 结构空白；不反序列化成浮点、不摘要、不删字段 |
| 请求准备 | `internal/llmadapter/request_efficiency.go` | 发送副本；稳定工具目录顺序；保留全部工具定义、消息顺序与调用配对 |
| 来源投影 | `internal/contextapp/evidence_efficiency.go` | 当前已限定会话的 envelope 内、相同来源通道、全字段一致的重复证据才合并 |
| 实际计量 | `internal/llmadapter/usage.go`、`internal/app/chat_generation_budget.go` | 读取供应商原始 usage；整轮聚合，流式累计值不重复累加 |
| 契约兼容 | `internal/bridge/protocol.go`、`web/src/bridge/client.ts` | 原三项用量字段不变，追加可选缓存字段；旧事件继续有效 |
| 全局回退 | `internal/config/token_efficiency.go` | 启动时统一读取 `LUNITIDE_TOKEN_EFFICIENCY`，所有模型/对话共用 |

### 3.1 无损 JSON 处理

使用 `json.Compact`，保留键顺序、重复键、数字字面量、前导零字符串、转义、字符串中的空格/换行/代码。不用通用 map 解码后再编码，避免大整数精度、原文字面量变化。

适用两个位置：

- 历史 assistant 工具调用的参数对象/数组，仅改变传给模型的副本；不会重算或改写原执行参数、审批或持久历史。
- 明确属于结构化输出合同的工具结果：`office.generate/inspect/patch/range.patch/deliver` 与 `weather.get`。必须有非空、可明确关联的调用 ID。

普通消息、原文文件读取、未知/MCP 工具正文不处理。JSON 损坏、未完结、标量或大于 1 MiB 时原样绕过，不切断。即使两个时刻的工具结果完全相同，也保留两次调用及其证据时间关系。

### 3.2 精确来源去重

只对附件摘录、交接资料、检索证据分别处理。要求非空来源 ID 和 provenance，并比较 Type、ID、Revision、Provenance、Authority、Content、TokenCount、Deleted、CoverageEndSequence 全部字段；同文不同文件、不同版本、不同会话、不同权限都保留。

删除/可读性检查先执行，避免通过去重隐藏已删除来源。任务状态、系统要求、检查点、固定事实、用户消息均不按文本相似度合并。保留的附件仍是带引号的不可信用户资料，不升为系统指令。

诊断 trace 记录 `exact_source_duplicate`、重复来源数和避免重复的源字节数，只记录元信息，不打印材料正文。这个数值不能解释为供应商计费节省。

### 3.3 前缀缓存

当前请求的全部工具定义按名称稳定排序，缺名/同名歧义时保留原顺序让既有校验处理，不删功能。保持系统消息先后顺序与正文；不为了缓存把动态任务指令移动到其他权限层。

OpenAI 前缀缓存要求匹配相同前缀，实际用量由 usage 中缓存字段报告；具体模型、阈值和保留策略以供应商为准。[OpenAI 官方说明](https://developers.openai.com/api/docs/guides/prompt-caching)

Anthropic 现有显式缓存断点继续使用；其 input、cache read、cache creation 分项含义不同，应计入真实总输入且分别记录，不能重复相加缓存创建的 TTL 子项。[Anthropic 官方说明](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)

同时补齐实际请求合同：系统文本数组带 `type:text`；同轮相邻工具结果放入下一条 user 的多个 tool_result，保留 call ID、正文、图片归属与轮次边界。[Messages 合同](https://platform.claude.com/docs/en/api/messages/create)、[并行工具结果合同](https://platform.claude.com/docs/en/agents-and-tools/tool-use/parallel-tool-use)

DeepSeek 的 `prompt_cache_hit_tokens` / `prompt_cache_miss_tokens` 用于观察缓存命中；本模块不强塞其他供应商专有的缓存请求参数。[DeepSeek 官方说明](https://api-docs.deepseek.com/guides/kv_cache/)

稳定目录会改变过去不稳定的工具排列，虽不删除能力，仍可能影响模型选择概率。因此验证任务行为，不承诺输出逐字相同。

### 3.4 实际计量

保留 `inputTokens`、`outputTokens`、`totalTokens` 原义，新增：

- `cachedInputTokens`：已报告的缓存读取数量。
- `cacheWriteInputTokens`：已报告的缓存创建数量。
- `cacheUsageReported`：整轮相关调用均有可信缓存元数据时才为 true。

支持 OpenAI 兼容接口、DeepSeek 字段以及 Anthropic 真实非流式/嵌套 message_start 流式格式。多次工具续跑、专家协作、总结调用按实际回执各计一次；重复累计 usage 不逐帧求和。供应商没报、字段非法或部分调用未知，不编造 0%/100% 命中率或金额。失败/取消时保留已取得的计量，无法取得的用量不能估成供应商实报。

## 4. 本轮不默认采用的文章方法

| 方法 | 决策及原因 |
|---|---|
| 大幅降低输出上限 | 不采用；完整代码/文件/工具参数可能被截断。原工作任务输出和整轮上限保留 |
| 自动换小模型 | 不作为节省默认策略；用户当前模型和任务准确性优先 |
| LLMLingua、删除低权重词 | 不启用；关键否定、数字、要求与证据可能丢失，需独立真实任务评估 |
| 相似问题直接复用旧答案 | 不启用；天气、票务、股票、代码状态和文件版本易过期，也不能把旧工具执行冒充本次完成 |
| 截短任意工具结果 | 不采用；长内容通过可继续读取的分页、来源摘要或独立受检预算传递，不能假装完整 |
| 批处理即时对话 | 不采用；语音与实时任务需要及时反馈，不能为折扣排到离线队列 |
| 删除历史省空间/输入 | 不采用；沿用可追溯检查点和历史检索，不清用户原始数据 |

## 5. 验证、回退与验收

默认启用确定性处理。进程启动配置 `LUNITIDE_TOKEN_EFFICIENCY=off` 可整体绕过新增请求处理和证据投影，用于同模型 A/B 或兼容回退；`0/false/no` 等同。无需迁移数据库或每个语音模式重新配置。本轮未修改用户运行进程的环境。

已覆盖：大整数、科学计数法、重复键、代码缩进、缺调用 ID、工具名称映射冲突、32 并发共享请求不变、来源权限/版本不合并、删除来源不绕过、OpenAI/Anthropic 两种请求模式确实接入、供应商用量和整轮聚合、原文本/附件保持。

合成结构化结果样本：6,228 → 3,804 字节；本地同一估算方法 1,557 → 951 tokens。值与结构等价测试通过。**这仅是一个含较多缩进的测试样本，不是产品总体节省率或真实云账单**。原本紧凑 JSON 不会获得这部分收益。

真实 A/B 验收用同模型/同工具/同任务与独立临时输出目录，记录本次用量、首字/总耗时、工具结果、文件可打开性、尾部要求与来源完整性；先比较质量，再比较费用。外部接口状态与模型随机性分别记录。含身份数字、代码生成、长技能尾部约束、图片/JSON 解读、实时天气、跨文件数字与取消续跑，均不能因节省而失败。验收清单见本轮总表 K01–K08。
