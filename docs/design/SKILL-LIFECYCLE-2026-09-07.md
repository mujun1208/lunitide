# 技能创建、试用与发布统一设计

更新：2026-09-07。只修改产品源码和隔离测试数据，不安装新版应用、不清空用户资料。用户已暂停新增社区技能安装；市场条目与已安装记录分开处理。

## 三种入口，共用生命周期

| 入口 | 实际处理 | 导入后的状态 |
|---|---|---|
| 上传技能包 | `.skill` / `.zip` 的 SKILL.md、scripts、references、assets 完整保存；继续兼容 JSON；逐块校验和幂等提交 | 草稿 |
| 通过对话创建 | skill.create / skill.manage 保存真实 prompt、triggers、files；保留创建会话关联，改进草稿不丢关联 | 草稿 |
| GitHub 导入 | HTTPS 官方源/明确仓库 + 完整固定提交，原有发现、检查、扫描、审批；资源先保存，再事务提交草稿 | 草稿 |

创建和导入不会因为一次对话成功就变成已发布。用户可在当前对话或从技能中心选择草稿试用；准备好后在技能中心执行“安装并正式发布”。原有停用、废弃、删除、版本冲突检查继续有效。静态结构校验不是质量评测，试用记录也不是自动认证。

## 文件与来源

技能的实际工作约定为数据库中的 manifest.prompt。文件面板同时显示 SKILL.md、manifest.json 及完整配套资源。原始包中的 SKILL.md 或 manifest.json 与产品工作约定不同时，另保留 upstream 下的原始文件，不静默覆盖不同内容。

本地包以完整内容摘要保存于产品数据目录的 skill-package-store；可查看副本位于 skill-packages/技能ID/版本摘要。包数据与用户会话临时文件分离。这里是实际文件目录，不是根据名称画出的假目录树；外部编辑副本不会偷偷改写数据库工作约定，检测到变动会明确报错。

目录按128条分页；文本默认16KiB、最多32KiB分页，UTF-8边界完整，续读绑定版本摘要。二进制资源保留原始字节，文件面板明确显示其类型。模型可通过 skill.view 按3.8KiB结果页完整读取文本资源，并获得已物化目录路径；脚本不会因被查看或导入而自动运行。

新创建记录的 originSessionId 由服务端写入，仅用于恢复聊天中的技能产物卡，不作为全局技能目录的权限依据。旧记录没有该关联时不按创建时间猜测来源会话。

## 对话试用

- chat.start 的 trialSkillIds 是本轮明确选择的草稿，最多8个且不重复；语音入口不携带该字段。
- skill.try 只接受本轮允许集中的草稿；skill.invoke 继续只接受正式发布技能。未选草稿不能被模型自行启用。
- 试用仍走原模式权限、短期调用提案、会话绑定、版本摘要和单次消费校验；不能用试用绕过实际工具授权。
- 完整技能正文与尾部约束进入真实模型请求，界面可以只显示摘要。上下文不足就明确停止，不以普通回答或自动文档生成冒充已按技能执行。
- 修改、发布、停用后，旧提案不能继续使用。失去工具支持的模型也不能静默跳过技能然后声称试用成功。

## 上传与恢复

每个技能包最多8MiB压缩数据，解压最多32MiB、4096项；单个SKILL.md正文遵循48KiB读取边界。超限明确拒绝，不保存部分正文。大参考材料保留为单独资源。包必须包含一个明确技能入口，多个技能应分开上传，避免猜错或静默丢掉其他目录。

begin/chunk/commit/abort 独立实现。分块最多64KiB；重复分块必须字节相同，缺块、摘要变化、错误偏移不允许提交。提交失去回执可用同uploadId重试，返回同一草稿。上传会过期，可明确取消，不会锁住普通聊天发送。

ZIP拒绝越界路径、链接、Windows设备路径、同名大小写冲突和文件/目录冲突；保留二进制素材。文件自带的signature/publisherId不能冒充已核验身份。GitHub静态扫描只报告其实际覆盖，不宣称已经通过行为测试或效果验证。

## 创建模板与社区市场

创建模板采用固定版本的 anthropics/skills skill-creator，原始代理说明、评测脚本、参考格式和查看器一起保留。产品适配说明优先解释真实工具、草稿试用与发布流程。

Create → Eval → Improve → Benchmark 必须使用真实案例和结果：同案例/模型/预算进行带技能与不带技能对照，保留改善前基线，再记录可获得的结果、耗时和使用量。缺失的指标标记未知，不能把文档中的示例数当结果。上游依赖Claude CLI的脚本不等于Lunitide原生运行器；依赖未就绪时明确说明，通过产品实际试用与对照流程验证，不伪造执行。

find-skills 只作为发现入口。新社区条目默认市场待安装，不因升级启动自动安装；已有用户技能不被覆盖或自动发布。受限制或许可无法确认的上游技能不擅自分发，原生替代明确标注来源。来源、固定提交和依赖见[社区技能清单](COMMUNITY-SKILLS-SOURCES-2026-09-07.md)。

## 专家与技能的长描述

打字输入统一支持32768个Unicode字符、131072个UTF-8字节；实际发送内容包含引用和附件提示的总量一起检查，超限不裁切。用户消息、持久化、续接和输入队列使用同一合同。助手输出及语音仍保留各自独立限制。

迁移0146保留旧消息、搜索索引、队列和已有幂等回执。新上限不覆盖上下文预算：材料太多时给出明确反馈，不删除专家、技能或重要尾部约束来凑输入大小。
