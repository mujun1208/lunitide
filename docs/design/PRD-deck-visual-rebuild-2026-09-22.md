# PRD：演示文稿视觉重建（换设计源，不重写 Office Studio）

- 日期：2026-09-22
- 状态：方案待评审，**尚未开工**
- 触发：用户反馈「做出来的 PPT 非常难看，选项页复杂」，并要求对标 Kimi PPT
- 输入材料：用户提供的 Kimi 对话导出（`Harness 功能清单.docx`，239 段）；本次代码核查；公开资料检索
- 前置 PRD：`PRD-office-quality-commercial-2026-09-11.md`、`PRD-office-studio-v1.md`、`PRD-office-platform-closed-loop-2026-09-12.md`

---

## 0. 一句话结论

难看的根因不是模型，也不是 OOXML 写入能力，而是**设计源是 Go 代码里手写的 DrawingML 坐标，不是设计师能改的设计产物**。

对齐 Kimi 的双模式，分两条路解决，**模板填充模式优先**：

| | 模式 A：模板填充（主力） | 模式 B：自由布局（补位） |
|---|---|---|
| 设计源 | 用户自有的设计师 PPTX 模板 | HTML 主题包（CSS 设计系统） |
| 做法 | 保留模板页装饰，只替换占位符内容 | 渲染 HTML → 截图 → 文本层叠加 |
| 观感上限 | = 模板本身的设计水平 | = 主题 CSS 的水平 |
| 可编辑 | 原生全可编辑 | 文字可改、形状不可改 |
| 用在 | 有匹配模板的语义版式 | 没有匹配模板时 |

**关键发现（3.0 节）：模式 A 所需的「打开 pptx 包并替换部件」架构已经存在**，现有生成器就是这么工作的，只是 base 包来自它自己而不是设计师模板。因此模式 A 是换一个变量，不是新建管线。

两条路都保留现有 Spec、OOXML 写入、版本、QA、导出体系。这不是重做 Office Studio，改动集中在「设计源」这一层。

## 1. 核查结论：为什么前几轮没把「好看」做出来

`PRD-office-quality-commercial-2026-09-11.md` 的诊断是对的（它已经提出「统一品牌规则 + 语义版式库 + 模板编译 + 视觉验收」，并设计了四组对照实验）。
问题是落地时，其中三件事**从能力降级成了声明**。以下都有代码证据。

### 1.1 「三套风格」实际上是一套

`internal/officestudio/templates/ops-clear.json` 与 `brand-pitch.json` **除 `templateId` 外字节完全相同**（本次逐字节比对确认）：同样的 `slots`、同样的 `constraints`。
`editorial-report.json` 仅有极小差异。三套模板的真实差异只是 `internal/officestudio/theme.go` 里 `StarterBrand(id)` 的几个颜色字段。

后果：用户在「风格」页签里选择，**版面骨架一点没变，只换了颜色**。这直接解释了「选项很多但没用」的体感。
模板 JSON 里没有任何配色、字号、网格、间距信息——它不是设计产物，是一张 slot 白名单。

### 1.2 视觉验收被测试钉死在「未校准」

- `internal/officestudio/quality.go:116` 硬编码输出 `visualScore=uncalibrated`
- `internal/officestudio/variants.go:43` 硬编码输出 `designerReviewed=0`
- `quality_test.go:19`、`layoutplan_test.go:170-177` **用测试禁止**声明 `designer-checked` 或 `designerReviewed=36`

这套自律是对的（不许把工程变体冒充设计师复核），但它同时说明：**视觉闭环从未建成**，系统自己知道它没被设计师看过。
现有「渲染」只到 LibreOffice → PDF 预览，渲染结果没有回流去修版面。

### 1.3 上一版推荐的备选渲染后端从未启用

`internal/officestudio/adapter.go:98,102`：Presenton 与 PptxGenJS 仅是 `os.Getenv("LUNITIDE_PRESENTON")` / `os.Getenv("LUNITIDE_PPTXGENJS")` 探针，用于对照，不在产品路径上。

### 1.4 版式引擎只会切页，不会排版

`internal/officestudio/layoutplan.go`：溢出处理是「拆成更多页，续页标题追加（续）」；`splitOverlongBullets(..., 300)` 按字符切；`layoutItemLimit` 12（timeline/metrics 为 6）。
没有字号自适应、没有网格、没有留白/对比度优化。内容一多就变成「标题（续）（续）」，读起来是机器产物而不是设计稿。

### 1.5 素材层为零

有 `addSlideImages`（EMU 定位、contain/cover），但没有图标库、没有自动配图、没有插画、没有背景图形。
纯文字 bullet + 深蓝底（`DefaultBrand()` navy `#0B1F3A` + Calibri / 微软雅黑）就是 2003 年的观感。

### 1.6 两条画质不同的生成路径，用户多数走在丑的那条

| | 聊天 `pptx.gen` | 工作台 `office.generate` |
|---|---|---|
| 生成器 | `officetools.GenPptx`，**单一 `slideLayout1.xml` 复用给所有页** | `GenStudioPptxThemed`，16 种语义版式 |
| 版式数 | 3（title / section / content） | 16 |
| 图表/图片 | 无 | 原生 DrawingML 图表 + 嵌入工作簿 |

聊天里的「PPT专家」「slide-builder」技能走的是第一条，也就是最丑的一条；而且 `pptGenBlocked` 的九步流水线闸门让它**又慢又丑**。

### 1.7 选项复杂，是把工程内部状态摆到了用户面前

现有「可选设置」四页签清单（实测标签原文）：

- **简报**：受众、用途、目标页数、密级，外加**逐页**填写「页标题 / 页目的 / 页结论」
- **风格**：三个单选，页面上写着「工程变体，非设计师已检 36」
- **品牌**：品牌编号、西文字体、中文字体、主色、来源、许可、摘要、标识摘要，提示「登记品牌需要编号、来源、许可和 **64 位摘要**」，并声明「一级导入只登记颜色、字体与授权记录，**不还原 PPT 母版**」
- **说明**：四条工程免责声明 + 阶段条

最严重的一条：**工作台里没有生成按钮**——界面上明写「生成在右侧对话里进行；上方预览和工作台阶段不是生成按钮」。
用户面对一个要填 20 多个字段、却不能生成的工作台。这不是选项多的问题，是信息架构错位。

### 1.8 未能核实的一项

我**没有找到**上一版 PRD 设计的四组对照实验的人工盲评结果记录。`testdata/office-quality/*.json` 与 `qa_harness_test.go` 存在，但 `visualScore=uncalibrated` 被硬编码这一事实倾向说明人工盲评没有落地。不下断言，但这个实验必须先跑（见 6.1）。

## 2. 对标：Kimi 好看在哪一层

用户提供的 Kimi 对话自己给出了六层模型，其中一句是判断依据：
> 模型只决定「内容好不好」，真正决定「PPT 好看」的是——模板库 + 版式算法 + Office OpenXML 文件引擎 + 无头浏览器渲染回路 + 截图圈选交互。

把六层对到本项目现状：

| 层 | Kimi | lunitide 现状 | 判断 |
|---|---|---|---|
| 内容结构化 | 大纲树 / 结构化中间格式 | ✅ `officestudio.Spec` + `Brief` + `NarrativeNode` 已相当完整 | 不是瓶颈 |
| 模板与素材 | 设计师模板库、图标、配图、图表主题；支持上传自定义 PPTX 模板、参考图复刻 | ❌ 3 张 slot 白名单 + 3 组写死配色，无图标无配图 | **主瓶颈** |
| 版式引擎 | 自动分页 + 字号自适应 + 行距/对比度/留白 | ⚠️ 只有拆页 | **主瓶颈** |
| 文件格式引擎 | 浏览器 OOXML writer / 本地 DrawingML | ✅ 自写 OOXML、原生图表、嵌入工作簿 | **已是强项** |
| Agent 运行时 | 300 子 Agent | ✅ 工具链、预算、隔离已有 | 不是瓶颈 |
| 预览与编辑闭环 | 在线编辑 + 截图圈选改 | ⚠️ 结构预览 + LibreOffice PDF，无视觉回流 | 次瓶颈 |

检索补充到的技术细节（对话里没有）：

1. **Kimi Slides 的中间格式是 PPTD（逐页 YAML）**，含页内元素动画与预设主题，配本地浏览器编辑器，导出走浏览器 OOXML writer 或本地 DrawingML（依据：公开的逆向实现 Open-Deck-Skill）。也就是说 Kimi 的设计源是**一份富声明式文档 + 浏览器渲染**，不是代码里算坐标。
2. **Kimi PPT 官方口径**：双模式（经典模板模式＝模板库+AI 填充；智能布局模式＝AI 自主排版）；元素原生可编辑，复杂图表也可调；支持 PDF/Word/Excel/Markdown/图片/自定义 PPTX 模板输入；可导出 PPTX/PNG。
3. **业界另一条主流路线**：HTML/CSS 做设计源 → 无头浏览器截图作底图 → 用 `getBoundingClientRect` 提取文字坐标 → 生成可编辑文本框钉在底图上。视觉 100% 保真、文字可改，代价是形状不可编辑。对中文还有隐性优势：**绕开 LibreOffice / PowerPoint 字体度量不一致导致的串版**。

结论：差距不在模型，在设计源与素材。Kimi 的双模式正好对应下面方案里的「主题包」与「自由布局」两档。

## 3. 可行性判定

### 3.0 决定性发现：部件替换架构已经存在

`internal/officetools/studio_pptx.go:98-132` 的实际流程是：

1. `base, err := GenPptx(title, baseSlides)` —— 先生成一个**自己造的** pptx 包
2. `zip.NewReader(bytes.NewReader(base), ...)` —— 打开它
3. 把 `ppt/theme/theme1.xml` 与每个 `ppt/slides/slideN.xml` **替换**为手写 XML
4. 其余部件 `zw.Copy(f)` 原样拷贝

也就是说「打开一个 pptx 包、替换其中的部件、其余透传」这套架构**已经在产品主路径上运行**。
它不好看的唯一原因是第 1 步的 base 来自自己的 `GenPptx`，而不是一份设计师做的模板文件。

**把 base 换成用户提供的模板 = 换一个变量，不是新建一条管线。** 这是本 PRD 成本估算的最大修正项。

需要处理的两个真实难点：

- `studioSlideXML` 目前写死绝对 EMU 坐标并引用 `slideLayout1`。做模式 A 时**不应整体替换 `slideN.xml`**（那会删掉模板页里的装饰图形），而应只替换占位符内的文字与数据——即「填充」而非「重写」。
- 模板占位符容量固定，内容超出会溢出。由 4.5 的自适应排版接住：缩字号 → 减条目 → 拆页（拆页复用同一模板页）。

### 3.1 其余在手资产

**可行，且比预期容易**，因为三个关键资产已经在手：

1. **已有无头 WebView2 渲染工作器**。`internal/webviewhost/diagram_worker_windows.go` 已能在隐藏 WebView2 中通过虚拟主机（`diagram.lunitide.local`）加载本地 HTML、执行 JS、回传结果（当前回传 SVG，见 `internal/diagramrender/handler.go` 的 `Result.SVG`）。改成幻灯片渲染器，只差 WebView2 的 `CapturePreview` 截图调用，同一套绑定内即可。
2. **刚建成的隔离预览源** `preview.lunitide.local`（`internal/webviewhost/preview_origin.go`，严格 CSP：允许脚本、禁止外联与 bridge），正好是渲染 HTML 幻灯片的安全容器。
3. **OOXML 写入、原生图表、版本链、QA、导出与成套导出**均已成熟，全部复用。

**需要降低期望的部分**

- 「视觉媲美」与「完全原生可编辑」只在**模式 A** 下可兼得；模式 B 仍须二选一（见 4.4）。
- 模式 A 的观感上限就是模板本身的水平，产品无法超过素材。模板库的质量直接等于产品的质量。
- 模式 A 覆盖不了模板没有的语义版式（例如模板只有 12 页而内容需要 timeline），这类页必须回落到模式 B 或退化版式。
- 字体：模式 A 用模板自带字体（个人自用无授权问题）；模式 B 与对外分发场景须用思源/Noto（SIL OFL 允许嵌入与商用）。

### 3.2 素材与授权边界（个人自用）

用户为觅知网（51miz）个人版终身会员，明确**仅自用、不商用**。据此定边界：

| | 规则 |
|---|---|
| 模板与素材存放 | 本地用户目录（如 `%LOCALAPPDATA%/Lunitide/templates/`），**不进代码仓库、不打包进安装包、不随 release 分发** |
| 产品内置 | 只内置自有 HTML 主题与可商用开源素材（Lucide ISC、自绘图形、OFL 字体） |
| 模板来源标注 | 模板库条目记录来源与授权口径，复用现有 `license` 字段惯例 |
| 将来要商用 | 只需更换素材源，架构不变——这是把素材做成可插拔的理由 |

这条边界让「自用可以随便用好素材」和「将来可商用」不冲突，且不需要两套架构。

## 4. 方案

### 4.1 架构：只换设计源那一层

```
目标 → Deck IR（内容，无坐标） → 主题包（设计） → HTML 幻灯片
                                                      ↓
                                         无头 WebView2 渲染 → 截图
                                                      ↓
                                           视觉检查 → 回流修版
                                                      ↓
                                    导出：保真档（底图+文本层） / 原生档（DrawingML）
```

复用不动：`Spec`/`Brief`/`NarrativeNode`、facts 与引用、patch（改文案/换图/改图表）、版本与接受、`office.artifact.*` 全部 bridge、成套导出、存储用量。

### 4.2 Deck IR（内容层）

在现有 `officestudio.Spec` 上收敛，明确一条硬约束：**IR 不含任何坐标、字号、颜色**。
IR 只描述「这一页是什么语义版式、有什么内容、引用哪些事实」。它是唯一的内容真相，可版本化、可 diff、可回填。
现有 `Slide` 的 `purpose` / `claim` / `evidenceRefs` / `comparison` / `metrics` 保留，`layoutTrace` 从「坐标痕迹」改为「排版决策痕迹」。

### 4.3 主题包（设计层，设计师可改）

目录形态：

```
internal/officestudio/themes/<id>/
  theme.json      # 配色、字体、字号阶梯、网格、间距、圆角、图标风格、许可声明
  theme.css       # 设计系统实现
  slots/cover.html  section.html  content.html  metrics.html
        compare.html  timeline.html  process.html  chart.html
        quote.html  table.html  evidence.html  closing.html
```

- 自适应用 CSS Grid + `clamp()` 做字号阶梯，容器查询做密度适配。
- **验收硬标准：任意两套主题的同名 slot HTML 结构必须不同。** 这一条直接把 1.1 的问题钉死——防止主题再退化成「同一骨架换配色」。
- 字体许可写进 `theme.json` 并由测试校验（复用现有 `license` 字段惯例）。

### 4.4 导出两档（默认保真档）

| | 保真档（默认） | 原生档 |
|---|---|---|
| 做法 | 整页底图 + 可编辑文本框叠加 | IR → 原生 shape/表格/图表（复用现有 DrawingML 与嵌入工作簿） |
| 视觉 | 与预览 100% 一致 | 主题的简化还原 |
| 可编辑 | 文字可改，形状不可改 | 全部可改 |
| 适用 | 自己讲、对外发 | 交给别人改版式 |

界面上必须直说这个取舍：**要最好看选保真档，要别人能改版式选原生档**。
禁止默认给保真档却宣称「完全可编辑」——这是本 PRD 的诚实红线之一。

### 4.5 视觉闭环（把 `uncalibrated` 变成真分）

渲染后自动检查：文字溢出、元素遮挡、对比度（WCAG AA）、留白比例、孤行、图表标签拥挤、图片裁切过度。
超标时**按固定顺序**回流：① 缩字号（在主题阶梯内）→ ② 降密度（减 bullet/合并）→ ③ 拆页。每次回流后重新渲染截图复检。

两个独立指标，不许互相冒充：

- `visualScore`：自动规则分（本期要变成真实数值）
- `designerReviewed`：人工复核标记（自动分永远不能把它置为非 0）

### 4.6 交互简化：20+ 字段 → 3 步

1. **一句话目标**（+ 可选参考文件）
2. **大纲确认**：可增删改页、拖拽排序 —— 取代现在逐页填「页标题 / 页目的 / 页结论」
3. **主题选择**：缩略图网格 + 实时预览

然后**生成按钮放回工作台**（修掉 1.7 那条「工作台不能生成」）。

其余下沉：

- 受众 / 用途 / 密级 → 折叠进「更多设定」，默认不展开
- 品牌登记（编号 / 来源 / 许可 / 64 位摘要）→ 移到设置页，普通用户永不接触
- 四条工程免责声明 → 从主界面移除，改为文档与 hover 说明
- 「工程变体，非设计师已检 36」→ 不在用户界面出现

### 4.7 路径收敛

`pptx.gen` 不再自己写文件，改为转调 `office.generate`（`internal/app/office_generate_adapt.go` 已有 shape 适配代码）。
聊天与工作台共用同一条画质。同时重新评估九步流水线闸门（`pptGenBlocked`）：闸门的价值在内容完整性，不该让用户为丑的输出多等几轮。

### 4.8 素材层（低成本、高收益）

- **图标**：Lucide（ISC）本地内嵌，按语义自动选配（metrics / process / timeline 最吃这个）
- **图表**：ECharts 渲染期出图（保真档）＋ 原生 DrawingML 图表（原生档），同源数据
- **背景与装饰**：内嵌抽象图形、渐变、几何形（零版权风险）
- **配图**：联网图库（Unsplash / Pexels 免费商用）放 P2，且带开关
- **字体**：思源黑体 / 思源宋体（OFL）内嵌 + 系统回退

## 5. 明确不做（本期）

- 不重写 Office Studio 的版本链、QA、导出、成套导出、存储体系
- 不做用户上传 PPTX 母版还原（P2）
- 不做参考图复刻（P2）
- 不引入云沙箱、云端无头浏览器（本地桌面形态不需要，见第 7 节）
- 不为了追平「原生可编辑」而牺牲默认观感

## 6. 分期

### 6.1 P0：先判断方向对不对（不做产品化）

因 3.0 的发现，P0 主力改为**模式 A**（成本更低、上限更高）：

1. 用户从 51miz 下载 2–3 套喜欢的商务汇报模板，放入本地模板库
2. 解析模板：读 `ppt/slideLayouts/*`、`ppt/slides/*` 的占位符（`ph type`/`idx`）与 `theme1.xml`
3. 取一页真实内容，只替换占位符文字，其余部件透传 —— 验证装饰图形是否完整保留、中文是否不串版
4. 同时做 1 套 HTML 主题（cover / content / metrics / compare / closing 五个 slot）作为模式 B 的对照

然后跑上一版 PRD 已设计好、但看不到结果记录的对照实验，**固定模型、素材、信息量、目标页数**，用同一份经营汇报材料：

| 组 | 变量 |
|---|---|
| A | 当前输出（基线） |
| B | 只换提示词 |
| C | 模式 B：换 HTML 主题 |
| D | 模式 B + 布局规划 + 视觉回流 |
| **E** | **模式 A：51miz 模板填充** |

人工盲评（版面观感 / 关键内容保留 / 拿到后还要改多久）。

**出口判据**

- **E 最好（预期结果）** → 模式 A 作为主力，P1 先做模板填充，HTML 主题降级为补位
- E 与 D 接近 → 两模式并行，按语义版式是否有匹配模板来路由
- D 显著优于 A 但 E 不行（模板填充串版/装饰丢失） → 回到 HTML 主题路线
- B 就能追平 → 瓶颈在内容叙事不在设计源，本方案要改向
- 都没改善 → 停下来重新定位，不要继续投

这一步是防止第二次投错的闸门。先跑它。

### 6.2 P1：做成产品（视觉达标）

- **模板库与填充引擎（模式 A 主力）**：本地模板库管理、占位符解析、语义绑定、装饰保留、字体校验
- 1–2 套 HTML 主题（模式 B 补位，覆盖模板缺失的版式）
- 三步向导；生成按钮回到工作台；选项下沉
- 自适应排版（字号 / 密度 / 网格）+ 视觉回流
- 图标 + ECharts + 内嵌 OFL 字体
- 保真档导出
- 路径收敛（`pptx.gen` → `office.generate`）
- `visualScore` 真实化，`designerReviewed` 保持独立

### 6.3 P2：追平差异化能力

- 原生档完善（表格、图表、图标的原生映射）
- 用户上传 PPTX 母版还原
- 参考图复刻
- 在线版式微调（圈选改文案 / 换图 / 改图表已有，补版式）
- 引用核验（现有 facts / evidenceRefs 已有骨架）
- 联网配图（带开关）

## 7. 钱花在哪

用户材料里的付费清单落到「本地桌面产品」这个形态，可以省掉相当一部分。

**必须花**

| 项 | 说明 |
|---|---|
| 评测集 + judge token | 持续性支出，用户材料也提醒了这是隐性大头 |

**原本的最大成本项已被消除**：原估「6–8 套主题的设计人力」是决定性投入，现由用户已有的 51miz 个人版终身会员替代——模式 A 的设计来自模板库，不需要外包或自产设计。HTML 主题（模式 B）由工程自行实现，只覆盖模板缺失的版式，数量需求从 6–8 套降到 1–2 套。

**不需要花（本地形态的优势）**

| 项 | 为什么不需要 |
|---|---|
| 云沙箱（E2B / Daytona / Firecracker） | 已是本机执行 + Job Object 隔离 |
| 云端无头浏览器（Browserbase / Steel） | 本机已有 WebView2，且已有渲染工作器 |
| 商用字体授权 | 用思源 / Noto（OFL）规避 |
| 图标 / 图表库 | Lucide + ECharts 免费 |
| 搜索抓取 API | 已有 `web.search` / `web.fetch` |

**可选**：高级图库（摄图 / Getty），仅在客户要求商业级配图时采购。

## 8. 风险与红线

| 风险 | 对策 |
|---|---|
| **模式 A：整体替换 `slideN.xml` 会删掉模板页装饰** | 只替换占位符内的文字与数据，不重写整页；P0 第 3 步就要验证装饰完整保留 |
| **模式 A：占位符容量固定，内容溢出** | 走 4.5 的自适应排版（缩字号 → 减条目 → 拆页，拆页复用同一模板页） |
| **模式 A：模板自带字体本机缺失导致回退串版** | 生成前校验模板字体可用性，缺失时回退到已装字体并在质检里报告，不静默 |
| **模式 A：模板没有对应语义版式** | 回落策略需先定（见 9 节待确认 2）；不允许硬塞进不匹配的模板页 |
| **素材误入仓库或安装包** | 模板库固定在用户目录；加测试断言 release 清单里不含模板与素材文件 |
| 底图导出让形状不可编辑（模式 B） | 双档 + 界面直说取舍；禁止默认保真档却宣称「完全可编辑」 |
| 主题包退化成 slot 白名单（1.1 复发） | 验收测试：任意两套主题同名 slot 的 HTML 结构必须不同 |
| 视觉分再次自我豁免（1.2 复发） | 验收测试：视觉回流必须真实降低溢出 / 对比度违规计数，否则判未达标 |
| 备选后端再次停在环境变量探针（1.3 复发） | 渲染后端必须在产品默认路径上，不靠 `os.Getenv` 开启 |
| 重写现有体系导致回归 | 版本链 / QA / 导出 / patch 一律复用，改动限定在设计源层 |
| 字体许可法律风险 | `theme.json` 声明许可，测试校验，仅允许可嵌入可商用字体 |
| 中文排版串版 | 保真档天然绕开字体度量差异；原生档需单独做中文度量校验 |

## 9. 决策记录（2026-09-22 已确认）

| 议题 | 决定 | 影响 |
|---|---|---|
| 是否先跑 P0 | **先跑 P0**，验证方向再投入 | 6.1 生效，含新增 E 组 |

### 仍待确认

1. **模板库规模**：先放几套？建议 P0 用 2–3 套（覆盖 cover / content / metrics / compare / closing 即可判断）。
