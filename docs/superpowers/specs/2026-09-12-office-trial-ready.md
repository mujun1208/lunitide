# Office 试验包（可 100% 收口）

**日期：** 2026-09-12  
**对照 PRD：** `docs/design/PRD-office-quality-commercial-2026-09-11.md`（与 HTML 同一份）

## 为什么不是整份 PRD 的 100%

整份 HTML PRD 的产品验收不能只靠写代码做到 100%。设计师已检 36 变体、PowerPoint/WPS 实机矩阵、视觉模型、校准 85 分、竞品盲评、5–10 试点、Typst 出版内核、FR17/FR18 都不在本规格里。

本规格定义一份**封闭试验包**：包内条目必须能做到 100%，并且试验者不会把「未做的 PRD 章节」误当成产品已交付。

## 试验者可以完整走完的路径

1. 创建任务，编辑简报（受众、用途、页数、大纲、密级），不把空白显示成「管理层 / 经营汇报 / 12 页」。
2. 通过对话生成 PPTX / DOCX / XLSX / 独立 PDF；已填字段进入文件，未填字段不虚构密级或经营数字。
3. 检查、局部修改、草稿导出；正式交付按钮在未通过时禁用，并写出原因。
4. 看见试验范围说明：本包不声称设计师已检模板、校准 85、目标软件实机通过、竞品盲评或企业模板审批。

## 本包必须 100% 完成的条目

| ID | 条目 | 完成定义 |
|---|---|---|
| TR1 | 简报落盘不虚构 | `WithTaskBrief` 只保存已填字段；空受众/用途/页数/密级保持空 |
| TR2 | 快照不虚构 | `office.task.get` / 任务 DTO 返回原始 Brief，不经 `NormalizeBrief` |
| TR3 | Studio 概要不虚构 | 空白显示「未填写 / 页数未填写」；可填写并保存密级 |
| TR4 | 正式交付原因可见 | 未通过时按钮禁用，并说明是检查未过还是硬阻断 |
| TR5 | 试验范围可见 | Studio 写明本包包含什么、不声称什么 |
| TR6 | 试验脚本 | 试验者可按文档走完主路径，并知道哪些结果不算验收失败 |

## 明确不在本包（做了也到不了 PRD 100%）

- `designerReviewed=36`、校准视觉 85、竞品得分
- 把 `target-*` / `visual-model` / `pdfa` 标成 passed
- Presenton / PptxGenJS 作为第二生成内核
- FR17 / FR18
- 未重建前声称装机 0.4.75 已修
- 提交 / 推送 / VERSION / 打包（除非另行要求）

## 生成时仍允许的默认

`NormalizeBrief` 只用于 Word/PPT **生成规划**（空受众按管理层排版）。独立 PDF 继续只写原始 Brief。聊天证据可以继续用 NormalizeBrief，让模型知道生成时会用的默认。快照和 Studio 不得把这些默认写成用户已填。
