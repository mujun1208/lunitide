# ADR-017: 市场签名根（D-6）

## Status
Accepted（v1.0.0 · 2026-08-16 · 决策人：项目业主 · 接受方式：会话确认 2026-08-16）

## Context
M9 FR-07（能力市场）要求冻结 Registry 签名链根、审核与撤回流程；
威胁模型 `docs/threat/m9-04-market-signing.md`（T-10/11/12 供应链）已评审。
M6 已交付 Registry/SkillInstall 生命周期与 ed25519 委派签名机制。

## Decision
1. **签名链根**：市场签名根采用 **ed25519 密钥环**（复用 `internal/delegation` envelope
   的 keyID 版本化 Signer/KeyResolver 机制）：离线根密钥（本地安全保管，不参与日常签名）
   → 在线签名密钥（keyID 版本化，日常包签名）。签名对象为包清单 Canonical JSON 的
   SHA-256 摘要；安装前强制验签，验签失败零安装（M9-015/016）。
2. **审核流程**：组织能力包上架须经审核（review）→ 签名 → 发布；审核记录入组织审计链；
   个人资产发布适配器只接收 M8 生成的组织版本及其脱敏证明、重新授权票据和来源摘要，
   **M6/M9 永不接收私人原件**。
3. **撤回流程**：撤回组织版本向 M6 Registry 缓存和任务输入传播 tombstone；
   已安装副本进入隔离（quarantine）态并阻断执行，不静默卸载。
4. **轮换方案（批准条件之一）**：密钥环版本化——新 keyID 加入环 → 目录全量重签名 →
   旧 keyID 进入宽限期（仅验签不签名）→ 宽限期结束移出环；根密钥轮换需重签目录
   并发布轮换审计事件。
5. **M6 复用约束**：注册/签名/审核/撤回复用 M6 Registry/SkillInstall，不建第二套生命周期；
   M9 仅加组织覆盖层（org 前缀、组织审核、组织签名密钥环）。

## Alternatives considered
- **单一在线密钥（无密钥环）**：被否决——密钥泄露即全目录失守，且无轮换路径。
- **证书链 X.509 体系**：被否决——对本地单机产品过重；ed25519 envelope 已在 M6 验证。
- **撤回即远程卸载**：被否决——破坏安装方自主控制；隔离+阻断执行已满足安全目标。

## Consequences
- 解锁 T-9.3.1（market/registry.go）与 T-9.3.2 市场部分。
- 篡改包/未签名包/撤回后安装全部零安装负测（M9-015/016/017/018）。
