# ADR-013: 策略合并代数（D-3）

## Status
Accepted（v1.0.0 · 2026-08-16 · 决策人：项目业主 · 接受方式：会话确认 2026-08-16）

## Context
M9 FR-04/FR-05（只收紧策略层级 / SoD）要求冻结平台→组织→空间→项目的策略合并规则与版本凭证；
威胁模型 `docs/threat/m9-03-policy-algebra.md`（T-05/06 放宽拒绝）已评审。

## Decision
1. **四层只收紧合并**：Platform → Organization → TeamSpace → Project 逐层向下合并；
   合并语义为「收紧格取交」：每项能力取各层约束的**最严值**（区间取交、枚举取交、
   布尔取 AND、数值上限取最小/下限取最大）。任何维度在任何层级只能收紧，不能放宽。
2. **放宽即拒绝**：若下层策略在任一维度比上层宽松，合并拒绝并返回 M9-008/010
   （策略放宽被拒），不进行「截断到父层」的静默矫正。
3. **禁止自批**：策略变更的发起主体不得同时是该变更的批准人（SoD 互斥，M9-009）；
   审批人集合与发起人交集非空即拒绝。
4. **版本凭证**：合并结果携带 policy digest（Canonical JSON SHA-256，排序键无空白）
   与来源层版本链；每次授权判定绑定 digest，策略变更后旧 digest 判定不可重放。
5. **合并证明（形式化说明，批准条件之一）**：收紧格合并对「放宽为零」的保证来自
   逐维度单调性——交运算在偏序（严格程度）上单调递增，且每层输入经自身校验合法，
   故输出必然不宽于任一层输入；「自批为零」由审批人集合与发起人集合的互斥检查保证
   （代数上为集合交空断言）。该说明随 `TestMergeTightenOnly` 全负测落地。

## Alternatives considered
- **最下层优先（override）合并**：被否决——子级放宽成功即违反 FR-04 硬约束（子级放宽成功必须为 0）。
- **宽松层静默截断到父层**：被否决——静默矫正掩盖策略配置错误，必须显式拒绝。

## Consequences
- 解锁切片 2 全部任务卡（T-9.2.1 algebra.go / T-9.2.2 approval.go）。
- 策略模拟器须支持合并预演（变更前后 digest 与逐维度 diff）。
