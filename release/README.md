# Windows release security policy

`Build-Release.ps1` stages only the native Go executables, WebView2 loader, renderer assets, and license notices. `Verify-Layout.ps1` rejects every other root and known Electron, Node, and Python runtime pattern, then requires `SHA256SUMS.txt` to describe every staged payload file exactly once with no missing or extra entries.

The WebView2 NuGet package hash and the independently pinned x64 `WebView2Loader.dll` hash are both source-controlled. When installed `nuget.exe` or `dotnet nuget verify` supports signature verification, an invalid package signature always fails. If no verifier is available, development-only builds emit a warning and continue with both hashes enforced; production builds fail closed. Installer creation requires signing by default. `-AllowUnsignedDevelopment` is the only unsigned installer path and its output is non-publishable. Production/tag builds require `LUNITIDE_SIGN_COMMAND`, an exact 40-hex publisher match to `LUNITIDE_SIGNER_THUMBPRINT`, a timestamped Authenticode signature, and successful Windows SDK `signtool verify /pa /all /v` policy validation of the signature and timestamp chain.

The installer rejects downgrade by default; `/ALLOWDOWNGRADE` is the explicit override. Before replacing files it accepts only a valid ownership marker, or the legacy uninstall registration whose `InstallLocation` exactly matches the fixed per-user path. It checks process-stop and removal failures, replaces the complete release directory so stale binaries cannot survive, and never places user data there. Uninstall retains `%LOCALAPPDATA%\Lunitide` unless `/PURGE` is explicitly supplied.

`Test-Install.ps1` intentionally exercises the real per-user Windows Known Folder paths. It refuses to run when an existing Lunitide install, registration, or data root is present, launches the installed product, waits for the trusted WebView2 document to load, closes the real window with `WM_CLOSE`, and verifies that Desktop and Engine exit cleanly. Use it only in a disposable Windows account or clean VM because a real window, shortcuts, HKCU uninstall registration, and application data root are exercised.
