# Lunitide 0.19.3

用 0.19.2 的时候你可能遇到过：月伴语音聊了几轮之后，反应一轮比一轮慢，你打断一句再问，它半天不出声；紧接着识别也开始出问题——要么卡住没反应，要么只出来一两个字。越用越卡，只能退出重进。根因是打断时语音合成没有真正停下来：GPT-SoVITS 在 CPU 上一次推理要 30-90 秒，你嘴上打断了，那条还在跑的「僵尸推理」却占着合成队列，下一轮的每一段都排在它后面；积压的推理又把 CPU 吃光，把负责听你说话的识别引擎饿得接不住完整语句。这一版把打断的「最后一公里」接通了。

## 打断之后立即干净

- **以前**：打断只是「丢弃结果」，已经在跑的推理照跑不完——队列被僵尸占住，下一轮回复越等越久，多轮下来卡顿持续加重。
- **现在**：打断会当场掐断在飞的合成请求（HTTP 连接直接断开），单飞队列立刻释放；打断之后新一轮的第一段马上就能开始合成，不再给僵尸排队。
- 排队途中被打断的段落会在进引擎之前直接丢弃，不会浪费算力，也不会在你收声之后突然冒出半句旧回复。

## 识别不再被合成饿死

- 僵尸推理不再堆积成 CPU 风暴，语音识别在多轮对话全程都能拿到算力，正常语速下不再出现「只识别出一两个字」或整句识别不出的问题。
- 专门加了回归测试锁死这条链路：打断在飞的合成后，新一轮请求必须立即进入引擎——这条测试在修复前必挂，修复后常绿。

## 依赖安全升级

- 渲染层依赖审计清零：修复 DOMPurify（高危）、Vite（高危）、KaTeX / @vitest/mocker / fast-uri（中危）共 7 项已知漏洞，`npm audit` 现为零告警。
- Go 工具链升级到 1.26.10，修复标准库 crypto/x509 已知漏洞（GO-2026-6809，修复前本产品语音后端的 WebSocket 调用链可达）；`govulncheck` 与 `golangci-lint` 全绿。

## 不改什么

- 不改 poison / 月伴 TTS 音色 / 玉盘像素 / 星尘配方。
- 不改 0.19.2 的重试语义、三档预算、G-301~308 闸口与止损语义。
- 月伴的全部音色配置、参考音频路径、流式与整段两种合成方式保持原样；图表渲染（mermaid 12）仅是安全升级，用法不变。

## 兼容与覆盖安装

- Windows 端直接覆盖安装，配置、会话、记忆、已配对信息全部保留。
- 更新源只认最新版本；本版安装包不得覆盖更早 tag 的 digest。
