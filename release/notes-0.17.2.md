# Lunitide 0.17.2

装上 0.17.1 之后你会遇到四件糟心事，这一版把它们全部收口：

1. **附件传不上去**——文件一大上传就失败，或者卡片一直转圈。根因是 WebView2 154 起会丢弃超过 64KB 的页面消息帧，而大文件分块正好踩在这个尺寸上。现在分块降到传输安全尺寸，附件与技能包走同一条修复后的通道，大文件上传稳定完成。
2. **流式回复时追问没有下文**——模型正在写长回复时你追加的问题（带不带图片都一样）只收到一句"已并入"，之后就没有然后了。现在追问会被真正回答：模型读完补充内容继续生成，不会悄悄丢掉。
3. **流式中追加图片追问读不出图**——排队发送的图片现在和正常发送完全同一条链路：先走你配置的 OCR 模型（供应商 OCR → 本地 OCR → Windows OCR 兜底），读出文字直接作答；纯文字模型不会再收到它看不了的图片请求而报错。
4. **消息看不清何时发的、用量看不到**——每条消息（包括正在生成的那条）都带完整"年-月-日 时:分:秒"时间戳；输入框旁的上下文用量百分比常驻显示，上下文窗口从 0 修复为模型真实窗口。

另外，此前已修复但尚未随安装包发布的两项手机端改进一并发布：

- **APP 扫码闪退修复**：Android 壳打包了缺失的 androidx.core 运行时，扫码配对不再启动即崩。**手机需要重新下载安装新 APK**（`Lunitide-Android-0.17.2.apk`）。
- **手机端媒体资源走网关代理**：远程会话里的图片等媒体不再依赖直连，弱网下也能加载。

## 消息与时间

- 每条历史消息和正在生成的 AGENT 回复都显示完整日期时间（此前 live 回复只有状态没有时间）。
- 会话切换后重新进入，时间戳保持一致。

## 附件与上传

- 大文件上传分块修复：WebView2 154+ 传输安全分块，附件、技能包上传同享。
- 流式中排队的图片追问：图片经 OCR 链（供应商配置的 OCR 模型 → 本地下载的 OCR 模型 → Windows OCR 兜底）识别为文字后作答；该识别链路与正常发送路径完全一致，纯文字聊天模型不会收到图片请求。
- 流式中排队的文字追问：消费后强制追加一轮模型调用（此前普通对话单轮预算下追问会被静默丢弃），回答里会真正结合你的补充。

## 用量与上下文

- 输入框旁常显上下文用量百分比，悬停可见"已用 token / 模型窗口"。
- 新会话首条消息后上下文窗口即显示真实值（此前显示 / 0 tokens）。

## 手机端（随本次安装包发布）

- 扫码闪退修复：重装新 APK 后扫码配对可用。
- 媒体资源经网关代理加载。
- 连不上电脑时不再白屏卡死：显示错误页，可一键重新扫码配对或重试连接。
- 候选地址并行探测：启动时同时测全部已知地址（局域网 IPv4 / 公网 IPv6），先通先用，
  蜂窝网络下不再被失效地址逐个拖慢 8 秒；电脑具备公网 IPv6 时，手机流量即可直连使用。

## 不改什么

- 不改 OCR 识别链路顺序（供应商 OCR → 本地 OCR → Windows OCR 兜底，不用大语言模型看图）。
- 不改 poison / 月伴 TTS 音色 / 玉盘像素 / 星尘配方。
- 不改既有界面布局与交互习惯。

## 兼容与覆盖安装

- 直接覆盖安装即可，配置、会话与数据全部保留。
- 更新源只认最新版本；本版安装包不得覆盖更早 tag 的 digest。
- 手机端请从 Release 下载新的 `Lunitide-Android-0.17.2.apk` 覆盖安装。
