# Lunitide 0.16.4

上一版（0.16.3）装上后，手机上配对、聊天、追问、恢复会话都通了——但用真实手机全流程模拟逐项核验时发现两个收尾问题：手机上进入对话后，左上角没有导航按钮，想回首页或切换会话只能刷新页面；另外每次打开页面浏览器都会记一条安全策略报错（不影响功能，但调试和审计时能看到）。这一版把这两件事收口。

## 手机伴侣：对话界面有了导航按钮

- **手机上（窄屏）左上角常驻汉堡按钮。** 根因是按钮的渲染条件里，导航开关组件永远被视为「已存在」且窄屏模式从不置位收起状态，两个条件都不满足时按钮直接不渲染——而手机正好落在这个空档：抽屉导航的样式和交互其实早就写好了，按钮却永远不出现。现在窄屏（680px 以下）始终渲染按钮，点开即见会话列表、新对话和设置入口，点空白处关闭。桌面行为完全不变（仍是收起侧栏后才出现悬浮按钮）。
- 修复经过完整的手机模拟验证：Android 视口下配对 → 安装引导 → 发消息 → 流式回复 → 追问 → 再次进入 → 恢复会话 → 打开抽屉导航，14 项功能断言与 7 项全链路审计（零限流拦截、零桥接失败、零控制台错误、请求量在预算内、流式事件完整）全部通过。

## 安全策略：消除每次加载的报错

- **内容安全策略（CSP）里移除一条 Chrome 判定为非法的条目。** `ws://[::1]:*`（本机 IPv6 WebSocket 白名单）被 Chrome 判定格式非法后整条忽略——等于从来没生效过，却让每次打开页面都多一条控制台报错。同源 WebSocket 连接本就由「'self'」覆盖，移除零功能损失，控制台从此干净。

## 不改什么

- 配对安全模型、限流策略（120 次/分钟）完全不变。
- 月伴 TTS 音色、玉盘像素、星尘配方均不动。
- 桌面端界面与交互完全不变。

## 兼容与覆盖安装

- 直接覆盖安装即可，配对关系与本地数据全部保留。
- 已配对的手机无需重新配对，装完后进入对话界面即可看到左上角导航按钮。
