# Lunitide 0.17.7

上一版（0.17.6）在实际手机上暴露出一串硬伤：点扫码屏幕自动转成横屏、激光线竖着扫不了码；配对明明成功，一进系统就全屏报「WebView2 Bridge 当前不可用」，模型也用不了；退出重进还是报错；不连 Wi-Fi 时浏览器打不开配对页、装不了 APP。这一版把根因逐一修掉，并用一道「可用性闸门」把标准钉死：**能进系统就必须可用，不可用就退回重新扫码配对**。

## 扫码真正竖屏了

- 上一版的方向解锁为什么没生效：内置扫码组件在自己的配置文件里把横屏写死了，运行时解锁根本覆盖不了它。这一版换成自定义竖屏扫码页，点扫码**不再转横屏**，取景框和激光线都是横着的，直接对准二维码就扫。

## 系统「不可用报错」的根因修复

- 实测取证发现：安卓壳里 HTTPS 请求完全正常（配对就是它做的），但桥接用的 WebSocket 在部分手机网络栈下**静默失败**——配对成功、桥却一条消息都没送到，所以进系统全是「WebView2 Bridge 当前不可用」。
- 这一版把整条桥搬到 HTTPS 上（响应先行、事件持续流式推送，语义与原来完全一致）：配对能通，桥就一定能通。聊天流式回复、语音对话、终端这些持续推送的能力全部走同一条通道。

## 进入系统前先验证：不可用就退回重扫

- 配对成功后、放你进系统前，APP 会先用刚拿到的授权向电脑发一条最轻量的验证请求，整条链路真实通了才放行。
- 验证不通过时**不进入系统**，直接显示原因和「重新扫码配对」按钮（也提供「重试验证」应对网络瞬断）——按你的标准：进入正式系统就必须可用，否则退回重新扫码。
- 以后任何时候打开 APP 发现电脑连不上，壳会弹「连不上电脑」页，给「清除并重新扫码配对」和「重试连接」两个出口；浏览器打开则自动退回配对页。不会再看到一个全屏报错的系统。

## 不连 Wi-Fi 也能下载安装了

- 二维码首选地址改为**公网 IPv6**（蜂窝流量和家里 Wi-Fi 都能直连），局域网 IPv4 退居其次。上一版 IPv4 置顶导致不连 Wi-Fi 时浏览器打不开配对页、下载不了 APP。
- 同时补了一个网络层守卫：旧地址「黑洞化」（防火墙静默丢包、连接既不成功也不报错）时，以前会永远卡在旧地址上；现在按请求时限主动断开并轮换到下一个候选——离家切蜂窝后自动换 IPv6 直连才真正可靠。

## 其它

- 壳层不再把「连接正常关闭」误判成故障抢弹错误页（上一版配对成功后页面被错误页抢走就是它）。

## 不改什么

- 不改 poison / 月伴 TTS 音色 / 玉盘像素 / 星尘配方。
- 不改既有界面布局与交互习惯。
- 不做云账号、不做官方中继服务器。

## 兼容与覆盖安装

- Windows 端直接覆盖安装即可，配置、会话与数据全部保留。
- 安卓端用新 APK 覆盖安装即可；已配对信息保留。若覆盖后首次打开验证不通过（电脑关机/换网络），按提示重新扫码配对即可。
- 更新源只认最新版本；本版安装包不得覆盖更早 tag 的 digest。
