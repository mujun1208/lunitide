# Lunitide 0.19.2

用 0.19.1 的时候你可能遇到过：网络抖一下、上游限流一次、或流式回复传到一半断了——助手直接把这轮对话判失败，你得手动重发一遍。更早的时候这类瞬断更常见，只是从没告诉你为什么。这一版把「瞬断自愈」补齐了：以前的重试机制写好了但从未真正启用（所有请求都锁死为「只试一次」），现在把它激活并补上安全边界。

## 网络瞬断、限流、断流现在自动重试

- **以前**：连接被拒、429 限流、5xx 抖动——一次失败就直接报错给你，整轮重来。
- **现在**：这类瞬时故障自动重试（最多 3 次尝试），带指数退避。退避加了随机抖动，多个并发请求同时撞限流时不再集体同步重试互相踩踏；服务器明确指定的等待时间（Retry-After）则严格照办。
- 主对话、意图识别、专家团、后台代理、代码工作区全链路统一生效。

## 流式回复的重试有严格的交付边界

- 流式回复**一个字都还没发给你**时遇到断流/停摆/过载，会在同一轮里悄悄重试一次，你只会感觉首字稍慢，不会看到失败。
- **已经发出内容**的流绝不重试——不会出现回复重复、内容错乱的场面。这条「不重试契约」由交付时钟精确把关，并有专门的测试钉死。
- 上游「光思考不产出」的停摆、流中断、过载这几类可自愈故障纳入重试白名单；参数错误、鉴权失败这类不会因为重试变好的故障仍然快速失败。

## 对上游的友好性

- 重试之间有真实退避（不打出密集重试风暴），抖动让并发客户端错峰。
- 流式请求在零字节阶段的重试不需要幂等键保护（天然安全），非流式保持幂等键契约不变。

## 不改什么

- 不改 poison / 月伴 TTS 音色 / 玉盘像素 / 星尘配方。
- 不改 0.19.1 的工具面、三档预算、G-301~308 闸口与止损语义。
- 会话恢复与历史记录兼容，旧版本数据直接继续用。

## 兼容与覆盖安装

- Windows 端直接覆盖安装，配置、会话、记忆、已配对信息全部保留。
- 更新源只认最新版本；本版安装包不得覆盖更早 tag 的 digest。
