# Lunitide 0.15.2

装上 0.15.1 之后：产品总览的诊断报告里会出现「模型有新一代：glm-5.3 → glm-5」这类发现，可你从来没有配置过 glm-5——系统只是凭产品内置档案里登记的演进路径就报了升级分析，没有新旧两代可对比，分析是无源之水。0.15.2 把升级检测改为配置驱动：新一代模型真的进入你的供应商配置，分析才会出现。不改 poison / 月伴 TTS 音色 / 玉盘像素 / 星尘配方。不声称产品 100%。

已装 0.15.1 可直接覆盖安装。不要覆盖 `v0.15.1` 及更早 tag 的 digest。不要重签 `v0.15.1`。本包挂 GitHub Latest，应用内更新从 `latest.json` 下这一版。

## 1. 升级分析以你的配置为准

- 现在只配置了上一代主力（比如 GLM-5.3、DeepSeek 4 Pro）：诊断报告不再报「模型有新一代」，模型融合行如实显示「配置中没有出现新一代模型，暂无可分析的升级」。
- 将来某天你把新一代（比如 GLM-5.4、DeepSeek 5 Pro）加进了供应商配置：那一刻诊断报告才给出「模型有新一代：旧 → 新」的发现，证据写明配置事实——「供应商已配置新一代 X，当前主力仍是 Y」。
- 执行净化照旧生成完整升级方案（新旧能力差异、受影响功能、切换步骤、验证与回滚）；确认后把默认主力换成新一代、点「重新检测」，该发现自动消失——自净化闭环不变。

## 2. 顺带核实

- 上一版报告里的「video 模型槽位没有可用配置」（PH_M01）属实：文生视频槽位确实未配模型，配置后该发现同样自动消失。

## 3. 不做

- 不重签 `v0.15.1` 及更早版。
- 不改月伴音色、玉盘像素和星尘配方。
- 不改对话界面布局与交互习惯。
- 不改 poison 自愈机制。
