# Lunitide 0.14.0

装上 0.13.x 之后：产品概览的诊断报告只认手写清单，引擎里真实存在的大批功能入口（600 多个运行时动词）被算在覆盖之外，能力被低估、新入口没有讲解卡；实测探针只有「跑通 / 失败 / 未测」三档，一些「入口已经跑到、只是参数被拒」的功能被误报成坏的，而会开浏览器、发消息、装东西的危险操作探测器会真的去执行；GLM、DeepSeek 出新一代模型时产品毫无感知，诊断报告不知道你配置的主力模型已经落后一代，更不会给同步升级方案。0.14.0 把这些收口。不改 poison / 月伴 TTS 音色 / 玉盘像素 / 星尘配方。不声称产品 100%。

已装 0.12.0 及以上版本可直接覆盖安装。不要覆盖 `v0.13.2` 及更早 tag 的 digest。不要重签 `v0.13.2` 及更早版。本包挂 GitHub Latest，应用内更新从 `latest.json` 下这一版。

## 1. 诊断报告看得见全部运行时功能

- 引擎现在把整个运行时动词表（含内部调度表共 651 个动词）在启动接线时登记给产品中枢；诊断报告新增一行统计：注册动词多少、用户功能多少（其中多少由动词表自动建卡、多少已挂在手写功能卡上）、运行时内部多少。
- 过去没有手写卡的用户动词直接从产品概览里消失；现在每个未覆盖的用户动词自动得到一张讲解卡，标明「由动词表自动登记」，入口与链路是通用模板，是否真的跑得通以诊断实测行里的证据为准。
- 引擎管道类动词（文件、日志、协调、传输等 38 类前缀）不建卡、只进统计行——它们让产品跑起来，但不是你用的功能。未识别前缀的动词一律按管道处理，不会被悄悄建卡冒充功能。
- 修复后有回归测试锁定：动词表覆盖每个已登记的用户动词、危险动词只读不执行、内部动词不出现在探测结果里、卡数与报告口径一致。

## 2. 探针实测分五档，不再误报也不乱动你的机器

- 实测结果从三档扩成五档：**已跑完**（pass）、**入口已跑到**（reached，处理函数执行了但功能未完整跑完，比如参数被拒）、**不代跑**（skipped，会开窗口、占麦克风、安装、联网或执行命令的操作，探测器只登记不执行）、**失败**（fail）、**尚未跑完**（untested）。
- 「入口已跑到」和「不代跑」都不计入通过数，也不算失败——报告会分开写「本轮读回 a/b、入口已跑到 c 项、不代跑 d 项」，前端诊断面板对这两档给了中英文说明。
- 43 个危险动词（浏览器导航、发消息、开会、装东西、执行命令等）明确列入不代跑名单，每个都写了不代跑的理由；这些功能卡上的实测行显示「不代跑」而不是假装跑过。
- 修复后有回归测试锁定：五档与状态一一对应、不代跑不计入分母分子、干净一轮的报告不出现中间档字样。

## 3. 产品源码根可配置

- 诊断报告讲解功能链路需要读产品源码。过去只能靠自动探测或环境变量；现在支持在数据目录写 `product-source-root.json` 持久配置，优先级为：锁定配置 > 手动配置 > `LUNITIDE_SOURCE_ROOT` 环境变量 > 自动探测。
- 配置一个不含产品文件的目录会被拒绝并提示，不会静默指错；访客模式（无源码）的报告会写明两条配置路径的指引。
- 修复后有回归测试锁定：配置根优先于探测、无产品文件的目录被拒绝。

## 4. 模型深度融合：换代感知与同步升级

- 产品中枢现在内置模型能力档案库（GLM、DeepSeek、豆包、Kimi 等在用型号），档案里显式写明换代关系（GLM 5.3 → GLM 5、DeepSeek 4 Pro → DeepSeek 5 Pro 等），不猜版本号；未登记的能力一律写「未登记」，不编造。
- 供应商页配置的模型（含哪个是默认主力、上下文窗口、是否可用）会同步进诊断：报告新增「模型融合」一节，写明已接入供应商、每家的模型与主力标注。
- 四类新发现：主力槽位未配（warn，绑定具体受影响功能）、**模型有新一代**（info，写明当前型号与后继型号）、上下文窗口未登记、供应商不可用。
- 检出「有新一代」后，执行净化咨询会拿到一份五件套升级任务书：能力差异对比、受影响功能清单、产品同步升级方案、验证步骤、回退方案。你在供应商页把默认模型换成新一代、重新诊断后，该提示自动消失——升级闭环由测试锁定（清单里出现新模型不等于已采纳，只有换了默认主力才算）。
- 修复后有回归测试锁定：升级检出、清单不等于采纳、四类发现计数、换模型后提示消失、未注入供应商时报告零漂移。

## 5. 渲染层依赖安全更新

- 上游新披露 source-map-js（高危，事件循环拒绝服务）与 dompurify（低危两例）安全通告。锁文件已就地升级到修复版，前端全量测试与构建重跑通过。katex 经 mermaid 传递依赖的两例低危通告修复需要破坏性降级，暂不处理，不影响 moderate 闸门。
