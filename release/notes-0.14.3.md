# Lunitide 0.14.3

装上 0.14.2 之后：纯静默的挂死流确实在 4 分钟被切断了，但真实调用记录里又出现新形状——模型卡住之后，网关还在不停发心跳保活字节（`: keepalive` 注释行）和空数据帧。字节在流动、事件在到达，0.14.2 的字节级看门狗每次都被这些「空转流量」重置，于是挂死照旧陪着网关耗到底（生产记录里一整条流全程心跳型挂死 325 秒）。0.14.3 给看门狗补上两只新时钟：事件时钟（只认真正带回数据的 SSE 事件）和内容时钟（只认真正的思考/正文/工具增量），与原有字节时钟组成三层防线。现在无论挂死是什么形态——纯静默、心跳空转、空帧空转——最多 4 分钟被切断，按可重试超时处理，同回合自动带上已写内容接续重试。不改 poison / 月伴 TTS 音色 / 玉盘像素 / 星尘配方。不声称产品 100%。

已装 0.12.0 及以上版本可直接覆盖安装。不要覆盖 `v0.14.2` 及更早 tag 的 digest。不要重签 `v0.14.2` 及更早版。本包挂 GitHub Latest，应用内更新从 `latest.json` 下这一版。

## 1. 心跳型挂死：字节在流、事件没有

- 网关为维持连接会周期性发 `: keepalive` 注释字节。模型真挂死时，这些字节让字节级看门狗永远等不到「静默 4 分钟」，旧版只能陪网关耗到它自己放弃。
- 新增事件时钟：只有真正带回数据的 SSE 事件才重置它。心跳注释不算——连续 4 分钟只有心跳没有事件，判定连接已死，立即切断，按可重试超时处理，同回合自动接续。

## 2. 空帧型挂死：事件在到、内容没有

- 更隐蔽的形状：网关持续发空数据帧或 ping 事件。它们是「有意义的事件」，事件时钟也被重置，但模型从未吐出任何思考/正文/工具增量。
- 新增内容时钟：只有真正的思考增量、正文增量、工具调用片段才重置它，空帧和 ping 一律不算——连续 4 分钟没有新内容，切断并自动接续重试。

## 3. 三条协议线全部覆盖

- 三只时钟对三条生产流式协议同时生效：OpenAI chat-completions 线、Anthropic Messages 线、OpenAI Responses 线（方舟 Agent Plan 走的就是这条）。
- 0.14.2 已切断的纯静默形状照旧由字节时钟负责，三层各自兜底一种形态，互不替代。

## 4. 边界：什么不会被误切

- 健康的心跳节律不受影响：正文增量之间夹着 keepalive 或 ping 是网关的正常行为，只要内容在分钟级持续产出，三层时钟都不会触发。
- 健康的思考间隙照旧不切：模型边想边吐思考增量，内容时钟随之重置，思考再久也继续等。
- 长任务时钟仍由回合预算管（最长 3 小时不变），本版只收紧「死了的连接」的判定。
- 主动点停止照旧立即生效，不会被误判成超时。
- 被切断前已收到的正文和思考内容全部保留，续写轮次接着用。

## 5. 回归锁定

- 真实传输链路测试从 8 项扩到 13 项（真实 TLS 服务器、真实 HTTP/2 与 HTTP/1.1、真实适配器，非桩替换）：新增心跳型挂死、空帧型挂死、Anthropic ping 型挂死、Responses in_progress 型挂死四类切断测试，以及「心跳节律夹正文不误切」的反向测试。
- 每只时钟在测试里单独隔离武装（其余两只关闭），切断用时即证明是哪一层在起作用；三层到重试的全链路（超时 → 错误分类 → 可重试判定 → 回合内自动接续）逐层有测试钉住。
