# Lunitide 0.17.4

上一版装好后，产品知识中枢的健康分有个语义问题：没跑到的检查也扣分，机器明明没有真实问题，健康分却到不了 100。这一版把健康分改成只认真实问题：**没有真实、可解决的问题，健康就是 100%**。同时修掉了三张能力卡的误报和听写探针找错路径的问题，并把 Go 工具链升到 1.26.9，修掉 11 个标准库可达安全漏洞。

## 产品知识中枢：健康分只认真实问题

- **健康分基线改为 100 分**：只有真实发生的失败才扣分——探针真实跑失败、今天的引擎日志里有真实故障（宕机、超时、下载校验失败等）。没有这些问题，健康分就是 100%。
- **没跑起来不再扣分**：没跑起来（untested）、入口跑到但功能没跑完（reached）、诊断不能代跑的项（skipped，会开窗口、占麦克风、联网或安装的操作）都如实列在报告里，但一律不扣分——它们只说明这一轮没拿到证据，不说明产品有病。
- **覆盖率单列，不进健康分**：本轮读回多少（x/y）单独一行显示。它说明这轮复查了多少项，不代表健康程度。
- **"未测"不再按警告显示**：某一项这次没跑起来，不算缺陷、不算警告；执行净化会自动再跑它。仍失败才按真实问题报。

## 知识卡与探针修复

- **三张能力卡不再误报**：capability.list / capability.roles.get / capability.roles.set 三张自动生成的卡，此前被审计规则一刀切排除，误报"步骤未按真实调用写清"。现在按真实调用链追踪到处理函数，与其它卡一样可查证。
- **听写探针查找路径修正**：ASR 运行时实际装在数据根目录的 voice 子目录下，探针此前找高了一层，把健康安装误报为"模型未就绪"。修正后本机实测：听写 1.6 秒识别出文本、播放探测音正常、下载字节与服务器核对一致、OCR 从探测图读出文字，四项全部通过。

## 安全：随 Go 1.26.9 修复标准库漏洞

- **工具链从 go1.26.6 升级到 go1.26.9**：govulncheck 检出 11 个可达的标准库漏洞（涉及 net/http、crypto/tls、net/textproto、os），全部在 1.26.9 中修复。本版安装包即以修复后的工具链构建，升级后这些漏洞不再存在。

## 不改什么

- 不改 poison / 月伴 TTS 音色 / 玉盘像素 / 星尘配方。
- 不改既有界面布局与交互习惯。
- 不改 OCR 识别链路顺序（供应商 OCR → 本地 OCR → Windows OCR 兜底，不用大语言模型看图）。

## 兼容与覆盖安装

- Windows 端直接覆盖安装即可，配置、会话与数据全部保留。
- 更新源只认最新版本；本版安装包不得覆盖更早 tag 的 digest。
