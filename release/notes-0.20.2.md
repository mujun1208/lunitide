# Lunitide 0.20.2

0.20.0/0.20.1 里你可能遇到过：同一个「查一家公司的公开信息」问题，问两次结果不一样——一次能给出完整的公司概况，另一次却只回一句「疑似环境故障，请检查代理」草草收场。根因有三层：搜索通道里没有国内引擎，网络一波动境外源全灭；爱企查、企查查这类站点的登录墙/反爬 403 被当成了「环境故障」，把工具止损预算烧穿、对话被提前掐断；产品也不会记住「这个站有墙、百度那条路走得通」这个教训，下次同样的查询还要再撞一遍。这一版把三层一起收口，同样的提问产出同样质量的结果。

## 国内搜索直连，中文查询不再看境外网络脸色

- **以前**：网页搜索阶梯只有 DuckDuckGo 和两个 Bing 镜像，全在境外；大陆网络波动时三个源一起超时，查询直接落空。
- **现在**：阶梯扩到五级。中文查询把**百度、搜狗**排在最前（境内直连、稳定可达），Bing 中国镜像、DuckDuckGo、Bing 国际依次兜底；英文等查询保持原有顺序，国内源殿后救场。
- 新增百度/搜狗结果页解析与验证码页识别：命中反爬验证页自动降级到下一个源，绝不把验证码当结果返回。

## 登录墙不再触发「通道故障止损」

- **以前**：抓取爱企查、企查查等站点被 403/登录墙挡住，也算一次「工具失败」；连续撞四次墙，G-308 闸口判定「疑似环境故障」，直接拦截后续所有工具调用——明明网络好好的，对话却被掐死。
- **现在**：失败分类。**登录墙、反爬 401/403、验证码页**属于「单个数据源的局部障碍」，不再计入止损预算，模型保留换路绕行的自由；只有**超时、断网、连接重置**这类真正的通道故障才累计止损。真断网时止损照常触发，防重复空跑的护栏没有放松。

## 数据源障碍记忆：撞过的墙不再撞第二遍

- **现在**：当某个站点的登录墙挡住直抓、而同一轮里改走网页搜索（如百度企业卡片）成功拿到信息时，引擎会把这个教训沉淀成项目级记忆：「该站点有登录墙，同类企业/公司信息查询优先走 web.search」。
- 下次同类查询，这条记忆会作为背景证据注入对话，模型从第一步就选已验证的路径，不再把轮次浪费在已知的墙上；记忆写入遵循既有记忆治理开关（关闭记忆采集时不写入）。
- 障碍是瞬时误判（比如临时限流恢复）时，同站点抓取成功会自动清除该记录。

## 不改什么

- 不改 poison / 月伴 TTS 音色 / 玉盘像素 / 星尘配方。
- 不改工具闸口其余规则：真环境故障的止损、单通道连续失败换路提示、内容安全闸口全部保持原样。
- 不改搜索结果渲染界面与缓存行为；不引入 CGO 和新的外部依赖。

## 兼容与覆盖安装

- Windows 端直接覆盖安装，配置、会话、记忆、已配对信息全部保留；障碍记忆随项目记忆存储，升级后自动生效。
- 更新源只认最新版本；本版安装包不得覆盖更早 tag 的 digest。
