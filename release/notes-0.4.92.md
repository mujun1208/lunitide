# Lunitide 0.4.92

0.4.91 装上之后，记忆页还是旧运营表、OCR 设置仍像在卖 PaddleOCR-VL、媒体中心没有真正的会话队列。0.4.92 把这批已经接线的记忆 / OCR / 媒体能力收进安装包。覆盖升级仍走 GitHub `latest.json`。不改 poison / 月伴 TTS 音色 / 玉盘像素 / 星尘配方。不声称产品 100%。不把 AgentHub 焊进 SessionPage。不重做办公 PPT 视觉稿。不把本机 OCR 换成 PaddleOCR-VL-1.6。

已装 0.4.91 可直接覆盖安装。`v0.4.92` 的 Setup + `latest.json` 挂到 GitHub Latest。不要覆盖 `v0.4.91` / `v0.4.90` / `v0.4.89` / `v0.4.88` / `v0.4.87` / `v0.4.86` / `v0.4.85` / `v0.4.84` 的 digest。不要重打 `v0.4.91`。

## 1. 记忆

- 记忆页按条目读写：打开抽屉会拉当前条和版本历史，可更正、可忘记。
- 手工记下的条目带「撤销」；对话里保存的记忆同样可以撤销，提示条能点。
- 高级管理里可以看记忆世代：预览、启用、丢弃。启用用该世代的修订号，不会拿整库修订号去撞冲突。
- 导入 / 导出 / 清空走 Fabric v2 档案，不再假装旧运营表已经是新产品。

## 2. OCR

- 识别顺序固定：已配置的视觉模型能用就先用（能力路由或供应商绑定），然后 RapidOCR（`RapidOCR-json.exe`），最后 Windows OCR。
- 默认策略是本机自动：`ppocr` → `windows-ocr`，复杂文档引擎为 `none`。绑定供应商时也不会偷偷把复杂引擎写成 PaddleOCR-VL-1.6。
- 旧路由里 `sendToCloud=never` 不再挡住已经配好的视觉模型。
- PaddleOCR-VL-1.6 安装闸门保持关闭（`NO_VERIFIED_RUNTIME_PROFILE`），查询页也不会因为库里写过允许安装就打开按钮。
- 办公扫描 PDF 的文本缓存跟着 OCR 路由修订走。路由真的改了才重识别；周报一类办公产物不会拿过期 OCR 结果。

## 3. 媒体

- 产品默认打开媒体会话。重复启动不会每次把设置修订号 +1。
- 播放队列按当前会话列资产，不会把整个媒体库倒进抽屉。跳转、上一首/下一首按队列转，并刷新列表。
- 本机播放走签名媒体源；签名安装包里的播放器 PE 一并签名。

## 4. 其他接线

- MCP 市场缺 uv 的服务可以走一键 uv 安装，不再把整页说成 Node 不可用。
- 技能可以绑专家；知识中心入口按已落地的产品页走。
- 桌面见-做-核、一键技能/MCP 导入、畸形 Excel 不崩引擎，继续按 0.4.91。

## 5. 发布

- GitHub Latest 指向 `v0.4.92`。旧版 tag 保留。本地只保留这一次签名安装包。
