# Lunitide 0.13.1

装上 0.13.0 之后：月伴的每周归档在周报内容较长时会静默失败——引擎日志里反复出现「weekly companion archive did not complete: failed SUMMARY_FAILED」，归档Coverage 不前进，旧周的回忆依据一直缺失。根因是摘要模型的输出上限被硬编码在 2048 token：一周的滚动摘要连同上周结论一起生成时很容易超限，超限即被硬截断，结构化 JSON 半截不闭合，归档只能判失败。0.13.1 把这一条收口。不改 poison / 月伴 TTS 音色 / 玉盘像素 / 星尘配方。不声称产品 100%。

已装 0.13.0 可直接覆盖安装。不要覆盖 `v0.13.0` 及更早 tag 的 digest。不要重签 `v0.13.0` 及更早版。本包挂 GitHub Latest，应用内更新从 `latest.json` 下这一版。

## 1. 每周归档不再被输出上限截断

- 摘要输出上限从 2048 提到 8192 token，仍在 DeepSeek / GLM / GPT 等主流模型的单次输出上限之内；与换哪个模型无关，以前哪个模型来跑长周报都会截断。
- 每批摘要的超时从 60 / 90 秒统一放宽到 3 分钟：长摘要本来就需要更长的生成时间，只提上限不放宽超时会在另一处失败。3 分钟仍在每小时归档清扫的 10 分钟总预算之内。
- 真的再撞到输出上限时，失败原因会直接写明「summary truncated at output token limit」，不再伪装成「invalid structured JSON」，日志里一眼可诊。
- 补了三条回归测试锁住上限地板、参数透传和截断报错语义，防止将来被改回去。
