# Lunitide 0.15.0

装上 0.14.3 之后：挂死流会被及时切断了，但对话界面还有三件烦心事没收口——切到别的窗口再回来，正在走的耗时芯片不见了；有时提交完决策卡，对话就停在「等待响应」，打字发送都没反应，非得再喊一句「继续完成任务」才动；有时没做任何决策，它也会这样卡住。0.15.0 把这三件事一次收口：回合计时跟着回合走，面板重挂载即恢复；被决策消费掉的停泊回合立即收尸，你的选择作为新回合直接发出；再加一只看门狗兜底，把真正死掉的回合按取消收尾——历史落定、队列清空、恢复横幅照常出现。同时给每轮对话加上一行收尾统计：本轮耗时和输入/输出/合计 tokens，实时对话里有，翻历史消息也还在。不改 poison / 月伴 TTS 音色 / 玉盘像素 / 星尘配方。不声称产品 100%。

已装 0.12.0 及以上版本可直接覆盖安装。不要覆盖 `v0.14.3` 及更早 tag 的 digest。不要重签 `v0.14.3` 及更早版。本包挂 GitHub Latest，应用内更新从 `latest.json` 下这一版。

## 1. 每轮对话的收尾统计

- 一轮对话结束后，回复下方多出一行统计：本轮耗时（如「本轮耗时 3m 12s」）加 token 用量（输入 / 输出 / 合计，千分位分隔）。
- 耗时由后端计量：从回合检查点开始，覆盖其中所有模型调用、工具循环和接续波次，比前端自己掐表更准；usage 事件直接带上时长。
- 统计随消息持久化（独立小文件，不进会话工作区摘要），重开应用翻历史，这行统计还在。
- 中英文界面各有文案；没有数据的回合只显示有数的部分，两者都没有就不显示，不占版面。

## 2. 切窗回来，耗时芯片不再消失

- 以前：回合开始时刻只存在面板组件里，切走再回来组件重挂载，计时起点丢了，芯片消失。
- 现在：回合开始时刻随回合记录在跨会话存活的注册表里，面板重挂载时直接恢复，芯片接着走。

## 3. 提交决策后不再卡死

- 根因：决策卡（user.ask）提交后，服务端把停泊的流直接消费掉，前端注册表里的回合永远等不到终态事件；窗口隐藏期间事件被丢弃时，这个「僵尸回合」就一直占着输入队列，后续发送全部入队等一个不会来的事件。
- 现在：决策提交成功后，前端识别出这类被消费的 user.ask 停泊回合（按调用 ID 和工具名双重校验），立即静默收尸，你的选择作为新回合直接发出，不再排队死锁。

## 4. 无故卡在「等待响应」：看门狗兜底

- 新增前端看门狗：每 30 秒扫一遍存活回合，静默超过 5 分钟、且既不在等用户决策、也没有工具在跑的回合，判定为僵尸，用一条合成的取消事件走正规收尾——历史落定、输入队列清空、恢复横幅出现。
- 等决策和跑工具的回合安静很久是正常的，看门狗不碰它们；刚有动静的回合也不碰。
- 决策被消费后（无论是手动提交、全权限自动审批、还是月伴语音自动审批），「等决策」豁免立即清除——若之后流事件已全部丢失，看门狗能在 5 分钟内收尸，不再永久卡住。

## 5. 回归锁定

- 前端全量 2830 项测试（387 个文件）全绿。新增回归覆盖：user.ask 僵尸决策后新回合直接发出（不入队死锁）、面板重挂载恢复耗时芯片、看门狗收尸 / 豁免 / 重复挂载幂等 / 豁免清除时序（fake timers 钉死）、耗时与 token 格式化中英文两套。
- Go 侧新增回合统计测试：真实流式回合跑完 → usage 事件带时长 → 历史页带 turnStats → 不泄漏文件私有字段 → 统计文件不进会话工作区摘要；损坏或缺失的统计文件跳过，不报错。
