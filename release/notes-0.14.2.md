# Lunitide 0.14.2

装上 0.14.1 之后：长文任务虽然第一秒就能看到字往下写了，但模型通道偶尔整条流挂死——连接建立之后零字节静默六到十几分钟才被网关放弃，而客户端的流式空闲看门狗设的是 3 小时，挂死期间全程陪等。表现为一次任务拖到十几分钟仍然失败重来；真实调用记录里同一回合三次挂死（6.5 / 9.3 / 2.1 分钟）全部白等。0.14.2 把这只看门狗换掉：流式空闲 4 分钟、响应头 60 秒收口，挂死流在分钟级被切断并按可重试超时处理，同回合自动接续重试，不从头再来。不改 poison / 月伴 TTS 音色 / 玉盘像素 / 星尘配方。不声称产品 100%。

已装 0.12.0 及以上版本可直接覆盖安装。不要覆盖 `v0.14.1` 及更早 tag 的 digest。不要重签 `v0.14.1` 及更早版。本包挂 GitHub Latest，应用内更新从 `latest.json` 下这一版。

## 1. 挂死流分钟级切断并自动重试

- 模型流一旦连续 4 分钟没有任何新字节，判定连接已死，立即切断并按「可重试超时」处理：同一回合内自动带上已写出的内容重发请求，接着写，不从头再来。
- 请求发出后 60 秒连响应头都没回来的，判定这次请求没到达模型，快速失败进入重试，不再陪等。
- 被切断前已经收到的正文和思考内容全部保留，续写轮次接着用。

## 2. 边界：什么不会被误切

- 健康的思考间隙不受影响：模型边想边吐思考增量、边写边吐正文增量，只要分钟级有新字节就继续等——思考再久也不切。
- 长任务时钟仍由回合预算管（最长 3 小时不变），本版只收紧「死了的连接」的判定，不改变长文任务的总时长上限。
- 主动点停止照旧立即生效，不会被误判成超时。
- 模型内部调用（规划、上下文收拢）实测首字节在 15 秒内回来，60 秒响应头限时有充分余量，不会误伤。

## 3. 回归锁定

- 新增 8 项真实传输链路测试（真实 TLS 服务器、真实 HTTP/2 与 HTTP/1.1、真实适配器，非桩替换）：健康流完整收完、挂死流（HTTP/2 / HTTP/1.1 / Anthropic 协议）判可重试超时且保留部分内容、响应头挂死快速失败、用户取消不误判、临界思考间隙不误切。
- 超时到重试的全链路（传输层超时 → 错误分类 → 可重试判定 → 回合内自动接续）逐层有测试钉住；看门狗数值本身（空闲 4 分钟、响应头 60 秒）由配置断言测试锁死。
